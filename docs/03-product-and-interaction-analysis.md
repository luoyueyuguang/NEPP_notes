# 03 · 产品与交互分析

> 本文档从"产品"视角分析这套资料：用户是谁、怎么用、业务规则是什么。产品行为全部从代码/文档结构推断，标注推断等级。

## 1. 产品定位

**NEPP_notes 是一个"自研考研刷题系统"的单人产品**——形态上是两本 PDF 讲义，行为上是"学习→刷题→订正"的完整闭环。

- 目标考试：考研数学（一）+ 计算机统考 408；
- 目标用户：作者本人（luoyue），可扩展为分享给其他考生；
- 交付形态：PDF（Release 双版本），可在任意设备阅读；
- 核心承诺：**"做题时不看到答案"**——由 `\showsolutions` 开关与双版本发布保证。

## 2. 用户角色与使用场景

| 角色 | 场景 | 使用产物 |
|---|---|---|
| 学习者（作者本人） | 章节学习 | `*-full.pdf` 知识部分 |
| 练习者 | 章节刷题 | `*-exercises.pdf` 习题部分 |
| 自测者 | 180 分钟限时模拟 | `*-exercises.pdf` 模拟卷 |
| 订正者 | 对照答案复盘 | `*-full.pdf` 解析部分 |
| 维护者 | 修订内容/重建 | 源码 + 构建命令 |

## 3. 核心交互流程

### 3.1 刷题工作流（产品核心体验）

```mermaid
flowchart LR
    A[下载 exercises 版] --> B[章节知识复习<br/>用 full 版]
    B --> C[做章节习题<br/>exercises 版]
    C --> D[答案不确定？]
    D -->|是| E[翻 full 版对应章节<br/>对照解析订正]
    D -->|否| F[下一章]
    E --> F
    F --> G[冲刺：模拟卷 180 分钟限时]
    G --> H[full 版逐题复盘]
```

**业务规则（从 REVIEW.md 提取的官方建议）**：
1. "建议实际使用时先关闭解析，按 180 分钟完成，再打开解析订正"（数学 REVIEW §4）；
2. "强化阶段：完成综合提高题和'真题风格与综合训练'；冲刺阶段：关闭解析，每套 180 分钟限时完成；建议顺序使用卷一、卷二、卷三"（数学 REVIEW §7）；
3. "复盘时不要只核对最终数值，应核对定理条件、积分区域、曲面方向、统计量分布条件和估计量参数范围"（数学 REVIEW §7）。

### 3.2 模拟卷使用流程

408 卷面布局（exams.tex 头部注释）：
- 单选：DS 1–11、CO 12–22、OS 23–32、CN 33–40；
- 综合：DS 41–42（23 分）、CO 43–44（23 分）、OS 45–46（15 分）、CN 47（9 分）；
- 四科总分 45/45/35/25，与统考分值结构一致。

数学卷面布局：
- 选择 10 题（高数 6、线代 2、概率 2）、填空 6 题（高数 4、线代 1、概率 1）、解答 6 题（高数 4、线代 1、概率 1）；
- 学科分值近似高数 96 / 线代 27 / 概率 27（REVIEW 记录）。

### 3.3 版本选择规则

| 你处于什么状态 | 用哪个 PDF |
|---|---|
| 学新章节 | `*-full.pdf`（只看知识框部分，习题区有答案也无妨） |
| 刷章节题 | `*-exercises.pdf` |
| 限时模拟 | `*-exercises.pdf` |
| 复盘订正 | `*-full.pdf` |

## 4. 内容组织规则（从结构推断的业务规则）

1. **章节内部固定顺序**：知识（定义→公式→结论→警示/例题）→ `\newpage` → 习题。习题永远独立成节，不与知识混排；
2. **习题分级**：基础过关题（保底掌握）→ 综合提高题/真题风格与综合训练（能力拔高）；
3. **题型标记**：题号前缀标注题型（选择题/填空题/计算题/证明题/简答题/综合题），408 题目标注"（真题风格·选择题）"等；
4. **答案可见性规则**：所有解析/答案必须处于 `\ifshowsolutions` 条件块内——这是内容编写者的硬性义务；
5. **拓展隔离规则**：超纲内容（Jordan 标准形、矩母函数、Cayley–Hamilton 等）必须标注"拓展"，不进入主线备考负担；
6. **自包含规则**：题目不得依赖外部图片（REVIEW 曾把依赖缺失图的题改写为自包含文字题）；
7. **唯一性规则**：选择题答案必须唯一——多解/无解/条件不足的题一律改写或标注"信息不足"。

## 5. 边界情况处理（从审阅记录提取的产品决策）

| 边界情况 | 产品决策 |
|---|---|
| 题目有两个正确选项 | 改写题干/选项，重设干扰项 |
| 题目无正确选项 | 改写或明确"信息不足"（如银行家算法 Max/Need 不完整） |
| 题面依赖缺失图 | 改为自包含文字题 |
| 解析与答案不一致 | 以独立复算为准统一（TCP 慢开始 `1,2,4,8,9` 案例） |
| 教材约定冲突（如曼彻斯特编码方向） | 明确"以题目约定为准"写入题干 |
| 复杂度过高（解析给 O(n²) 而题干要求高效） | 改解法（链表自底向上归并 O(n log n)） |
| 答案分布偏斜（正确答案集中 B/D） | 选项重排 + 同步答案，分布调至 9/11/10/10 等 |

## 6. 前后端协同（本项目的"前后端"）

- **内容层**（章节/习题/解析源）与**渲染层**（main.tex 的样式系统）分离：章节文件只写内容语义（用知识框环境），不写排版细节；
- **开关层**（`\showsolutions`）横切内容层：内容作者无需关心开关实现，只需把解析放进条件块；
- **发布层**（CI + Release）消费渲染层产物：`main.pdf` → 双版本 PDF → GitHub Release 资产。

## 8. 产品风险

1. **准确性质押**：产品承诺"可刷题"，一旦某题答案错误，刷题体验直接受损——审阅闭环是产品的生命线；
2. **版本分裂**：exercises/full 双 PDF 若不同步（漏改一处解析），用户会困惑——开关机制从源头上保证二者由同一源码生成，但发布流程需验证；
3. **时效性**：2027 新大纲发布后需增量复核，否则产品过时；
4. **超纲内容污染**：拓展内容若被误当主线复习，浪费时间——依赖正文标注，无机械隔离。
