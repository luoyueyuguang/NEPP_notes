# 02 · 设计原因与工程思想

> 本文档回答"为什么这样设计"。所有判断基于仓库证据（代码、REVIEW 报告、git 历史、编写规范），区分 **已确认事实** / **合理推断**。

## 1. 项目定位与演化轨迹

仓库的 git 历史展示了清晰的三阶段演化：

```
2025-07  手写笔记阶段     — 按章提交，个人零散笔记
2026-07  上旬 AI 成书阶段 — 408 全书初版、习题替换、Unicode 修复、字号调整
2026-07  中旬 审阅阶段    — 四轮/多轮 REVIEW、逐题闭环、README 规范化
2026-07  下旬 发布阶段    — v1.1.0 → 习题/解析分离 → v1.2.0 双版本发布
```

**设计推断**：作者的目标不是"记录笔记"，而是"获得一套可持续演进、可发布、可长期刷题的备考资料"。这解释了为什么：

- 引入 CI 与审阅报告（资料要长期可靠）；
- 使用 GitHub Release 发布 PDF（要跨设备使用/分享）；
- 做习题/解析分离（资料要真正用于刷题，而非浏览）。

## 2. 核心设计哲学

### 2.1 知识框语义化（已确认）

两本书都围绕 tcolorbox 建立**六类语义框**：

| 框 | 语义 | 数学配色 | 408 配色 |
|---|---|---|---|
| `mydef` | 定义——不可含糊的精确陈述 | 蓝 | SoftTeal 底 + Teal 左线 |
| `formula` | 公式/要点——可直接套用的结论 | 粉 | SoftAmber 底 + Amber 左线 |
| `conclusion` | 结论——由定义+公式推出的可核验结果 | 蓝黑 | SoftBlue 底 + Navy 左线 |
| `attention` | 考点警示/易错点 | — | SoftAmber 底 + Amber 标题"注意" |
| `examplebox` | 例题 | — | SoftGray 底 + 标题"例题" |
| `tablebox` | 结构化对照表 | teal 边框 | Navy 表头 |

这背后的思想是**"排版即信息架构"**：读者扫一眼颜色/边框就能判断当前内容的知识层级——是必须背的定义、可以用的公式，还是需要警惕的陷阱。408 侧还用 `borderline west` 左竖线强化视觉分组，且所有框共享 `studybox` 基础样式（圆角、可跨页、统一间距），保证"同类框同构"。

### 2.2 "教材为骨干，应试为出口"（已确认，408-context.md）

`local/408-context.md` 明确要求：**以高质量教材为内容主干，"非王道/天勤"**。教材体系为：

- DS：邓俊辉《数据结构（C++语言版）》+ Sedgewick《算法》第4版
- CO：Patterson & Hennessy《计算机组成与设计》+ CS:APP
- OS：OSTEP + 陈海波《现代操作系统：原理与实现》
- CN：Kurose《计算机网络：自顶向下方法》+ 谢希仁（仅术语对齐）

**设计原因推断**：市面辅导书（王道/天勤）是为应试速成写的，表述高度浓缩但常牺牲原理性；以经典教材为骨干能保证概念体系的正确性和深度，再由 `attention` 框和习题把知识"考试化"。这是"原理优先、应试转化"的策略——与一般考研资料"应试优先、原理从简"相反。

### 2.3 元数据审慎主义（已确认）

仓库对"真题"极其克制：

- 所有年份/题号未经权威核验 → 正文统一降级为"真题风格"；
- `appendix-exams.tex`（含年份题号索引）从构建链**物理移除**，仅保留 `appendix-audit.tex` 说明原因与核验字段要求；
- REVIEW.md 明确记录："不能把未经逐卷核验的年份、题号和题源归属作为事实发布。"

**工程思想**：宁可损失"真题光环"的营销价值，也不发布未经证实的元数据。这是典型的**证据纪律**——在 AI 生成内容的场景下尤其重要，因为它直接关系到资料的公信力。

### 2.4 审阅闭环制度化（已确认）

两份 REVIEW.md 是仓库里最有工程价值的文档：

- math：四轮审阅，每轮发现前轮遗漏（第三轮发现"闭圆域最值、仿射解集维数"等，第四轮发现"多元链式法则、二维 Taylor 公式"等）；
- 408：多轮审阅，第三轮做**逐题闭环静态计数**（112 道题补齐 110 个解析），并独立复算代表性数值（Huffman WPL=228、TLB=120ns、GBN≈19.05% 等）。

REVIEW 报告不仅记录"改了什么"，还记录**"为什么结论只适用于当前版本"**——承认审阅的时点性，拒绝"已证明全书无误"的过度声明。这是对 AI 生成内容本质风险的诚实回应：生成快、出错快，必须用"多轮独立复审"对冲。

### 2.5 单一全局状态：解析开关（已确认）

`\ifshowsolutions` 是全书**唯一全局布尔状态**，只在各自主 `main.tex` 定义一次。408 REVIEW 记录了关键教训：曾有 5 个子章节重复声明并强制执行 `\showsolutionstrue`，导致主入口关闭开关被局部覆盖。修复方式是**删除全部局部声明**。

**设计原因**：内容量大（几百道题），若每个章节各自管理开关，必然出现漂移；把开关收敛到唯一权威点，配合"所有解析块无条件服从全局开关"的约定，才能保证"关掉=全书无答案"这个不可违背的产品承诺。

## 3. 技术取舍分析

| 取舍 | 选择 | 原因（推断+证据） | 代价 |
|---|---|---|---|
| 引擎 | XeLaTeX + fontspec | CJK 字体直接调用系统 Noto；数学符号兼容 | 构建慢、环境重 |
| 文档类 | ctexbook（book 子类） | 天然支持 part/chapter 分层、TOC、目录书签 | 版式需大量覆盖 |
| 代码排版 | listings（非 minted） | 408 规范明确"不要用 minted"；minted 需 shell-escape | 语法高亮较弱 |
| 图表 | tikz/pgfplots 内联绘制 | 自包含、无外部素材依赖（REVIEW 要求"不依赖缺失素材"） | 源码冗长 |
| 习题载体 | 源内嵌习题+开关 | 单一源文件保证题目与解析同步修改 | 需要双版本构建 |
| 发布产物 | PDF 双版本强制跟踪 | 用户直接消费 PDF；发布可追溯 | 仓库体积增长 |
| 真题处理 | 隔离而非删除 | 保留未来核验后恢复的可能性 | 仓库存在未发布内容 |
| 字号 | 408 曾 13.5pt→11pt | 压缩页数（409→428 页记录于 commit a9eb6b9） | 阅读密度上升 |

## 4. 两本书的风格分化

同一工程底座，两本书选择了不同的视觉与组织哲学：

**math**：极简。默认页面样式、`\textbf` 全局重定义为蓝色无衬线、三色知识框、无自定义封面。内容为王，视觉让位于阅读效率。

**408**：重设计。自绘封面、15 色配色系统、titlesec 徽章节标题、三套页眉页脚、`\sectionbadge`。工程上更像"书籍产品"。

**推断**：math 沿袭手写笔记时代的外观（克制、保守），408 是 AI 成书阶段从零构建（有预算做完整设计系统）。两种风格没有优劣，但 408 的"设计系统"做法（颜色 token、共享样式、统一间距）在工程上更可维护——颜色改名只需改入口文件。

## 5. 值得称赞与值得警惕的部分

**优秀工程思维**：
- 把"刷题不泄题"的产品需求翻译成"单一条件开关+双版本构建"的技术方案，控制面极小；
- 把审阅报告作为一等公民文档入库，而不是口头约定；
- 对 AI 生成内容坚持"证据优先"（真题风格降级、审阅边界声明）；
- `attention` 框专门承载"408 常考陷阱"，把高频失分点显性化。

**偶然复杂度/风险**：
- CI 只覆盖 math——408 的构建回归风险无门禁；
- 双版本构建依赖 `sed` 改源码再改回，若中途中断会留下脏状态（建议脚本化）；
- `math/out/main.pdf` 与 `release/*.pdf` 是二进制强制跟踪，长此以往仓库膨胀；
- REVIEW.md 中的页数等统计是历史快照，未标注日期，容易误读为当前值；
- 数学部分少量拓展内容（Jordan、矩母函数等）与主线同库存放，依赖正文标注隔离，缺少机械检查。

## 6. 现实约束推断

- **单人维护**：无 issue 模板、无贡献指南、无测试框架——所有质量动作（审阅、复算、构建检查）都是个人流程；
- **时间敏感**：备考资料有明确死线（考研季），解释了"先成书、再审阅、再发布"的节奏；
- **设备约束**：发布 PDF 而非在线文档，便于在平板/手机上刷题；
- **法律/伦理敏感**：AI 生成内容 + 参考他人教材 → 免责声明、致谢、侵权下架通道（Issues）三件套齐全。
