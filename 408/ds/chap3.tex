\section{串}

在编辑器里按一次“查找”，在 DNA 序列里找一段碱基，在日志里筛一个错误码，做的都是同一件事：在一段长字符串里找一个短字符串第一次出现的位置。串就是为这类“按字符连续比较”准备的结构。它的逻辑结构和线性表一样，只是每个元素限定为字符；操作上则常以整段子串为单位，而不是逐个元素处理。

串是零个或多个字符组成的有限序列，记作
\[
S=a_1a_2\cdots a_n\qquad(n\ge 0),
\]
其中 $n$ 是串长。$n=0$ 时称为空串，记作 $\varepsilon$。

以 $T=\texttt{abcababc}$ 为例：\texttt{abc}、\texttt{cab}、\texttt{ababc} 都是它的子串，子串必须连续；\texttt{aaa} 只是子序列，不是子串。包含子串的串叫主串，被查找的串叫模式串。从第一个字符开始的一段叫前缀，以最后一个字符结尾的一段叫后缀，“真”前缀、真后缀指不包含整个串本身。既是真前缀又是真后缀的串叫 border，例如 \texttt{abcababc} 的 border 是 \texttt{abc}；而 \texttt{abcab} 的 border 是 \texttt{ab}。

按起始位置和长度区分，长度为 $n$ 的串有 $n(n+1)/2$ 个非空子串，加上空串共 $n(n+1)/2+1$ 个；真子串（去掉串本身）有 $n(n+1)/2$ 个。这里按“位置”计数：\texttt{aaa} 中两个 \texttt{a} 算两个不同的子串。串相等要求长度相同且对应位置字符完全相同；按字典序比较时，从第一个不同的字符决定大小，若短串是长串的前缀，则短串更小。

\begin{attention}
空串 $\varepsilon$ 的长度为 0；空格串由一个或多个空格组成，长度等于空格个数，至少为 1。空串是任何串的子串，也是任何非空串的真前缀和真后缀。题目里“空串”“空格串”“长度为 0”是三种不同说法。
\end{attention}

\subsection{串的存储与基本操作}

顺序存储最常见。408 的代码通常约定 \texttt{ch[1..length]} 保存字符，\texttt{ch[0]} 空着不用，串长单独放在 \texttt{length} 字段：
\begin{lstlisting}[language=C]
#define MAXLEN 255
typedef struct {
    char ch[MAXLEN + 1];   /* ch[1..length] 存字符，ch[0] 不用 */
    int  length;           /* 当前串长 */
} SString;
\end{lstlisting}
有的教材把长度塞进 \texttt{ch[0]}（值域只有 $0\sim255$），但做题时若题目给了 \texttt{length} 字段，就按上面的约定理解。堆分配存储把字符放在 \texttt{malloc} 得到的一段连续空间里，结构体只保存首地址和长度，适合串长变化较大的场合：
\begin{lstlisting}[language=C]
typedef struct {
    char *ch;              /* 指向堆区，按实际串长分配 */
    int   length;
} HString;
\end{lstlisting}
块链存储把字符切成固定大小的块，块与块之间用指针连接。它的插入、删除比顺序存储灵活，但想取第 $i$ 个字符得沿链找块，不能随机访问。

三种布局画的都是逻辑结构：顺序存储靠下标随机访问；堆分配多一次间接寻址，换来可变串长；块链把字符切块，找第 $i$ 个字符要沿链定位。

串的 ADT 以整串为操作对象：赋值 \texttt{StrAssign}、复制 \texttt{StrCopy}、判空 \texttt{StrEmpty}、比较 \texttt{StrCompare}、求长 \texttt{StrLength}、取子串 \texttt{SubString}、连接 \texttt{Concat}、定位 \texttt{Index}、清空 \texttt{ClearString}。前几个操作基本都是一次 $O(n)$ 的搬运；本章的重点是
\[
\texttt{Index}(S,T,\textit{pos}),
\]
即从主串 $S$ 的第 \textit{pos} 个字符起，找模式串 $T$ 第一次出现的位置，找不到返回 0。下面的 BF 和 KMP 都是它的实现。

\subsection{朴素匹配：失配就从头再来}

BF（Brute Force，暴力匹配）的做法很直接：把 $T$ 依次对齐到 $S$ 的每个起点，逐字符比较；一旦失配，$T$ 整体右移一位，$T$ 的指针回到第一个字符，主串指针回到本轮起点的下一个位置。下面记主串长 $n=|S|$、模式串长 $m=|T|$，通常 $n\ge m$。

取 $S=\texttt{ababcabcacbab}$、$T=\texttt{abcac}$：
\begin{itemize}
  \item 第 1 趟从 $S[1]$ 对齐：前两对 \texttt{a}、\texttt{b} 相同，第 3 对 $S[3]=\texttt{a}$ 与 $T[3]=\texttt{c}$ 失配。
  \item 第 2 趟从 $S[2]$ 对齐：$S[2]=\texttt{b}$ 与 $T[1]=\texttt{a}$ 立即失配。
  \item 第 3 趟从 $S[3]$ 对齐：\texttt{abca} 四对相同，第 5 对 $S[7]=\texttt{b}$ 与 $T[5]=\texttt{c}$ 失配。
  \item 第 4、5 趟分别从 $S[4]$、$S[5]$ 对齐，首字符就失配。
  \item 第 6 趟从 $S[6]$ 对齐：$S[6..10]=\texttt{abcac}=T$，匹配成功，返回 6。
\end{itemize}

代码里用 $i$ 记主串当前比较位置、$j$ 记模式串当前比较位置。失配时本趟起点是 $i-j+1$，下一趟从它的下一位开始，所以 $i$ 改成 $i-j+2$：
\begin{lstlisting}[language=C]
int Index_BF(SString S, SString T) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (S.ch[i] == T.ch[j]) { ++i; ++j; }
        else { i = i - j + 2; j = 1; }   /* 回到本趟起点的下一位 */
    }
    if (j > T.length) return i - T.length;  /* 本趟起点 */
    return 0;
}
\end{lstlisting}
匹配成功时 $j=T.length+1$，$i$ 停在匹配段之后，所以起点是 $i-T.length$。

比较次数取决于失配发生得多早。最好情况每趟首字符就失配，比较 $n-m+1$ 次，$O(n)$；最坏情况每趟都比到 $T$ 的末尾才失败，比较 $(n-m+1)m$ 次，$O(nm)$。典型触发串是 $S=\texttt{aaaa}\cdots\texttt{a}$、$T=\texttt{aaaab}$：每一趟先匹配若干 \texttt{a}，最后一个字符才失败。平均情况要看字符分布，不能不加条件地写成 $O(n+m)$；408 问最坏复杂度时答 $O(nm)$。

BF 的问题不在慢，而在重复。失配时前 $j-1$ 个字符已经确认相等，这些信息被丢掉了，下一趟又从 $T[1]$ 开始比。KMP 要做的就是把这段信息留下来。

\subsection{KMP：让主串指针只向前走}

还是用 $T=\texttt{abcababc}$。假设主串的一段是 $S=\texttt{abcabcab}\cdots$，$T$ 从 $S[1]$ 对齐：
\[
\begin{array}{rcccccccc}
S: & \texttt{a} & \texttt{b} & \texttt{c} & \texttt{a} & \texttt{b} & \texttt{c} & \texttt{a} & \texttt{b}\\
T: & \texttt{a} & \texttt{b} & \texttt{c} & \texttt{a} & \texttt{b} & \texttt{a} & \texttt{b} & \texttt{c}
\end{array}
\]
前 5 个字符 \texttt{abcab} 相同，第 6 对 $S[6]=\texttt{c}$ 与 $T[6]=\texttt{a}$ 失配。注意已匹配的 \texttt{abcab} 有 border \texttt{ab}：它的前缀 \texttt{ab} 等于后缀 \texttt{ab}。把 $T$ 右移，使 $T[1..2]$ 对准刚匹配过的最后两个字符 $S[4..5]$，这两个字符就不用再比；下一次直接比较 $T[3]=\texttt{c}$ 与 $S[6]=\texttt{c}$。

图中上半部分是失配前的对齐，两个彩色框标出相等的前后缀；下半部分是右移后的对齐，绿色勾表示这几个字符不用重新比较，主串指针仍停在原来的失配字符处。

推广到一般情况：设失配发生在 $T[j]$，已匹配部分是 $P=T[1..j-1]$。若 $P$ 的最长 border 长度为 $k$，把 $T$ 右移 $(j-1)-k$ 位，就能让 $T[1..k]$ 对准 $P$ 的后缀，下一次比较 $T[k+1]$ 与 $S[i]$，主串指针 $i$ 不动。

为什么可以跳过中间的位移？假设某个更小的位移 $d<(j-1)-k$ 也能匹配，那么 $P$ 就存在一个长度大于 $k$ 的 border，和 $k$ 是最长 border 矛盾。所以按最长 border 滑动不会漏掉任何可能的匹配。

把每个 $j$ 对应的 $k+1$ 预先算出来，就是 \textbf{next} 数组（下标从 1 开始）：
\begin{equation}
\mathrm{next}[j]=
\begin{cases}
0, & j=1,\\[2pt]
1+\max\{\,k\mid 0\le k<j-1,\ T[1..k]=T[j-k..j-1]\,\}, & j\ge 2.
\end{cases}
\end{equation}
$k=0$ 时约定空串等于空串，所以 $j\ge2$ 时 $\mathrm{next}[j]\ge1$。用文字说：next[j] 是 $T[1..j-1]$ 的最长相等真前后缀长度加 1。这里的“真”不能丢：若把整个 $T[1..j-1]$ 当前缀，失配后模式串不会移动，等于没跳。失配后的实际位移是
\[
(j-1)-(\mathrm{next}[j]-1)=j-\mathrm{next}[j].
\]

408 常用下标从 1 开始的版本，$\mathrm{next}[1]=0$、$\mathrm{next}[2]=1$。有的教材用 $\mathrm{next}[1]=-1$（所有值减 1），有的直接用 0 下标的前缀函数 $\pi$（存 border 长度本身）；做题前先看题干采用哪套约定。

匹配过程只改模式串指针：
\begin{lstlisting}[language=C]
int Index_KMP(SString S, SString T, int next[]) {
    int i = 1, j = 1;
    while (i <= S.length && j <= T.length) {
        if (j == 0 || S.ch[i] == T.ch[j]) { ++i; ++j; }
        else j = next[j];          /* i 不动，只退模式串 */
    }
    if (j > T.length) return i - T.length;
    return 0;
}
\end{lstlisting}
$j=0$ 是 $\mathrm{next}[1]=0$ 带来的哨兵。首字符失配时 $j$ 变成 0，下一轮走 \texttt{j==0} 分支，$i$ 和 $j$ 同时加一，相当于放弃当前起点、从主串下一个字符重新开始。C 的 \texttt{||} 从左到右短路，所以 \texttt{T.ch[0]} 不会被读。匹配成功时 $j=T.length+1$，返回 $i-T.length$。

复杂度这样看：$i$ 只增不减，最多增加 $n$ 次；每次失配 $j=\mathrm{next}[j]$ 都严格减小；$j$ 只在 $i$ 增加时增加，所以 $j$ 减小的总次数不超过它增加的总次数，也不超过 $n$。因此 while 循环至多执行约 $2n$ 次，匹配阶段 $O(n)$；预处理 $O(m)$；总时间 $O(n+m)$。额外空间是 next 数组的 $O(m)$。

\subsection{next 数组怎么算}

先把 $T=\texttt{abcababc}$ 手算一遍。设 $\pi[j]$ 是 $T[1..j]$ 的最长 border 长度，则 $\mathrm{next}[j]=\pi[j-1]+1$（$j\ge2$），$\mathrm{next}[1]=0$：
\begin{center}
\begin{tabular}{c|cccccccc}
$j$ & 1 & 2 & 3 & 4 & 5 & 6 & 7 & 8\\ \hline
$T[j]$ & a & b & c & a & b & a & b & c\\

图里 $\pi$ 行存的是 border 长度本身，next 行把它右移一位再加 1；$j=6$ 时看的是 $\pi[5]=2$，所以 $\mathrm{next}[6]=3$。$\mathrm{next}[1]=0$ 不对应任何 border，只是首字符失配时的哨兵。

$j=6$：前 5 个字符 \texttt{abcab} 的最长 border 是 \texttt{ab}，长度 2，所以 $\mathrm{next}[6]=3$。$j=4$：\texttt{abc} 没有非空 border，$\mathrm{next}[4]=1$。当 $m\ge2$ 时 $\mathrm{next}[2]=1$ 恒成立，因为前 1 个字符没有真前缀，border 长度为 0。

手算时每个 $j$ 都重新找 border，最坏 $O(m^2)$。利用已经算出的值可以做到 $O(m)$。设当前在求 $\mathrm{next}[i+1]$，$k$ 表示“当前候选 border 长度加 1”：
\begin{itemize}
  \item 若 $k=0$，没有更短的候选，直接让 $k$ 变成 1，$\mathrm{next}[i+1]=1$；
  \item 若 $T[i]=T[k]$，当前 border 可以延长一位，$k\leftarrow k+1$，$\mathrm{next}[i+1]=k$；
  \item 否则当前长度不行，退到更短的 border。$T[1..k-1]$ 的最长 border 长度是 $\mathrm{next}[k]-1$，所以令 $k\leftarrow\mathrm{next}[k]$，再比较 $T[i]$ 与新的 $T[k]$。
\end{itemize}
\begin{lstlisting}[language=C]
void GetNext(SString T, int next[]) {
    int i = 1, k = 0;
    next[1] = 0;
    while (i < T.length) {
        if (k == 0 || T.ch[i] == T.ch[k]) {
            ++i; ++k;
            next[i] = k;
        } else {
            k = next[k];          /* 退到更短的 border */
        }
    }
}
\end{lstlisting}
当 $k=0$ 时，条件里的 \texttt{T.ch[k]} 因为短路不会被读；随后 $k$ 变成 1，等价于“从空前缀重新开始配”。

拿 $T=\texttt{abcababc}$ 走一段：算到 $\mathrm{next}[6]=3$ 后，$i=6,k=3$。$T[6]=\texttt{a}\ne T[3]=\texttt{c}$，退到 $k=\mathrm{next}[3]=1$；再比 $T[6]=\texttt{a}=T[1]=\texttt{a}$，于是 $i=7,k=2$，$\mathrm{next}[7]=2$。这段过程就是下面这条链从 6 退到 3、再退到 1。

链上每个值都是“下一个候选位置”。$j=6$ 失配时，先试长度 2 的 border（跳到 3），不行再试长度 0（跳到 1），最后到哨兵 0。next 链的每个后继都严格变小，所以这条链最多走 $m$ 步。

预处理复杂度：$i$ 从 1 增到 $m$，只增不减；$k$ 每次失配严格减小，且只在 $i$ 增加时增加，所以总回退次数不超过 $m$，整个 \texttt{GetNext} 是 $O(m)$。

\subsection{前缀函数：同一个量的另一种记法}

很多教材和代码不用带哨兵的 next，而直接定义前缀函数
\[
\pi[i]=\max\{k\mid 0\le k<i,\ T[1..k]=T[i-k+1..i]\},
\]
即 $T[1..i]$ 的最长相等真前后缀长度，$\pi[1]=0$。它和 next 只差一个平移：
\[
\mathrm{next}[j]=\pi[j-1]+1\quad(j\ge2),\qquad \mathrm{next}[1]=0.
\]
反过来 $\pi[i]=\mathrm{next}[i+1]-1$。两者含的信息完全相同，做题时不要混用：题目要 next 就给带 1 的版本，要 $\pi$ 就给从 0 开始的长度。

0 下标实现里，模式串记作 $P[0..m-1]$，$\pi[0]=0$，$\pi[i]$ 表示 $P[0..i]$ 的最长 border 长度。构造代码比 1 下标的 \texttt{GetNext} 更短：
\begin{lstlisting}[language=C]
void GetPi(const char *P, int m, int pi[]) {
    pi[0] = 0;
    for (int i = 1, k = 0; i < m; ++i) {
        while (k > 0 && P[i] != P[k])
            k = pi[k - 1];       /* 退到更短的 border */
        if (P[i] == P[k]) ++k;
        pi[i] = k;
    }
}
\end{lstlisting}
这里 $k$ 直接就是 border 长度，不是 next 里的长度加 1，所以回退写 $\pi[k-1]$ 而不是 $\pi[k]$。这是两套写法最容易写错的地方。

用 $\pi$ 匹配时，$i$ 扫主串，$j$ 是已匹配长度；失配就 $j=\pi[j-1]$，$j=m$ 时报告起点 $i-m+1$，然后令 $j=\pi[j-1]$ 继续找下一次出现（允许重叠）。匹配阶段的摊还分析与 1 下标版本完全一样，仍是 $O(n)$。

\subsection{nextval：跳过注定失败的比较}

next 有一个小毛病：如果 $T[j]=T[\mathrm{next}[j]]$，失配后跳到 $\mathrm{next}[j]$，比较的还是同一个字符，必然再次失配。nextval 把这种连续相同的跳转一次走完。定义为
\[
\mathrm{nextval}[j]=
\begin{cases}
0, & j=1,\\
\mathrm{next}[j], & T[j]\ne T[\mathrm{next}[j]],\\
\mathrm{nextval}[\mathrm{next}[j]], & T[j]=T[\mathrm{next}[j]].
\end{cases}
\]
因为 $\mathrm{next}[j]<j$，右边的 $\mathrm{nextval}$ 在从左到右计算时已经求出，不需要真的递归。

先算一个具体例子。对 $T=\texttt{abcababc}$：
\begin{center}
\begin{tabular}{c|cccccccc}
$j$ & 1 & 2 & 3 & 4 & 5 & 6 & 7 & 8\\ \hline
$T[j]$ & a & b & c & a & b & a & b & c\\
$\mathrm{next}[j]$ & 0 & 1 & 1 & 1 & 2 & 3 & 2 & 3\\
$\mathrm{nextval}[j]$ & 0 & 1 & 1 & 0 & 1 & 3 & 1 & 1
\end{tabular}
\end{center}
$j=4$：$\mathrm{next}[4]=1$，而 $T[4]=T[1]=\texttt{a}$，跳到 1 仍会比较 \texttt{a}；$\mathrm{nextval}[4]=\mathrm{nextval}[1]=0$，直接让主串指针前进。$j=8$ 同理：$\mathrm{next}[8]=3$，$T[8]=T[3]=\texttt{c}$，所以 $\mathrm{nextval}[8]=\mathrm{nextval}[3]=1$。

再看一个重复字符更多的例子：$T=\texttt{aaaab}$ 时 $\mathrm{next}=(0,1,2,3,4)$，$\mathrm{nextval}=(0,0,0,0,4)$。若在 $j=4$ 失配（文本当前字符不是 \texttt{a}），按 next 会依次跳 3、2、1，每次都在比较 \texttt{a}，直到 $j=0$ 才前进主串；nextval 直接把 $j$ 置 0。$j=5$ 不一样：$T[5]=\texttt{b}\ne T[4]=\texttt{a}$，所以 $\mathrm{nextval}[5]=\mathrm{next}[5]=4$，这里没有可跳过的重复字符。

代码和 \texttt{GetNext} 的差别只有两处：匹配成功时根据 $T[i]$ 与 $T[k]$ 是否相同决定写 $k$ 还是 $\mathrm{nextval}[k]$；失配回退用 $\mathrm{nextval}[k]$ 而不是 $\mathrm{next}[k]$。

\begin{lstlisting}[language=C]
void GetNextVal(SString T, int nextval[]) {
    int i = 1, k = 0;
    nextval[1] = 0;
    while (i < T.length) {
        if (k == 0 || T.ch[i] == T.ch[k]) {
            ++i; ++k;
            nextval[i] = (T.ch[i] != T.ch[k]) ? k : nextval[k];
        } else k = nextval[k];     /* 沿 nextval 链回退 */
    }
}
\end{lstlisting}

\begin{attention}
408 选择题里最容易错的几处：
\begin{itemize}
  \item $\mathrm{next}[j]$ 看的是前 $j-1$ 个字符，不是前 $j$ 个；$\mathrm{next}[1]=0$ 是哨兵，不对应 border。
  \item 下标从 1 开始时 $\mathrm{next}[1]=0$、$\mathrm{next}[2]=1$（$m\ge2$）；若改用 0 下标并令 $\mathrm{next}[0]=-1$，1 下标的值整体减 1；若直接问前缀函数 $\pi$，$\pi[i]$ 是 border 长度本身。
  \item 失配后的位移是 $j-\mathrm{next}[j]$，不是 $\mathrm{next}[j]-1$。
  \item BF 最坏 $O(nm)$，KMP 是 $O(n+m)$；不要把 BF 的平均情况当成最坏情况。
  \item next 只由模式串决定，和主串无关；同一个 $T$ 在不同 $S$ 上 next 不变。
\end{itemize}
\end{attention}
