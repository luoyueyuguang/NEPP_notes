\section{排序}

把 $n$ 个记录按关键字排成非递减序列，看起来只是比较和交换，实际要同时考虑三件事：比较多少次、搬动多少数据、关键字相同的记录会不会被拆散。以考生成绩表为例，总分相同的两个人原本按准考证号排列；如果排序后他们的先后次序变了，名次就会跟着变，这正是稳定性要解决的问题。

设待排序的记录为 $R_1,R_2,\dots,R_n$，对应的关键字为 $k_1,k_2,\dots,k_n$。排序就是确定一个排列 $p(1),p(2),\dots,p(n)$，使
\[
k_{p(1)}\leqslant k_{p(2)}\leqslant\cdots\leqslant k_{p(n)}.
\]
如果 $k_i=k_j$ 且 $i<j$，排序后 $R_i$ 仍然排在 $R_j$ 前面，就称这个排序算法是\textbf{稳定的}；否则称它是\textbf{不稳定的}。注意稳定性只对关键字相等的记录有意义，关键字各不相同时无所谓稳定与否。

按数据是否全部放进内存，排序分为\textbf{内部排序}和\textbf{外部排序}。内部排序的全部记录都在内存中，本章前面的插入、交换、选择、归并、基数排序都属于这一类；外部排序处理的是内存装不下的大文件，排序过程中要反复读写外存，做法一般是“先在内存中生成若干有序的初始归并段，再反复归并”。评价一个内部排序算法，主要看时间复杂度（比较次数与移动次数之和）、辅助空间和稳定性；外部排序还要看读写外存的次数，因为磁盘 I/O 通常比内存中的比较慢几个数量级。

\subsection{插入排序}

插入排序维护一个已经有序的前缀，每次把后面的一个记录插进这个前缀。它和整理扑克牌一样：左手是排好的牌，右手摸到新牌后，从右往左找位置插进去，后面的牌依次让位。

这里有一个贯穿始终的不变式：进入第 $i$ 趟时，前缀 $A[0..i-1]$ 已经有序；把 $A[i]$ 插进去后，前缀扩大到 $A[0..i]$，仍然有序。从 $i=1$ 做到 $i=n-1$，整个数组就排好了。插入排序是稳定的、原地的，在序列基本有序时非常快；代价是元素的后移，最坏情况下每趟都要搬动整个前缀。

\subsubsection{直接插入排序}

以 $\{49,38,65,97,76,13,27,49'\}$ 为例，带撇的 $49'$ 表示关键字同为 49 的另一个记录。初始时把第一个元素 49 看作已排好的前缀，随后依次插入 38、65、97、76、13、27、49'：
\[
\begin{aligned}
&49\mid 38\;65\;97\;76\;13\;27\;49'\\
\to\;&38\;49\mid 65\;97\;76\;13\;27\;49'\\
\to\;&38\;49\;65\mid 97\;76\;13\;27\;49'\\
\to\;&38\;49\;65\;97\mid 76\;13\;27\;49'\\
\to\;&38\;49\;65\;76\;97\mid 13\;27\;49'\\
\to\;&13\;38\;49\;65\;76\;97\mid 27\;49'\\
\to\;&13\;27\;38\;49\;65\;76\;97\mid 49'\\
\to\;&13\;27\;38\;49\;49'\;65\;76\;97.
\end{aligned}
\]
竖线左边是已排序前缀。插入 76 时，97 后移一格；插入 13 时，前缀里的元素全部后移；插入 49' 时，它停在 49 的后面，因为循环条件用的是严格大于。

\begin{lstlisting}[language=C]
void InsertSort(int A[], int n) {
    for (int i = 1; i < n; i++) {
        int temp = A[i], j = i - 1;
        while (j >= 0 && A[j] > temp) {   // 严格大于才后移
            A[j + 1] = A[j];
            j--;
        }
        A[j + 1] = temp;
    }
}
\end{lstlisting}

图里每一行是插入 $A[i]$ 之后的数组状态，浅色格子是已排序前缀，深色格子是刚插入的记录。可以看到插入排序只做“后移”和“填回”两种动作，前缀之外的元素从不被访问。

直接插入排序的比较次数和初始序列关系很大。最好情况是初始已经有序：每趟只比较一次就发现不用后移，共 $n-1$ 次比较，移动 0 次，时间 $O(n)$。最坏情况是初始逆序：第 $i$ 趟要比较 $i$ 次，总比较次数
\[
\sum_{i=1}^{n-1} i=\frac{n(n-1)}{2},
\]
后移次数也是 $\frac{n(n-1)}{2}$；若把每次暂存 \texttt{temp} 和最后回填也算作移动，还要再加 $2(n-1)$ 次。平均情况下比较和后移都约为 $\frac{n^2}{4}$，时间复杂度仍是 $O(n^2)$。辅助空间只有一个 \texttt{temp}，为 $O(1)$。循环条件是 \texttt{A[j] > temp}，等于时不后移，所以直接插入排序稳定。

若数组从下标 1 开始，常见写法是把 $A[0]$ 当作\textbf{哨兵}：把待插入记录本身存进 $A[0]$，内层循环就可以省掉 \texttt{j >= 0} 的判断，因为比较到下标 0 时 \texttt{A[0] > temp} 为假，循环自然停止。408 题里看到 $A[0]$ 不参与排序结果，就是这种带哨兵的写法；此时元素存放在 $A[1..n]$，有效长度是 $n$。

\subsubsection{折半插入排序}

折半插入排序只改“找位置”这一步。既然前缀 $A[0..i-1]$ 已经有序，插入 $A[i]$ 时可以用二分查找确定它应该落在哪里，而不必从后往前逐个比较。

\begin{lstlisting}[language=C]
void BinInsertSort(int A[], int n) {
    for (int i = 1; i < n; i++) {
        int temp = A[i];
        int low = 0, high = i - 1;
        while (low <= high) {                // 在前缀中折半查找
            int mid = (low + high) / 2;
            if (A[mid] > temp) high = mid - 1;
            else               low  = mid + 1;  // 相等时插到后面
        }
        for (int j = i - 1; j >= low; j--)   // 统一后移
            A[j + 1] = A[j];
        A[low] = temp;
    }
}
\end{lstlisting}

折半查找每趟最多比较 $\lceil\log_2(i+1)\rceil$ 次，$n$ 趟累计的比较次数为 $\Theta(n\log n)$，比直接插入排序的 $\Theta(n^2)$ 少。但找到位置之后，后移的元素个数没有变：前缀中大于 \texttt{temp} 的元素仍然要全部后移。所以移动次数的最坏情况仍是 $\Theta(n^2)$，总时间复杂度还是 $O(n^2)$，只是常数中的比较部分小了。折半插入排序的循环在 \texttt{A[mid] == temp} 时令 \texttt{low = mid + 1}，把相等记录插在后面，因此它也是稳定的。它适合比较操作很贵、移动相对便宜的场合；408 若问“折半插入减少了什么”，答案只是比较次数。

\subsubsection{希尔排序}

希尔排序（缩小增量排序）换了一个思路：先让相隔较远的元素大致归位，使序列变得“基本有序”，最后再做一次直接插入排序时，后移的距离就会短很多。

具体做法是取一个增量 $d$，把下标相差 $d$ 的记录看成一组，例如 $A[i],A[i+d],A[i+2d],\dots$ 为一组；对每组分别做直接插入排序。然后缩小 $d$，重复上述过程，直到 $d=1$，此时整个序列做一次普通的直接插入排序。注意分组不是把数组切成连续的三段，而是按固定间隔“跳着”取元素。

仍以 $\{49,38,65,97,76,13,27,49',55,4\}$ 为例。$d=5$ 时五组分别是 $(49,13)$、$(38,27)$、$(65,49')$、$(97,55)$、$(76,4)$，组内排序后得到
\[
\{13,27,49',55,4,49,38,65,97,76\}.
\]
接着取 $d=3$，三组为 $(13,55,38,76)$、$(27,4,65)$、$(49',49,97)$，排完得到
\[
\{13,4,49',38,27,49,55,65,97,76\}.
\]
最后 $d=1$ 做一次直接插入排序，得到
\[
\{4,13,27,38,49',49,55,65,76,97\}.
\]
原来 49 排在 49' 前面，最终 49' 却跑到了 49 前面。原因是 $d=5$ 时 49 和 49' 被分进了不同的组，排序后它们的相对次序就变了；后面的趟都是稳定排序，无法把这个次序改回来。所以希尔排序\textbf{不稳定}。

\begin{lstlisting}[language=C]
void ShellSort(int A[], int n) {
    for (int d = n / 2; d >= 1; d /= 2) {   // 增量每次减半
        for (int i = d; i < n; i++) {
            int temp = A[i], j = i - d;
            while (j >= 0 && A[j] > temp) { // 组内直接插入
                A[j + d] = A[j];
                j -= d;
            }
            A[j + d] = temp;
        }
    }
}
\end{lstlisting}

希尔排序的时间复杂度取决于增量序列，不能用一个统一的式子写完。取初始增量 $d=\lfloor n/2\rfloor$、之后每次减半直到 1 时，最坏情况是 $O(n^2)$；改用 Hibbard 增量 $1,3,7,\dots,2^k-1$，最坏可降到 $O(n^{3/2})$；Sedgewick 增量还能更好。平均情况下它通常明显快于直接插入排序，经验上常被写成 $O(n^{1.3})$ 左右，但这不是对所有增量序列都成立的严格结论。408 一般只要求会按给定增量手工模拟，并记住“依赖增量、通常优于 $O(n^2)$、最坏仍可能到 $O(n^2)$、不稳定、空间 $O(1)$”。

\subsection{交换排序}

交换排序通过交换逆序的元素对来逐步消除逆序。冒泡排序只交换相邻元素，快速排序则把元素交换到离枢轴较远的位置，因此两者的常数和适用场景差别很大。

\subsubsection{冒泡排序}

冒泡排序每趟从前往后扫描，比较相邻的两个元素，逆序就交换。一趟下来，当前未排序部分的最大元素会被一路“冒”到最后。下一趟的扫描范围就可以缩短一格。

以 $\{6,2,8,4,9,1,7\}$ 为例：
\[
\begin{aligned}
&6\;2\;8\;4\;9\;1\;7\\
\to\;&2\;6\;4\;8\;1\;7\mid 9\\
\to\;&2\;4\;6\;1\;7\mid 8\;9\\
\to\;&2\;4\;1\;6\mid 7\;8\;9\\
\to\;&2\;1\;4\mid 6\;7\;8\;9\\
\to\;&1\;2\;4\;6\;7\;8\;9.
\end{aligned}
\]
第一趟把 9 送到末尾，第二趟把 8 送到倒数第二格，依此类推。第五趟结束后整个序列已经有序，第六趟扫描时没有发生任何交换，算法就可以提前结束。

\begin{lstlisting}[language=C]
void BubbleSort(int A[], int n) {
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (A[j] > A[j + 1]) {        // 严格大于才交换
                int t = A[j]; A[j] = A[j + 1]; A[j + 1] = t;
                swapped = true;
            }
        }
        if (!swapped) break;               // 本趟无交换，已有序
    }
}
\end{lstlisting}

冒泡排序最好情况是初始有序：第一趟比较 $n-1$ 次、不交换，直接结束，时间 $O(n)$。最坏情况是初始逆序：比较次数为
\[
\sum_{i=1}^{n-1}(n-i)=\frac{n(n-1)}{2},
\]
每次比较都交换，一次交换要 3 次赋值，移动次数为 $\frac{3n(n-1)}{2}$，时间 $O(n^2)$。平均也是 $O(n^2)$，辅助空间 $O(1)$。

冒泡排序的稳定性由交换条件决定。写 \texttt{A[j] > A[j+1]} 时，相等元素不会交换，相对次序不变；若写成 \texttt{>=}，相等的两个元素也会交换，排序就不稳定了。这一点和直接插入排序的 \texttt{>} 是同一个道理。

\subsubsection{快速排序}

快速排序把排序拆成“划分”和“递归”两步。划分选一个枢轴（pivot），把序列重新排列成“左边都不大于枢轴，右边都不小于枢轴”，枢轴本身落到最终位置；然后对左右两段分别递归。

以 $\{49,38,65,97,76,13,27,49'\}$ 为例，取第一个元素 49 为枢轴。先从右往左找第一个小于 49 的 27，把它填到左端的坑里；再从左往右找第一个大于 49 的 65，填到右端的坑里；继续右找小、左找大，直到两个指针相遇，最后把 49 放进相遇处的坑。一趟划分后序列变成
\[
\{27,38,13\}\;49\;\{76,97,65,49'\},
\]
49 落在下标 3，左边三个元素都小于它，右边四个元素都不小于它。注意左右两段内部还没有排好，只是被分到了枢轴两边。

\begin{lstlisting}[language=C]
int Partition(int A[], int low, int high) {
    int pivot = A[low];                    // 取第一个元素为枢轴
    while (low < high) {
        while (low < high && A[high] >= pivot) high--;
        A[low] = A[high];                  // 右边的小数填左坑
        while (low < high && A[low] <= pivot) low++;
        A[high] = A[low];                  // 左边的大数填右坑
    }
    A[low] = pivot;                        // 枢轴落位
    return low;
}
\end{lstlisting}

\begin{lstlisting}[language=C]
void QuickSort(int A[], int low, int high) {
    if (low < high) {
        int p = Partition(A, low, high);
        QuickSort(A, low, p - 1);
        QuickSort(A, p + 1, high);
    }
}
\end{lstlisting}

划分过程从两端向中间扫描，每趟划分对长度为 $m$ 的区间做 $O(m)$ 次比较和移动，因此总时间取决于递归树的样子。如果每次枢轴都落在中间，递归树近似平衡：
\[
T(n)=2T(n/2)+O(n)\quad\Longrightarrow\quad T(n)=O(n\log n).
\]
如果每次枢轴都是当前区间的最小或最大值，例如初始序列已经有序、又固定取第一个元素作枢轴，那么每次划分只减少一个元素：
\[
T(n)=T(n-1)+O(n)\quad\Longrightarrow\quad T(n)=O(n^2).
\]
平均情况下，枢轴大致落在中间附近，可以证明 $T(n)=O(n\log n)$。

快速排序的最好和平均时间复杂度为 $O(n\log n)$，最坏为 $O(n^2)$。空间开销来自递归工作栈：划分均匀时栈深 $O(\log n)$，最坏时栈深 $O(n)$，平均 $O(\log n)$。快速排序不稳定，因为划分时的填坑/交换是跳跃式的。一个最小的反例是 $\{5,5',2,6,1\}$，取首元素 5 为枢轴，一趟划分后得到 $\{1,5',2,5,6\}$，两个 5 的次序已经反了。

实际实现中常用随机选枢轴或“三数取中”来避免最坏情况；408 题目若没有特别说明，一般按“取第一个元素”处理。还有一点容易混：有的题把一次划分叫“一趟”，有的题把递归树的一层叫“一趟”，两种口径的趟数不同，做题时先看题干怎么定义。

\subsection{选择排序}

选择排序每趟从尚未排序的部分中选出最小（或最大）的记录，放到这部分的前端。简单选择排序用线性扫描找最小元，堆排序则用堆来加速找最小元的过程。

\subsubsection{简单选择排序}

以 $\{5,8,2,9,1,7\}$ 为例。第一趟在全部 6 个元素中找最小值 1，与第一个元素 5 交换，得到 $\{1,8,2,9,5,7\}$；第二趟在剩下的 $\{8,2,9,5,7\}$ 中找最小值 2，与 8 交换，得到 $\{1,2,8,9,5,7\}$；继续下去，直到前 $n-1$ 个位置都确定。

\begin{lstlisting}[language=C]
void SelectSort(int A[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++)
            if (A[j] < A[min]) min = j;
        if (min != i) {
            int t = A[i]; A[i] = A[min]; A[min] = t;
        }
    }
}
\end{lstlisting}

\[

\]

\subsubsection{堆排序}

堆是一棵\textbf{完全二叉树}，并且每个非叶结点都不小于它的孩子（\textbf{大根堆}），或者都不大于它的孩子（\textbf{小根堆}）。大根堆的根是整棵树的最大值，小根堆的根是最小值。完全二叉树适合顺序存储：把结点按层序放进数组，父子关系可以直接用下标算出来。

图里同一棵完全二叉树的两种看法：上面是树，下面是数组。树上的小数字是数组下标，按层序一一对应。下标从 0 开始时，$i$ 的左孩子是 $2i+1$、右孩子是 $2i+2$、双亲是 $\lfloor(i-1)/2\rfloor$；最后一个非叶结点是 $\lfloor n/2\rfloor-1$，叶子从 $\lfloor n/2\rfloor$ 开始。408 教材也常用下标从 1 开始，那时左孩子是 $2i$、右孩子是 $2i+1$、双亲是 $\lfloor i/2\rfloor$，最后一个非叶结点是 $\lfloor n/2\rfloor$，做题前要先看清题目用的是哪一种。

堆的核心操作是\textbf{向下调整}（下沉）。假设以 $A[k]$ 为根的左右子树都已经是堆，只有 $A[k]$ 可能违反堆序，那么把 $A[k]$ 与较大的孩子交换，再沿着这条路径继续向下，直到它不小于两个孩子或者到达叶子。对长度为 $n$ 的堆，一次下沉最多走 $\lfloor\log_2 n\rfloor$ 层，每层最多比较两次（选较大的孩子、与根比较），所以是 $O(\log n)$。

\begin{lstlisting}[language=C]
// 大根堆的向下调整，堆的大小为 n
void SiftDown(int A[], int k, int n) {
    int temp = A[k];
    for (int i = 2 * k + 1; i < n; i = 2 * k + 1) {
        if (i + 1 < n && A[i] < A[i + 1]) i++;  // 选较大的孩子
        if (temp >= A[i]) break;                // 已满足堆序
        A[k] = A[i];
        k = i;
    }
    A[k] = temp;
}
\end{lstlisting}

建堆时，叶子本身可以看作大小为 1 的堆，所以从最后一个非叶结点开始，依次向前对每个结点做一次下沉。这样处理到根时，根的左右子树都已经是堆，正好满足下沉的前提。

\begin{lstlisting}[language=C]
void BuildMaxHeap(int A[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--)
        SiftDown(A, i, n);
}
\end{lstlisting}

建堆的总时间复杂度是 $O(n)$，不是 $O(n\log n)$。直观上，越靠近叶子的结点越多，但它们下沉的距离越短；第 $h$ 层的结点数约为 $n/2^{h+1}$，每个最多下沉 $h$ 层，总和
\[
\sum_{h\geqslant 0}\frac{n}{2^{h+1}}\cdot O(h)=O(n)\sum_{h\geqslant 0}\frac{h}{2^h}=O(n).
\]
真正排序时，先把数组建成大根堆，然后重复“把堆顶与当前堆的最后一个元素交换，堆的大小减 1，再对新堆顶下沉”。每交换一次，最大值就落到数组末尾的已排序区。

\begin{lstlisting}[language=C]
void HeapSort(int A[], int n) {
    BuildMaxHeap(A, n);
    for (int i = n - 1; i > 0; i--) {
        int t = A[0]; A[0] = A[i]; A[i] = t;  // 堆顶换到末尾
        SiftDown(A, 0, i);                    // 剩余 i 个元素恢复成堆
    }
}
\end{lstlisting}

堆排序不稳定。反例是 $\{5,5',3\}$：它已经是大根堆，第一次把堆顶 5 与末尾 3 交换，得到 $\{3,5',5\}$；下沉后变成 $\{5',3,5\}$；最后得到 $\{3,5',5\}$，5' 跑到了 5 前面。原因是堆顶和堆尾的交换是远距离的，相等关键字的相对次序无法保证。

堆本身还支持两种常用操作。\textbf{插入}：把新记录放到数组末尾，然后\textbf{向上调整}（上浮），与双亲比较，比双亲大就交换，直到满足堆序，代价 $O(\log n)$。\textbf{删除堆顶}：把最后一个记录移到堆顶，堆的大小减 1，再对堆顶下沉，代价也是 $O(\log n)$。这两种操作只影响一条从根到叶（或从叶到根）的路径，所以不需要重建整个堆。

\subsection{归并排序}

归并排序把两个已经有序的段合并成一个有序段。二路归并是最基本的形式：两个指针分别指向两段的开头，每次取较小的那个放到辅助数组，直到一段取完，再把另一段剩下的元素直接复制过去。

\begin{lstlisting}[language=C]
void Merge(int A[], int low, int mid, int high) {
    int *B = (int *)malloc((high - low + 1) * sizeof(int));
    int i = low, j = mid + 1, k = 0;
    while (i <= mid && j <= high) {
        if (A[i] <= A[j]) B[k++] = A[i++];  // 相等时先取左段
        else              B[k++] = A[j++];
    }
    while (i <= mid)  B[k++] = A[i++];
    while (j <= high) B[k++] = A[j++];
    for (i = low, k = 0; i <= high; i++, k++) A[i] = B[k];
    free(B);
}

void MergeSort(int A[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        MergeSort(A, low, mid);
        MergeSort(A, mid + 1, high);
        Merge(A, low, mid, high);
    }
}
\end{lstlisting}

归并排序的时间复杂度在最好、平均、最坏情况下都是 $O(n\log n)$。最好情况下比较次数少一些（两段交错得少，一段很快取完）；最坏情况下比较次数为 $\Theta(n\log n)$（$n=2^k$ 时恰为 $n\log_2 n-n+1$），量级不变。辅助数组需要 $n$ 个记录的空间，递归栈还需要 $O(\log n)$，总空间为 $O(n)$。合并时用 \texttt{A[i] <= A[j]} 保证相等时先取左段，所以归并排序稳定。它的代价是额外的 $O(n)$ 空间，这也是内部排序中“用空间换稳定”的典型。

\subsection{基数排序}

基数排序不比较关键字的大小，而是把关键字拆成若干位，按位分配和收集。以十进制整数为例，每个关键字可以看成 $d$ 位数字，每一位有 $r=10$ 种取值。最低位优先（LSD）的做法是：先按个位把记录分配到 10 个队列，再依次收集；然后按十位分配、收集；直到最高位。每趟分配和收集都必须稳定，否则前一趟排好的次序会被打乱。

以 $\{278,109,63,930,589,184,505,269,8,83\}$ 为例，个位分配的结果是：0 号队列有 930，3 号有 63、83，4 号有 184，5 号有 505，8 号有 278、8，9 号有 109、589、269。按队列编号从小到大收集，得到
\[
\{930,63,83,184,505,278,8,109,589,269\}.
\]
十位再分配、收集，得到
\[
\{505,8,109,930,63,269,278,83,184,589\}.
\]
最后按百位分配、收集，得到
\[
\{8,63,83,109,184,269,278,505,589,930\}.
\]

下面的数组版用计数排序完成每一趟“分配”和“收集”：先数出每个桶有多少个记录，算出每个桶在辅助数组中的起始位置，再按原序把记录放进对应的桶。链式版只是把辅助数组换成队列指针，思路相同。

\newpage
\begin{lstlisting}[language=C]
void RadixSort(int A[], int n, int d) {
    int *B = (int *)malloc(n * sizeof(int));
    int cnt[10], pos[10];
    int radix = 1;
    for (int p = 0; p < d; p++) {
        for (int r = 0; r < 10; r++) cnt[r] = 0;
        for (int i = 0; i < n; i++)          // 统计每个桶的记录数
            cnt[(A[i] / radix) % 10]++;
        pos[0] = 0;
        for (int r = 1; r < 10; r++)         // 每个桶的起始下标
            pos[r] = pos[r - 1] + cnt[r - 1];
        for (int i = 0; i < n; i++) {        // 按原序放入，保证稳定
            int r = (A[i] / radix) % 10;
            B[pos[r]++] = A[i];
        }
        for (int i = 0; i < n; i++) A[i] = B[i];
        radix *= 10;
    }
    free(B);
}
\end{lstlisting}

设关键字有 $d$ 位、基数为 $r$、记录数为 $n$。每趟分配要扫描 $n$ 个记录，收集要扫描 $r$ 个队列并把 $n$ 个记录接起来，所以每趟 $O(n+r)$，$d$ 趟共
\[
O\bigl(d(n+r)\bigr).
\]
若 $d$ 和 $r$ 都可以看作常数，基数排序是线性的 $O(n)$。辅助空间包括 $r$ 个队列的头尾指针；若记录用链结点串起来，还要 $n$ 个指针域，合计 $O(n+r)$。基数排序稳定，前提是每一趟的分配和收集都稳定。

基数排序还有最高位优先（MSD）的版本：先按最高位分组，再对每组递归地排下一位。MSD 不要求全局稳定，但实现更复杂，408 主要考 LSD。基数排序不是基于比较的排序，所以不受“比较排序最坏 $\Omega(n\log n)$”下界的限制；它的代价是要把关键字拆成位，并且位的取值范围不能太大，否则 $r$ 个队列的开销会超过比较排序。

\subsection{内部排序方法的比较}

把前面几种内部排序放在一起，可以看到它们在最好/平均/最坏时间、辅助空间和稳定性上的取舍。

\begin{tablebox}{内部排序算法比较}
\centering
\small
\begin{tabular}{lcccccc}
\toprule

表里的“最好时间”按比较和移动的总量来算。折半插入排序即使初始有序，也要为每个元素做一次折半查找，比较次数是 $\Theta(n\log n)$，所以最好情况不是 $O(n)$；但它的移动次数为 0，实际运行仍然很快。希尔排序的最坏 $O(n^2)$ 是就 $d=\lfloor n/2\rfloor,\lfloor n/4\rfloor,\dots$ 这个增量序列而言的，换增量序列上界会变。

怎么选算法，可以先看数据规模和初始状态。$n$ 很小时（例如几十个记录），直接插入排序和简单选择排序的常数小，反而比快排、归并快；若初始基本有序，直接插入或冒泡可以做到 $O(n)$，而简单选择排序仍要做满 $n(n-1)/2$ 次比较。$n$ 较大时，快速排序的平均常数最小，是通用内部排序的首选；但它最坏会退化到 $O(n^2)$，对初始有序的序列要特别小心。堆排序的最坏时间有保证，辅助空间只有 $O(1)$，适合空间紧张又要求稳定性能的场合，代价是常数比快排大。归并排序稳定，时间也稳定在 $O(n\log n)$，但需要 $O(n)$ 的辅助空间，常用在外部排序和链表排序中。若关键字可以拆成位数不多的“位”，基数排序可以做到线性，但它依赖关键字的表示形式。

要求稳定时，可以选择直接插入、冒泡、归并、基数排序；希尔、简单选择、快速、堆排序都不稳定。这个结论不要只背表，最好能各举一个反例：希尔是远距离分组，简单选择是把最小值换到前面，快速是填坑时跨过相等元素，堆是堆顶与堆尾交换。

图里是一棵比较判定树：每个内部结点是一次两两比较，每个叶子是一种可能的排列。3 个元素有 6 种排列，所以树至少要有 6 个叶子；二叉树高度为 $h$ 时最多有 $2^h$ 个叶子，因此 $h\geqslant\lceil\log_2 6\rceil=3$。推广到 $n$ 个元素，判定树至少有 $n!$ 个叶子，高度至少 $\lceil\log_2(n!)\rceil=\Theta(n\log n)$。这就是基于比较的排序最坏情况下界 $\Omega(n\log n)$ 的来源；堆排序和归并排序达到了这个量级，而基数排序因为不靠比较，可以突破这个下界。

还有几个和“趟数”有关的结论容易混。冒泡排序最多 $n-1$ 趟，最好 1 趟（第一趟无交换就结束）；简单选择排序和堆排序都是 $n-1$ 趟，每趟确定一个元素的最终位置；归并排序是 $\lceil\log_2 n\rceil$ 趟，与初始序列无关；基数排序是 $d$ 趟，$d$ 是关键字的位数；希尔排序的趟数等于增量序列的长度；快速排序的划分次数等于递归树的内部结点数，平衡或随机时约为 $\Theta(n)$，最坏为 $n-1$；递归深度最好/平均为 $O(\log n)$，最坏为 $O(n)$。比较这些数字时，先确认题目说的“一趟”是划分次数还是递归层数。

\subsection{外部排序}

内部排序要求所有记录同时放在内存里。如果文件有几十 GB，内存只有几百 MB，就不可能一次装下。外部排序的做法是：先把文件分成若干块，每块读入内存做内部排序，得到一个有序的\textbf{初始归并段}（run），写回外存；然后对这些归并段反复做多路归并，直到只剩一个有序文件。

设文件有 $N$ 个记录，内存缓冲区一次能容纳 $w$ 个记录，则初始归并段的个数约为
\[
m=\left\lceil\frac{N}{w}\right\rceil.
\]
若采用 $k$ 路平衡归并，每趟把 $k$ 个段合并成一个，段数变为原来的约 $1/k$，需要的趟数为
\[
t=\lceil\log_k m\rceil.
\]
例如 $m=100$、$k=4$ 时，$4^3=64<100$，$4^4=256\geqslant100$，所以需要 4 趟，而不是 3 趟。

\[
2N(t+1)=2N\bigl(1+\lceil\log_k m\rceil\bigr).
\]
外部排序的总时间由三部分组成：生成初始段时的内部排序时间、外存读写时间、归并时的内部比较时间。三者中外存读写通常占主导，所以减少归并趟数比减少比较次数更重要。

增大 $k$ 可以减少趟数，但 $k$ 路归并需要 $k$ 个输入缓冲区和 1 个输出缓冲区，内存中至少要能放下 $k+1$ 个块；$k$ 太大时每个缓冲区变小，I/O 的块数反而增加。另一个限制是内部归并的代价：如果每输出一个记录都线性扫描 $k$ 个段的首元素，最多需要 $k-1$ 次比较，一整趟最多约 $(k-1)N$ 次比较，$k$ 增大后这部分会变得很重。\textbf{败者树}就是用来把“选最小”的代价降到 $O(\log k)$ 的。

\end{center}

图里 $k=4$ 个叶子是 4 个归并段的当前首记录，内部结点保存比较的失败者，冠军单独放在根的上方。初始时 15 与 8 比较，8 胜、15 留在左内部结点；23 与 12 比较，12 胜、23 留在右内部结点；8 与 12 比较，8 胜、12 留在根结点，冠军为 8。若段 2 的下一个记录变成 30，只需沿虚线从叶子走到根：30 与结点里的 15 比较，15 胜、30 留下；15 再与根里的 12 比较，12 胜、15 留下；冠军变为 12。整条路径只有 2 次比较，而不是重新扫描 4 个段。

败者树的叶结点数为 $k$，内部结点数为 $k-1$，树高为 $\lceil\log_2 k\rceil$。初始建树需要 $k-1$ 次比较；此后每输出一个记录，沿叶到根的路径重赛，最多 $\lceil\log_2 k\rceil$ 次比较。归并 $N$ 个记录的总比较次数约为 $N\lceil\log_2 k\rceil$，比线性扫描的 $N(k-1)$ 小得多。\textbf{胜者树}也能做同样的事，但胜者树的内部结点保存胜者，重赛时要访问兄弟结点才能知道另一个候选者；败者树保存失败者，胜者可以直接和父结点中保存的失败者比较，访问的结点更少，这是它名字的由来。

初始归并段的长度不一定等于缓冲区大小。\textbf{置换-选择排序}可以在缓冲区只有 $W$ 个记录时，生成比 $W$ 长得多的归并段：先把 $W$ 个记录建成小根堆，输出堆顶（当前段的最小值）；读入下一个记录，如果它不小于刚输出的记录，就插入堆中继续参与当前段，否则暂存起来留给下一段；堆空时当前段结束，用暂存的记录建新堆，开始下一段。

图里是置换-选择的流程：判断“新记录是否不小于上次输出”是核心，满足就继续留在当前段，不满足就推迟到下一段。因为推迟的记录不参与当前堆，堆中始终有记录可输出，所以一个段可以超过缓冲区容量。对随机排列的输入，段的平均长度约为 $2W$；输入已经升序时，所有记录都能留在同一个段中，段长为 $N$；输入逆序时，每读入一个记录都要推迟，段长退化为 $W$。

当各初始归并段的长度不相等时，归并的先后顺序会影响总 I/O。把归并段看成带权叶子，权值是段长，构造一棵 $k$ 叉 Huffman 树，使带权路径长度
\[
\mathrm{WPL}=\sum_{i=1}^{m} w_i\,l_i
\]
最小，其中 $w_i$ 是第 $i$ 段的长度，$l_i$ 是它在树中的深度。这棵树叫\textbf{最佳归并树}，按它自底向上归并，总读写次数为 $2\,\mathrm{WPL}$。

图里是 9 个归并段、3 路归并的最佳归并树，叶子上的数字是段长，圆圈里的数字是合并后的段长。构造过程和 Huffman 树一样：每次取权值最小的 3 个结点合并，$2+3+6=11$，$9+11+12=32$，$17+18+24=59$，最后 $30+32+59=121$。按这棵树归并，WPL 为
\[
30\times1+(9+12+17+18+24)\times2+(2+3+6)\times3
=30+160+33=223,
\]
总读写次数为 $2\times223=446$。

如果初始段数 $m$ 不满足 $(m-1)\bmod(k-1)=0$，这棵树就不是严格的 $k$ 叉树，最后一层会有“缺孩子”的结点，Huffman 构造不能直接进行。这时要补若干个长度为 0 的虚拟段，把段数凑到满足条件为止。需要补的个数为
\[
(k-1)-\bigl((m-1)\bmod(k-1)\bigr).
\]
例如 $m=8$、$k=3$ 时，$(8-1)\bmod2=1$，需要补 1 个长度为 0 的段，按 9 个段构造；虚拟段不贡献 WPL，只是把树补成满 3 叉树。$m=9$、$k=3$ 时 $(9-1)\bmod2=0$，不需要补段，正好是图里的情况。
