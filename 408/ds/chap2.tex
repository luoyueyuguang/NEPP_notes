\section{栈与队列}

在文本编辑器里连按几次撤销，撤掉的内容正好按输入的逆序消失；打印机则相反，先提交的文档先输出。前一条规则是“后进先出”，后一条是“先进先出”，它们分别对应本章的两个主角——栈和队列。两者都是线性表，只是把插入、删除的位置限制住了：栈只允许在一端动手，队列规定一端进、另一端出。限制减少了可用的操作，却让“记住最近的若干件事”和“按到达顺序处理”变得非常直接。

这一章先看两种结构在顺序存储和链式存储下如何落地，重点是指针的约定和边界条件；然后把循环队列的下标运算讲清楚；接着用表达式求值说明栈的典型用法；最后讨论两端都能进出的双端队列。

\subsection{栈：把操作挤到一端}

栈只允许在表的一端插入和删除。允许操作的一端叫栈顶（top），另一端叫栈底（bottom）；插入叫入栈（push），删除叫出栈（pop）。

\begin{mydef}{栈}{stack-def}
栈是只允许在表的一端进行插入和删除的线性表。插入和删除都在栈顶进行，元素按后进先出（LIFO, Last In First Out）的次序离开。
\end{mydef}

这个定义有个直接推论：栈底元素只有在它上面的元素全部弹出后才可能被访问，所以栈不能像顺序表那样按下标随机存取。反过来说，判空、取栈顶、入栈、出栈都只碰栈顶，时间都是 $O(1)$。

\subsubsection*{顺序栈：top 到底指哪里}

最直接的做法是用一段连续空间 \texttt{data[0..MaxSize-1]} 存放元素，再用一个整数 \texttt{top} 记录栈顶位置。数组本身没有方向，代码怎么写取决于 \texttt{top} 指向哪里。408 常见两种约定：让 \texttt{top} 指向栈顶元素，或者让它指向栈顶上面的那个空位。

两种写法没有优劣，但公式不能混用。做选择题时先看初始化语句：若 \texttt{top = -1}，就是第一种；若 \texttt{top = 0}，就是第二种。入栈和出栈的“先移指针”与“先读写”也要跟着变——\texttt{++top} 是先加再用，\texttt{top++} 是先用再加，恰好对应“top 指栈顶”和“top 指空位”两种语义。

按第一种约定，顺序栈的常用操作可以写成这样。

\begin{lstlisting}[language=C]
#define MaxSize 50
typedef int ElemType;
typedef struct {
    ElemType data[MaxSize];
    int top;                 // 栈顶元素下标，空栈为 -1
} SqStack;

void InitStack(SqStack *S) { S->top = -1; }
bool StackEmpty(SqStack S) { return S.top == -1; }

bool Push(SqStack *S, ElemType e) {
    if (S->top == MaxSize - 1) return false;   // 栈满
    S->data[++S->top] = e;                     // 先移指针，再写入
    return true;
}

bool Pop(SqStack *S, ElemType *e) {
    if (S->top == -1) return false;            // 栈空
    *e = S->data[S->top--];                    // 先读出，再移指针
    return true;
}
\end{lstlisting}

\subsubsection*{共享栈}

两个栈各自按最大需求开数组，往往有一边长期空着。让它们共用一段空间就能互相调剂：栈 1 从下标 $0$ 向右长，栈 2 从下标 $\text{MaxSize}-1$ 向左长，各自的栈顶指针仍然指向自己的栈顶元素。

栈 1 的 \texttt{top1} 初始为 $-1$，栈 2 的 \texttt{top2} 初始为 $\text{MaxSize}$，两者都指向自己栈顶的元素。入栈分别是 \texttt{data[++top1] = e} 和 \texttt{data[--top2] = e}。判满条件为
\[
\texttt{top1}+1=\texttt{top2}.
\]
这里不能写成 \texttt{top1 == top2}：数组的一个位置只能属于一个栈，两个指针相邻时已经没有空位；若允许相等，那一格归谁就说不清了。

\begin{lstlisting}[language=C]
typedef struct {
    ElemType data[MaxSize];
    int top1;    // 栈 1 栈顶，初值 -1
    int top2;    // 栈 2 栈顶，初值 MaxSize
} SharedStack;

bool PushShared(SharedStack *S, int which, ElemType e) {
    if (S->top1 + 1 == S->top2) return false;   // 已满
    if (which == 1) S->data[++S->top1] = e;
    else            S->data[--S->top2] = e;
    return true;
}
\end{lstlisting}

\subsubsection*{链栈}

栈顶放在链表头部最省事：入栈就是头插，出栈就是删除首结点，两步都是常数时间。链栈不需要头结点，头指针本身就是栈顶指针，空栈时头指针为 \texttt{NULL}。

{\footnotesize\noindent 图怎么看：链表头就是栈顶，\texttt{top} 直接指向存放 $a_3$ 的结点。入栈时新结点的指针域指向原栈顶，再让 \texttt{top} 指向新结点；出栈时把 \texttt{top} 后移一格并释放原结点。\par}

\begin{lstlisting}[language=C]
typedef struct SNode {
    ElemType data;
    struct SNode *next;
} SNode, *LinkStack;

void InitStack(LinkStack *S) { *S = NULL; }

bool Push(LinkStack *S, ElemType e) {
    SNode *p = (SNode *)malloc(sizeof(SNode));
    if (p == NULL) return false;
    p->data = e;
    p->next = *S;      // 新结点接在原栈顶前面
    *S = p;
    return true;
}

bool Pop(LinkStack *S, ElemType *e) {
    if (*S == NULL) return false;
    SNode *p = *S;
    *e = p->data;
    *S = p->next;
    free(p);
    return true;
}
\end{lstlisting}

顺序栈容量固定，满了就只能报错；链栈不会因为容量满而失败，但每个元素多一个指针域，\texttt{malloc} 和 \texttt{free} 也有额外开销。两种实现的基本操作都是 $O(1)$。

关于出栈序列，有一个常用结论：$n$ 个元素按固定顺序入栈，可能得到的不同出栈序列数为第 $n$ 个 Catalan 数
\[
C_n=\frac{1}{n+1}\binom{2n}{n},
\]
即 $1,2,5,14,42,\ldots$。例如 $n=3$ 时六种排列中有五种可以由栈产生。判断某个具体序列是否合法，直接按“只能弹出当前栈顶”模拟一遍最稳妥。

\subsection{队列与循环队列}

队列把插入限制在表尾、删除限制在表头：新元素只能从队尾进，离开的只能是队头元素。先到的先离开，称为先进先出（FIFO, First In First Out）。

\begin{mydef}{队列}{queue-def}
队列是只允许在表尾插入、在表头删除的线性表。插入端称为队尾（rear），删除端称为队头（front）；入队记作 enqueue，出队记作 dequeue。
\end{mydef}

\subsubsection*{链队列}

链式队列用单链表实现，队头在链表头部，队尾在链表尾部。因为要在一头删除、另一头插入，必须同时保存 \texttt{front} 和 \texttt{rear} 两个指针。通常带头结点：\texttt{front} 指向头结点，\texttt{rear} 指向最后一个数据结点，空队时两者都指向头结点。头结点让空队和非空队的入队代码合并成同一段。

\begin{lstlisting}[language=C]
typedef struct QNode {
    ElemType data;
    struct QNode *next;
} QNode;

typedef struct {
    QNode *front;    // 指向头结点
    QNode *rear;     // 指向最后一个数据结点
} LinkQueue;

void InitQueue(LinkQueue *Q) {
    Q->front = Q->rear = (QNode *)malloc(sizeof(QNode));
    Q->front->next = NULL;
}

bool EnQueue(LinkQueue *Q, ElemType e) {
    QNode *p = (QNode *)malloc(sizeof(QNode));
    if (p == NULL) return false;
    p->data = e;
    p->next = NULL;
    Q->rear->next = p;   // 挂到队尾
    Q->rear = p;         // 更新队尾
    return true;
}

bool DeQueue(LinkQueue *Q, ElemType *e) {
    if (Q->front == Q->rear) return false;   // 空队
    QNode *p = Q->front->next;               // 队头数据结点
    *e = p->data;
    Q->front->next = p->next;
    if (Q->rear == p) Q->rear = Q->front;    // 删的是最后一个结点
    free(p);
    return true;
}
\end{lstlisting}

出队时那个 \texttt{if} 不能省。删除的若是队列中唯一的结点，\texttt{rear} 还停在它上面；结点释放后 \texttt{rear} 就成了悬挂指针，下一次入队会往已释放的内存里写。判断条件写成 \texttt{rear == p} 即可。

\subsubsection*{顺序队列与假溢出}

\subsubsection*{循环队列的下标运算}

循环队列仍然用 \texttt{Q[0..MaxSize-1]}，只是规定任何下标加一后都要对 \texttt{MaxSize} 取模：\texttt{rear} 走到 \texttt{MaxSize-1} 后再加一，回到 $0$。

\begin{tikzpicture}[font=\scriptsize, >=stealth]
  \draw[RuleGray, dashed] (0,0) circle (2.5);
  \foreach \i in {0,...,7} {

    \ifnum\i=0 \def\fc{Teal!20}\else

{\footnotesize\noindent 图怎么看：环上的编号按顺时针排列，\texttt{front} 指向队头元素 \texttt{Q[5]}，\texttt{rear} 指向下一个可写的空位 \texttt{Q[1]}。从 \texttt{Q[5]} 走到 \texttt{Q[7]}，再绕回 \texttt{Q[0]}，这四格就是队内元素；\texttt{Q[1]} 本身不存元素。\par}

设 \texttt{MaxSize} 为 $M$，采用“\texttt{front} 指向队头元素、\texttt{rear} 指向队尾元素的下一个位置”的约定，基本关系如下：
\begin{itemize}
    \item 初始：\texttt{front = rear = 0}；
    \item 判空：\texttt{front == rear}；
    \item 入队：\texttt{Q[rear] = e}，然后 \texttt{rear = (rear + 1) \% M}；
    \item 出队：\texttt{e = Q[front]}，然后 \texttt{front = (front + 1) \% M}；
    \item 元素个数：$(\texttt{rear}-\texttt{front}+M)\bmod M$。
\end{itemize}
\noindent 个数公式里加 $M$ 是为了处理 \texttt{rear} 绕圈后小于 \texttt{front} 的情况：\texttt{rear}-\texttt{front} 可能是负数，加上 $M$ 再取模，结果就落回 $0\sim M-1$。例如上图 $M=8$，$(1-5+8)\bmod 8=4$。

空队时 \texttt{front} 与 \texttt{rear} 相等；如果允许数组装满，满队时两个指针同样相等。为了区分这两种情况，最常见的办法是牺牲一个单元——\texttt{rear} 永远不追上 \texttt{front}，当 \texttt{rear} 的下一个位置就是 \texttt{front} 时判满：
\[
(\texttt{rear}+1)\bmod M=\texttt{front}.
\]
代价是数组最多只存 $M-1$ 个元素。下图把空队和满队并排放在一起，两者的指针位置完全相同，这就是必须引入额外信息的原因。

\noindent \texttt{tag} 的维护很简单：每次入队置 $1$，出队置 $0$。只有当 \texttt{front == rear} 时才需要看它——相等且 \texttt{tag} 为 $0$ 说明最后一次操作是出队，队空；相等且 \texttt{tag} 为 $1$ 说明最后一次操作是入队，队满。

按牺牲一个单元的方案，循环队列的代码是：

\begin{lstlisting}[language=C]
typedef struct {
    ElemType data[MaxSize];
    int front;   // 队头元素下标
    int rear;    // 队尾元素的下一个位置
} SqQueue;

void InitQueue(SqQueue *Q) { Q->front = Q->rear = 0; }

bool EnQueue(SqQueue *Q, ElemType e) {
    if ((Q->rear + 1) % MaxSize == Q->front) return false;  // 满
    Q->data[Q->rear] = e;
    Q->rear = (Q->rear + 1) % MaxSize;
    return true;
}

bool DeQueue(SqQueue *Q, ElemType *e) {
    if (Q->front == Q->rear) return false;                  // 空
    *e = Q->data[Q->front];
    Q->front = (Q->front + 1) % MaxSize;
    return true;
}

int QueueLength(SqQueue Q) {
    return (Q.rear - Q.front + MaxSize) % MaxSize;
}
\end{lstlisting}

下标约定不止这一种。若题目把 \texttt{rear} 定义为“指向队尾元素”，常见初始化是 \texttt{front = 0}、\texttt{rear = M-1}；入队时先 \texttt{rear = (rear+1) \% M} 再写入，出队仍然先取 \texttt{Q[front]} 再 \texttt{front = (front+1) \% M}。这时元素个数变成
\[
(\texttt{rear}-\texttt{front}+1+M)\bmod M,
\]
判空是 $(\texttt{rear}+1)\bmod M=\texttt{front}$；若同样牺牲一个单元，判满则是 $(\texttt{rear}+2)\bmod M=\texttt{front}$。这些式子不必死背：画出环，数一数从 \texttt{front} 走到 \texttt{rear} 要经过几格，公式自然就出来了。

\subsection{表达式：一棵树，三种遍历}

计算 \texttt{1+2*3} 得到 $7$ 而不是 $9$，因为乘法先算。运算符有优先级，同级还有结合方向，括号又能强行改变次序。把表达式写成树以后，这些规则都变成树的结构：内部结点是运算符，它的左右子树就是两个操作数；子树必须先算完，因为父结点需要它们的结果。

三种记法只是同一棵树的三种遍历：
\begin{itemize}
    \item 中缀表达式：运算符夹在两个操作数中间，符合人的阅读习惯，但需要优先级、结合性和括号来消除歧义；
    \item 后缀表达式（逆波兰表示）：运算符在操作数之后，运算次序由位置唯一确定，不需要括号，从左往右扫描即可求值；
    \item 前缀表达式（波兰表示）：运算符在操作数之前，从右往左扫描即可求值。
\end{itemize}

\subsubsection*{中缀转后缀}

转换只用一个运算符栈。从左到右扫描中缀表达式，把操作数和运算符分别处理：

\begin{enumerate}
    \item 遇操作数，直接输出；
    \item 遇左括号，入栈；
    \item 遇右括号，依次弹出栈顶运算符并输出，直到弹出左括号为止；左括号只出栈，不输出；
    \item 遇运算符，若栈空、栈顶是左括号，或栈顶运算符优先级低于当前运算符，就把当前运算符入栈；否则反复弹出栈顶并输出，直到满足入栈条件；
    \item 扫描结束后，把栈中剩余的运算符依次弹出输出。
\end{enumerate}

优先级只涉及两级：\texttt{*}/\texttt{/} 高于 \texttt{+}/\texttt{-}。左括号入栈后视为最低，只有右括号能让它出栈。同级运算符左结合，所以栈顶优先级“不低于”当前运算符时就要弹出——这样先出现的同级运算符会先输出。

以 $A+B*(C-D)-E/F$ 为例，逐步跟踪如下。

\centering\small
\setlength{\tabcolsep}{4pt}
\begin{tabular}{@{}clll@{}}
\toprule
步骤 & 读入 & 运算符栈（底$\to$顶） & 输出 \\
\midrule
1 & \texttt{A} & 空 & \texttt{A} \\
2 & \texttt{+} & \texttt{+} & \texttt{A} \\
3 & \texttt{B} & \texttt{+} & \texttt{AB} \\
4 & \texttt{*} & \texttt{+ *} & \texttt{AB} \\
5 & \texttt{(} & \texttt{+ * (} & \texttt{AB} \\
6 & \texttt{C} & \texttt{+ * (} & \texttt{ABC} \\
7 & \texttt{-} & \texttt{+ * ( -} & \texttt{ABC} \\

11 & \texttt{E} & \texttt{-} & \texttt{ABCD-*+E} \\
12 & \texttt{/} & \texttt{- /} & \texttt{ABCD-*+E} \\

\noindent 第 9 步的右括号把括号内的减号弹了出来；第 10 步读到的减号优先级低于栈顶的 \texttt{*} 和 \texttt{+}，于是两者依次弹出，减号才入栈。最后扫描结束时栈里还剩 \texttt{/} 和 \texttt{-}，先后弹出就补上了结果的末尾。注意输出的操作数顺序始终是 $A,B,C,D,E,F$，改变的只是运算符的位置，可以用这一点快速自查。

不想跟踪栈时，可以先把中缀表达式按优先级完全加括号，再把每个运算符移到它所在括号的右括号之后，最后去掉所有括号。$A+B*(C-D)-E/F$ 的全括号形式是
\[
\bigl((A+(B*(C-D)))-(E/F)\bigr),
\]
把运算符依次移到对应右括号后面，就得到 \texttt{ABCD-*+EF/-}。

\subsubsection*{后缀表达式求值}

后缀表达式从左往右扫描，只用一个操作数栈：遇操作数入栈；遇运算符弹出两个操作数，先弹出的是右操作数，后弹出的是左操作数，计算完把结果压回栈。减法和除法不满足交换律，这个次序不能反。扫描结束时栈中剩下的唯一元素就是答案。

\begin{lstlisting}[language=C]
int EvalPostfix(char *s) {          // 操作数为单个数字字符
    SqStack S; InitStack(&S);
    for (int i = 0; s[i] != '\0'; i++) {
        if (s[i] >= '0' && s[i] <= '9') {
            Push(&S, s[i] - '0');
        } else {
            int b, a;
            Pop(&S, &b);             // 先弹出的是右操作数
            Pop(&S, &a);             // 后弹出的是左操作数
            switch (s[i]) {
                case '+': Push(&S, a + b); break;
                case '-': Push(&S, a - b); break;
                case '*': Push(&S, a * b); break;
                case '/': Push(&S, a / b); break;
            }
        }
    }
    int v; Pop(&S, &v);
    return v;
}
\end{lstlisting}

以 \texttt{5 1 2 + 4 * + 3 -} 为例，栈的变化如下。

\centering\small
\begin{tabular}{@{}cll@{}}
\toprule
读入 & 操作 & 栈（底$\to$顶） \\
\midrule
\texttt{5} & 入栈 & $5$ \\
\texttt{1} & 入栈 & $5,1$ \\
\texttt{2} & 入栈 & $5,1,2$ \\

\noindent 最后一步若把次序弄反，会算成 $3-17=-14$。记住“先弹出的是右操作数”，或者在草稿上把两个数按弹出顺序标成 $b,a$，再写 $a-b$。

前缀表达式扫描方向相反：从右往左，遇操作数入栈，遇运算符弹出两个，先弹出的是左操作数。两种扫描方向对应两种弹出次序，做题时不要凭感觉，按扫描方向推一遍。

实际编译器更常用两个栈直接算中缀：一个操作数栈，一个运算符栈。遇操作数入操作数栈；遇运算符，先把运算符栈中所有优先级不低于它的运算符弹出并各做一次运算，再把它入栈；遇左括号直接入栈；遇右括号弹出运算符直到左括号；扫描结束后清空运算符栈。它和中缀转后缀的规则一一对应，区别只是运算符出栈时立刻计算，而不是写进输出。408 若问转换过程中运算符栈的最大深度，左括号也占一个位置，不要漏算。

\subsection{双端队列}

栈把操作锁在同一端，队列把进和出分到两端。双端队列（double-ended queue，deque）把两端的限制都放开：两端都可以插入，也都可以删除。

\begin{mydef}{双端队列}{deque-def}
双端队列是允许在表的两端进行插入和删除的线性表。若限定插入只在一端进行、删除仍可在两端进行，称为输入受限的双端队列；若限定删除只在一端进行、插入仍可在两端进行，称为输出受限的双端队列。
\end{mydef}

两种受限方式只是把“插入端”或“删除端”固定住，另一端的相应操作仍然保留。退化关系也很直接：插入和删除都限制在同一端，得到栈；固定一端只进、另一端只出，得到队列。

判断某个输出序列能否由双端队列产生，先抓住两条限制：任何时刻能取走的只有两端的元素，中间元素必须等两端被取空才轮得到；元素进队后相对次序不再改变。若插入还只允许在一端，则有一个更强的不变量——队列中的元素始终是输入序列里尚未输出的连续一段，删除只是在段的两端划掉元素，还没插入的部分只能接在插入端。

以“只在右端插入”为例，输入 $a,b,c,d$，看输出 $a,d,b,c$ 是否能做到：
\begin{itemize}
    \item 插入 $a$，从左端删除 $a$；
    \item 依次插入 $b,c,d$，此时队列为 $b,c,d$，从右端删除 $d$；
    \item 从左端删除 $b$，再删除 $c$。
\end{itemize}
得到 $a,d,b,c$。同样的序列用栈做不到：要第一个输出 $a$，只能压入 $a$ 后立刻弹出；之后压入 $b,c,d$，弹出 $d$ 时栈顶是 $c$，无法越过 $c$ 去取 $b$。这说明双端队列的输出能力严格强于栈。

检查候选序列时可以逐项模拟：当前要输出的元素若还没入队，就把输入一直插入到它为止；插入完成后，它必须正好位于某一端，否则该序列不可能。这个模拟不需要回溯——只在一端插入时，多插入元素只会把目标挡在更里面，不会带来新的可能。

也正因为限制还在，双端队列并不能产生所有排列。$n=3$ 时，栈能产生 $5$ 种出栈序列，队列只有 $1$ 种，而三种双端队列都能产生全部 $3!=6$ 种；元素多起来以后就不行了：$n=4$ 时，输入受限的双端队列能产生 $22$ 种，输出受限的也是 $22$ 种，只有无限制的双端队列才能产生全部 $24$ 种。

\subsection{数组与特殊矩阵的压缩存储}

二维数组在内存里仍是一维排列，只是排列顺序有两种。设数组 $A$ 有 $m$ 行 $n$ 列，每个元素占 $L$ 字节，首元素 $A[0][0]$ 的地址为 $\operatorname{LOC}(0,0)$，则
\[
\text{行优先：}\ \operatorname{LOC}(i,j)=\operatorname{LOC}(0,0)+(i\cdot n+j)L,
\]
\[
\text{列优先：}\ \operatorname{LOC}(i,j)=\operatorname{LOC}(0,0)+(j\cdot m+i)L.
\]
行优先先把一整行存完再存下一行，所以 $A[i][j]$ 前面有 $i$ 整行、每行 $n$ 个元素，再加上本行的 $j$ 个。列优先同理，只是行列互换。若题目下标从 $1$ 开始，先把 $i,j$ 各减 $1$；若某维有下界，也要先减去下界再套公式。

特殊矩阵的非零元素有规律，可以只存一部分。对称矩阵满足 $A[i][j]=A[j][i]$，存下三角（含主对角线）即可，共 $n(n+1)/2$ 个元素。按行存放、下标从 $0$ 开始时，元素 $A[i][j]$（$i\geqslant j$）在一维数组中的下标为
\[
k=\frac{i(i+1)}{2}+j .
\]
这个式子来自计数：前 $i$ 行共有 $1+2+\cdots+i=\frac{i(i+1)}{2}$ 个元素，第 $i$ 行里 $A[i][j]$ 前面还有 $j$ 个。访问上三角的 $A[i][j]$（$i<j$）时，利用对称性改取 $A[j][i]$，代入同一公式即可。

三角矩阵与对称矩阵的区别在于，另一侧不是对称元素而是同一个常量 $c$，所以存储量是 $n(n+1)/2+1$：三角区照上面的方式存，另外留一个单元放 $c$。

三对角矩阵只有主对角线及其上下相邻的两条对角线可能非零，共 $3n-2$ 个位置。按行存放、下标从 $0$ 开始时，$|i-j|\leqslant 1$ 的元素映射为
\[
k=2i+j .
\]
可以这样核对：第 $0$ 行有 $2$ 个元素，占 $k=0,1$；第 $i\geqslant1$ 行的位置是 $k=3i-1,\,3i,\,3i+1$，所以行首下标依次是 $2,5,8,\ldots$。最后一行只有 $2$ 个元素，总数正好是 $3n-2$。

稀疏矩阵的非零元素很少，用三元组 $(\text{行},\text{列},\text{值})$ 表或十字链表存储，空间与非零元素个数 $t$ 成正比，而不是固定为 $n^2$。

\subsection{栈与队列的典型应用}

\subsubsection*{括号匹配}

编译器检查括号是否配对，用的是栈。遇左括号入栈；遇右括号，若栈已空说明右括号多了，否则弹出栈顶检查类型是否相同。扫描结束后栈必须为空，否则说明还有左括号没配上。整个过程每个括号只进出栈一次，时间 $O(n)$，空间 $O(n)$。

\begin{lstlisting}[language=C]
bool BracketMatch(char *s) {
    SqStack S; InitStack(&S);
    for (int i = 0; s[i] != '\0'; i++) {
        char c = s[i];
        if (c == '(' || c == '[' || c == '{') {
            Push(&S, c);
        } else if (c == ')' || c == ']' || c == '}') {
            char top;
            if (!Pop(&S, &top)) return false;              // 右括号多
            if ((c == ')' && top != '(') ||
                (c == ']' && top != '[') ||
                (c == '}' && top != '{')) return false;     // 类型不配
        }
    }
    return StackEmpty(S);                                   // 左括号多则失败
}
\end{lstlisting}

\subsubsection*{递归与调用栈}

函数调用时，系统把返回地址、参数和局部变量压入调用栈，函数返回时再弹出。递归函数每深入一层就多一个栈帧，递归深度就是同时存在的栈帧数的最大值。

\begin{lstlisting}[language=C]
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
\end{lstlisting}

任何递归都能用显式栈改写成非递归：把每层需要保存的状态自己压栈，就绕开了系统调用栈。如果递归调用是函数的最后一步（尾递归），还可以直接改成循环，连栈都不需要。

\subsubsection*{层次遍历}

队列的 FIFO 性质保证按层访问：根结点先入队；每次取队头访问，并把它的孩子依次入队。同一层的结点一定排在前一层所有结点之后，所以出队顺序就是层序。

\begin{lstlisting}[language=C]
void LevelOrder(BiTree T) {          // 队列元素类型设为 BiTree
    SqQueue Q; InitQueue(&Q);
    if (T != NULL) EnQueue(&Q, T);
    while (Q.front != Q.rear) {
        BiTree p;
        DeQueue(&Q, &p);
        visit(p);
        if (p->lchild != NULL) EnQueue(&Q, p->lchild);
        if (p->rchild != NULL) EnQueue(&Q, p->rchild);
    }
}
\end{lstlisting}

打印任务队列、键盘缓冲区、消息队列和操作系统的就绪队列也都是队列。它们要的共同性质是“先到先处理”：后来的任务不能插到先来的任务前面，否则先到的任务可能被无限推后。

\subsection*{几处容易记混的地方}

\begin{itemize}
    \item \texttt{top} 的两种约定不能混用。看见 \texttt{top = -1} 就用“指向栈顶元素”那一列，看见 \texttt{top = 0} 就用“指向空位”那一列；入栈、出栈、判空、判满要一起换。
    \item 循环队列牺牲一个单元时，数组长度是 $M$，可存元素最多 $M-1$ 个。题目问“容量”还是“数组大小”，答案不同。
    \item 元素个数公式随 \texttt{rear} 的含义变化：\texttt{rear} 指向队尾下一空位时是 $(\texttt{rear}-\texttt{front}+M)\bmod M$；\texttt{rear} 指向队尾元素时是 $(\texttt{rear}-\texttt{front}+1+M)\bmod M$。
    \item 后缀表达式求值，先弹出的是右操作数。减法和除法必须写成“后弹出者减/除先弹出者”。
    \item 共享栈判满条件是 \texttt{top1}+1=\texttt{top2}，前提是 \texttt{top1}、\texttt{top2} 都指向各自栈顶元素。
    \item 链队列删除最后一个结点后，\texttt{rear} 要回指头结点；否则 \texttt{rear} 成为悬挂指针，下一次入队就会写已释放的内存。
\end{itemize}
