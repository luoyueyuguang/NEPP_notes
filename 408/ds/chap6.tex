\section{查找}

在一百万条学籍记录里按学号找一个人，和在二十个人的通讯录里找一个名字，差别不只是快慢。前者要求你根本不能逐条翻看，后者随手扫一遍也能接受。查找这一章讨论的就是这件事：记录按什么方式摆放，给定一个关键字之后需要比较多少次才能定位；以及当记录还要频繁插入、删除时，这种摆放方式怎样维护。

\subsection{从“比较几次”说起}

先看一个最小的例子。把 $21,35,47,58,69$ 依次放进一个数组，从头逐个比较。找 $47$ 要比较 $3$ 次（$21,35,47$）；找 $60$ 要把五个元素都比一遍才能确认不在表中，比较 $5$ 次。如果问“平均要比较几次”，就必须先说清楚对哪些查找对象平均：是对表中已有的五个元素等概率地找，还是把可能出现的任意关键字都算进来。前者叫查找成功，后者叫查找不成功，两个平均值通常不相等。

\begin{mydef}{查找表、关键字与平均查找长度}{ch6-asl}
查找表是由同一类型记录构成的集合。只做查询、检索的称为静态查找表；还要支持插入、删除的称为动态查找表。记录中用来标识它的数据项叫关键字；能唯一标识记录的是主关键字，不能唯一标识的是次关键字。

平均查找长度（Average Search Length，ASL）是查找过程中关键字比较次数的期望：
\[
\mathrm{ASL}=\sum_{i=1}^{n}P_i\,C_i,
\]
其中 $n$ 是查找对象的个数，$P_i$ 是查找第 $i$ 个对象的概率，$C_i$ 是找到它所需的比较次数。
\end{mydef}

公式里的“查找对象”在成功和失败两种口径下不是同一批东西。等概率时，成功查找取 $P_i=1/n$，分母是 $n$；失败查找要把所有可能落空的位置都算进去，分母往往不是 $n$，例如折半查找的判定树有 $n+1$ 个失败位置，散列表有 $m$ 个散列地址。题目没有明说时，先看它给的是“成功”还是“不成功”，再确定分母。

\subsection{顺序查找：哨兵只是省掉一次边界判断}

顺序查找没有任何前提：表可以无序，可以用数组，也可以用链表。从一端开始逐个比较，相等就返回位置，走完还没有相等就是失败。数组实现时，常把待查关键字先写进 $0$ 号单元，让循环从 $n$ 倒着走：

\begin{lstlisting}[language=C]
typedef struct {
    ElemType *elem;      // elem[0] 留作哨兵
    int TableLen;
} SSTable;

int Search_Seq(SSTable ST, KeyType key) {
    ST.elem[0].key = key;                       // 哨兵
    int i;
    for (i = ST.TableLen; ST.elem[i].key != key; --i)
        ;                                       // 不必判断 i >= 1
    return i;                                   // 返回 0 表示失败
}
\end{lstlisting}

循环从 $n$ 递减到 $0$，无论表里有没有这个关键字，$i=0$ 时一定会与哨兵相等而停下。这样循环条件里少了一个下标越界的判断，但关键字比较的次数并没有减少，时间复杂度仍是 $O(n)$。

成功查找时，第 $i$ 个元素要比较 $n-i+1$ 次，等概率平均为
\[
\mathrm{ASL}_{\text{成功}}=\frac{1}{n}\sum_{i=1}^{n}(n-i+1)=\frac{n+1}{2}.
\]
失败查找时，从 $a_n$ 一直比较到哨兵，共 $n+1$ 次；若不用哨兵，只比较 $n$ 个元素就发现越界，代价是 $n$。两种写法只差一个常数，但考试常拿这个数字设选项，写答案时要看清代码里有没有哨兵。

如果表已经按关键字有序，失败查找可以在第一个大于待查关键字的元素处提前停下。此时 $n+1$ 个失败区间的比较次数依次是 $1,2,\ldots,n,n$，平均为 $\dfrac{n(n+3)}{2(n+1)}$；成功查找的平均次数仍是 $(n+1)/2$，因为每个元素的位置没有变。

\subsection{折半查找：判定树把比较次数画出来}

折半查找要求两条：表必须顺序存储，并且按关键字有序。顺序存储是为了 $O(1)$ 取到中间位置，链表找中点本身就要走 $O(n)$，所以链表不能直接折半。下面以递增表为例，递减表把两个分支对调即可。

\begin{lstlisting}[language=C]
int Binary_Search(SSTable ST, KeyType key) {
    int low = 1, high = ST.TableLen;
    while (low <= high) {
        int mid = low + (high - low) / 2;   // 等价于 (low+high)/2，且不溢出
        if (ST.elem[mid].key == key)
            return mid;
        else if (ST.elem[mid].key > key)
            high = mid - 1;
        else
            low = mid + 1;
    }
    return 0;                                // low > high，查找失败
}
\end{lstlisting}

每比较一次，待查区间缩小一半。把每次选中的 \texttt{mid} 画成一个结点，就得到折半查找的判定树：圆形结点是表中真实存在的元素，方形结点是 \texttt{low > high} 时落入的空区间。$n$ 个元素之间和两端一共有 $n+1$ 个空档，所以方形结点正好 $n+1$ 个。

成功查找的比较次数就是圆形结点所在层数，因此
\[
\mathrm{ASL}_{\text{成功}}=\frac{1\cdot1+2\cdot2+4\cdot3+4\cdot4}{11}=\frac{33}{11}=3.
\]
失败查找时，最后一个被比较的圆形结点是方形结点的父结点，按常见约定只数这些关键字比较，不再把空指针判断另算一次。于是上图中失败代价为 $3$ 的有 $4$ 个、为 $4$ 的有 $8$ 个：
\[
\mathrm{ASL}_{\text{不成功}}=\frac{4\cdot3+8\cdot4}{4+8}=\frac{44}{12}=\frac{11}{3}\approx3.67.
\]
如果题目把“判断空指针”也算一次比较，就在每个失败代价上再加 $1$，得到 $4$ 和 $5$，平均值变为 $56/12=14/3$。两种答案都有人用，关键是同一道题里口径要统一。

判定树的高度是 $\lceil\log_2(n+1)\rceil$，因为一棵高度为 $h$ 的二叉树最多容纳 $2^h-1$ 个内部结点。由此最坏情况比较 $\lceil\log_2(n+1)\rceil$ 次，平均约 $\log_2(n+1)-1$ 次（$n$ 较大时），时间复杂度 $O(\log n)$。

\begin{attention}
\texttt{mid} 的取整方式会改变判定树的形状。取 $\lfloor(\text{low}+\text{high})/2\rfloor$ 时，对偶数个元素，右子树结点数不少于左子树；取 $\lceil(\text{low}+\text{high})/2\rceil$ 时反过来。题目若给出了具体的比较过程或判定树，就按过程画，不要默认某一种取整；若只问“最坏比较次数”，两种取整得到的树高相同。
\end{attention}

\subsection{分块查找：索引表加块内顺序}

折半查找快，但插入一个元素可能要移动半个表；顺序查找插入方便，查找又太慢。分块查找取中间路线：把记录按关键字分成若干块，块与块之间整体有序，块内可以无序；另外建一张索引表，每项记下该块的最大关键字和该块的起始地址。

设表长 $n$，分成 $b$ 块，每块 $s$ 个元素，$n=bs$。索引表用顺序查找、块内也用顺序查找时，索引平均比较 $(b+1)/2$ 次，块内平均 $(s+1)/2$ 次，总代价
\[
\mathrm{ASL}=\frac{b+1}{2}+\frac{s+1}{2}
=\frac{1}{2}\left(\frac{n}{s}+s\right)+1.
\]
由均值不等式，$s=\sqrt n$ 时取最小值 $\sqrt n+1$，此时块数也约为 $\sqrt n$。若索引表改用折半查找，索引部分降为约 $\log_2(b+1)-1$ 次，总代价约为
\[
\mathrm{ASL}\approx\log_2(b+1)-1+\frac{s+1}{2}.
\]
分块查找的插入、删除只影响一个块：块内重新排列，块太大就分裂，太小就与相邻块合并，索引表随之更新。它适合记录数较大、需要按块组织的索引顺序文件。

\subsection{二叉排序树}

折半查找每次把区间砍一半，但要求连续存储；如果记录还要频繁插入、删除，数组的搬移代价很高。二叉排序树（Binary Search Tree，BST）把“比一次、丢掉一半”的思路搬到链式结构上：左子树的所有关键字小于根，右子树的所有关键字大于根，左右子树本身也都是 BST。

408 默认 BST 中不出现重复关键字；若题设允许相等，通常约定统一放左子树或统一放右子树。例如依次插入 $45,24,53,12,37,93$，先来的 $45$ 做根；$24<45$ 往左，$53>45$ 往右；$12<24$ 挂在 $24$ 左边，$37>24$ 挂在 $24$ 右边，$93>53$ 挂在 $53$ 右边。查找 $37$ 的路径是 $45\to24\to37$，比较三次。

BST 有一个很实用的性质：对整棵树做中序遍历，得到的就是关键字的递增序列。判断一棵二叉树是不是 BST，最稳妥的办法就是检查中序序列是否严格递增；删除时能用前驱或后继替代，也是因为中序次序不能被打乱。

查找和插入可以写成同一套下降过程。查找走到空指针就失败；插入走到空指针就把新结点挂在那里，所以新结点一定是叶子。关键字已经存在时通常不重复插入。

\begin{lstlisting}[language=C]
typedef struct BSTNode {
    KeyType key;
    struct BSTNode *lchild, *rchild;
} BSTNode, *BSTree;

BSTNode *BST_Search(BSTree T, KeyType key) {
    while (T != NULL && T->key != key)
        T = (key < T->key) ? T->lchild : T->rchild;
    return T;                          // NULL 表示失败
}

bool BST_Insert(BSTree *T, KeyType key) {
    if (*T == NULL) {
        *T = (BSTNode *)malloc(sizeof(BSTNode));
        (*T)->key = key;
        (*T)->lchild = (*T)->rchild = NULL;
        return true;
    }
    if (key == (*T)->key) return false;
    if (key < (*T)->key)
        return BST_Insert(&(*T)->lchild, key);
    return BST_Insert(&(*T)->rchild, key);
}
\end{lstlisting}

查找的代价是根到目标结点的路径长度。树越矮越快：最平衡时树高与折半判定树相同，为 $O(\log n)$；最坏时每个结点只有一个孩子，退化成单链表，$O(n)$。同样六个关键字，插入顺序不同，形态可以差很多。

\subsection{AVL 树：把树高控制在 $O(\log n)$}

BST 的查找代价完全取决于树高，而树高又取决于插入顺序。要让它稳定在 $O(\log n)$，就得在每次插入、删除后检查并修复失衡。AVL 树首先是一棵 BST，在此基础上再要求：任意结点的左右子树高度之差不超过 $1$。

平衡因子定义为
\[
\mathrm{bf}=\text{左子树高度}-\text{右子树高度},
\]
AVL 树中每个结点的 $\mathrm{bf}\in\{-1,0,1\}$。空树高度记 $0$，只有根的树高度记 $1$。

含 $n$ 个结点的 AVL 树能有多高？反过来问更好算：高度为 $h$ 的 AVL 树最少需要多少个结点。根占一个；为了让结点总数最少，左右子树高度取 $h-1$ 和 $h-2$（两者相差不超过 $1$），并且都取对应高度的最少结点形态，于是
\[
N(h)=N(h-1)+N(h-2)+1,\qquad N(0)=0,\ N(1)=1.
\]
依次得到
\[
\begin{array}{c|cccccc}
h & 1 & 2 & 3 & 4 & 5 & 6\\ \hline
N(h) & 1 & 2 & 4 & 7 & 12 & 20
\end{array}
\]
这个数列比斐波那契数列每项少 $1$（$N(h)=F_{h+2}-1$），按指数增长，所以 $h=O(\log n)$，最坏约为 $1.44\log_2(n+1)$。高度为 $5$ 的 AVL 树至少要有 $12$ 个结点，而不是满二叉树的 $31$ 个。

以 LL 为例，右旋的代码只有三行指针操作：

\begin{lstlisting}[language=C]
AVLNode *RotateRight(AVLNode *p) {
    AVLNode *L = p->lchild;
    p->lchild = L->rchild;      // L 的右子树挂到 p 的左边
    L->rchild = p;
    return L;                   // L 成为新的子树根
}
\end{lstlisting}

左旋完全对称，把 \texttt{lchild} 与 \texttt{rchild} 对调即可。LR 先对 $A$ 的左孩子左旋，再对 $A$ 右旋；RL 先对 $A$ 的右孩子右旋，再对 $A$ 左旋。

插入最多做一次旋转（单旋或双旋）：调整后这棵子树的高度回到插入前的值，祖先的平衡因子不会继续变化。删除不一样，一次旋转可能让子树变矮，祖先可能接着失衡，所以删除最坏要沿路径做 $O(\log n)$ 次调整。

\subsection{B-树：为磁盘访问设计的多路查找树}

内存里的比较很快，磁盘的一次读写在毫秒级。二叉树每个结点只放一个关键字，$10^6$ 条记录树高约 $20$，意味着二十次磁盘访问；如果把一个结点做成一个磁盘块，放几百个关键字、几百个孩子，树高会降到三四层。B-树就是这种“多路、平衡”的查找树。

\begin{mydef}{$m$ 阶 B-树}{ch6-btree}
一棵 $m$ 阶 B-树满足：
\begin{enumerate}
  \item 每个结点最多有 $m$ 棵子树、$m-1$ 个关键字；
  \item 除根外，每个数据结点至少有 $\lceil m/2\rceil-1$ 个关键字；若它还有孩子，则至少有 $\lceil m/2\rceil$ 棵子树；根若不是最底层，至少有 $2$ 棵子树；
  \item 结点内关键字递增排列，$K_i$ 左侧子树的所有关键字小于 $K_i$，右侧子树的所有关键字大于 $K_i$；
  \item 所有失败结点（最底层数据结点的空指针）都在同一层。
\end{enumerate}
\end{mydef}

这里要先统一术语。有的教材把最底层存放关键字的结点叫“叶结点”，有的把它的空孩子叫“叶结点/失败结点”。本文把前者叫\textbf{数据结点}，后者叫\textbf{失败结点}；树高按数据结点的层数计，根为第 $1$ 层，不计失败结点层。读题时先看它是否把失败结点也算一层，必要时换算。

一个数据结点的内部布局是“指针、关键字、指针、关键字……指针”：$n$ 个关键字把关键字空间切成 $n+1$ 段，正好对应 $n+1$ 个孩子指针。

\textbf{查找。} 从根开始，在结点内找到第一个不小于待查关键字的位置：相等就成功；否则沿前一个指针下降。走到失败结点就说明不存在。磁盘访问次数等于树高，结点内比较次数不超过 $m$。

\textbf{插入。} 新关键字总是先插入最底层数据结点。若插入后关键字数不超过 $m-1$，直接完成；若达到 $m$ 个，就把结点分裂：取第 $\lceil m/2\rceil$ 个关键字上升给父结点，左右两半各成一个结点（$m$ 为偶数时取第 $m/2$ 或 $m/2+1$ 个都能保持合法，本文统一取前者，题目另行指定时按题目）。父结点可能因此也达到 $m$ 个，继续分裂，最坏一直传到根；根分裂时产生新根，树高加 $1$。

\textbf{删除。} 先找到关键字。若它不在最底层，用中序前驱或后继替换它，问题转成删除最底层的关键字。删除后若关键字数低于 $\lceil m/2\rceil-1$，就发生下溢：
\begin{itemize}
  \item 兄弟结点够借（关键字数多于下限）：父结点中的分隔关键字下移，兄弟中相邻的关键字上移，相当于绕父结点转一下；
  \item 兄弟也只有下限个关键字：把当前结点、父结点中的分隔关键字、兄弟合并成一个结点。父结点少了一个关键字，可能继续下溢。
\end{itemize}
根结点只剩 $0$ 个关键字时，删除根，让它的唯一孩子成为新根，树高减 $1$。

\textbf{高度。} $n$ 个关键字对应 $n+1$ 个空指针（失败结点）。高度为 $h$ 时，失败结点至少有 $2\lceil m/2\rceil^{h-1}$ 个，因此
\[
n+1\ge 2\left\lceil\frac{m}{2}\right\rceil^{h-1}
\quad\Longrightarrow\quad
h\le 1+\log_{\lceil m/2\rceil}\frac{n+1}{2}.
\]
另一方面，高度为 $h$ 的 $m$ 阶 B-树最多有 $m^h-1$ 个关键字，所以
\[
h\ge \left\lceil\log_m(n+1)\right\rceil.
\]
以 $m=3$、$n=7$ 为例，最矮可以是 $2$ 层（最多 $3^2-1=8$ 个关键字），最高不超过 $1+\log_2 4=3$ 层。实际树高取决于插入、删除的历史，不一定取到这两个端点。

\subsection{B+ 树：把索引和数据分开}

B+ 树是 B-树为数据库和文件系统改造出来的变体。最大的变化是：分支结点只存索引，所有关键字和记录指针都放在叶结点；叶结点之间再用指针串成有序链表。

具体性质可以对照 B-树记：
\begin{itemize}
  \item 每个分支结点最多有 $m$ 棵子树；非叶根至少 $2$ 棵，其他分支结点至少 $\lceil m/2\rceil$ 棵；
  \item 分支结点的子树个数与关键字个数相等（B-树是关键字数比子树数少 $1$）；
  \item 分支结点中的关键字是各子树最大关键字的副本，只起分界作用；
  \item 所有关键字都出现在叶结点，叶结点存放记录指针（或记录本身），并按关键字顺序链接。
\end{itemize}

\subsection{散列表}

前面所有方法都靠比较关键字来缩小范围，散列则试图不比较：用一个函数把关键字直接算成地址。比如学号 $20230117$，令 $H(k)=k\bmod 1000$，地址就是 $117$。理想情况下一次就能定位，时间复杂度 $O(1)$。

问题是不同的关键字可能算出同一个地址，这叫冲突。例如 $117$ 和 $20231117$ 都会落到 $117$。散列技术要解决两件事：设计一个把关键字打散的散列函数；冲突发生时安排一个规则继续找位置。

\textbf{散列函数。} 常见的有：
\begin{itemize}
  \item 除留余数法：$H(k)=k\bmod p$，$p$ 取不大于表长 $m$ 的最大素数。它最简单，也最常考。不要把 $p$ 取成 $2$ 的幂，否则关键字的低位相同就会全部冲突。
  \item 直接定址法：$H(k)=a k+b$。关键字基本连续时不会冲突，但地址空间可能浪费很大。
  \item 平方取中法：把关键字平方，取中间几位。关键字的每一位都不够均匀时，平方后中间位通常更均匀。
  \item 数字分析法：关键字位数较多时，挑分布均匀的若干位作地址。
  \item 折叠法：把关键字分成等长几段，相加后取低位。
\end{itemize}

\textbf{装填因子。} 记
\[
\alpha=\frac{n}{m},
\]
其中 $n$ 是已存入的记录数，$m$ 是散列表长度。$\alpha$ 越大，表越满，冲突越多。开放定址法必须 $\alpha<1$；链地址法可以超过 $1$，但链会变长。

\subsubsection{开放定址法}

冲突时按一个探测序列找下一个空槽：
\[
H_i=\bigl(H(key)+d_i\bigr)\bmod m,\qquad i=0,1,2,\ldots
\]
常用的 $d_i$ 有三种：

\begin{itemize}
  \item 线性探测：$d_i=i$，即依次看 $H,H+1,H+2,\ldots$。实现最简单，但会产生\textbf{聚集}：一段连续被占用后，任何落到这段里的关键字都要往后排，这段就越排越长。
  \item 二次探测：$d_i=1^2,-1^2,2^2,-2^2,\ldots$，即左右交替跳平方步。它能打散线性探测的连续聚集；若希望双向平方探测覆盖整张表，常取 $m$ 为 $4k+3$ 的素数。只取单向 $i^2$ 时通常覆盖不了全部位置，不能把“$4k+3$”无条件套到所有二次探测实现上。
  \item 双重散列：$d_i=i\cdot H_2(key)$，步长由第二个散列函数决定。$H_2(key)$ 要与 $m$ 互质，否则探测序列可能只覆盖表的一部分。它打散效果最好。
\end{itemize}

\subsubsection{ASL 的手算方法}

散列表的 ASL 通常不套近似公式，而是对着表逐个数。

\textbf{成功查找。} 对每个已存入的关键字，数它从本地址开始探测了几次（第一次散列也算一次），求和除以 $n$。前面线性探测的例子中，七个关键字的探测次数是
\[
1,1,1,1,1,1,7,
\]
所以
\[
\mathrm{ASL}_{\text{成功}}=\frac{1+1+1+1+1+1+7}{7}=\frac{13}{7}\approx1.86.
\]

\textbf{不成功查找。} 对每个可能的散列地址 $j$，假设要找一个散列到 $j$ 但表中不存在的关键字，沿探测序列走到空槽为止，记下经过的槽数 $c_j$（包含最后那个空槽），再对 $m$ 个地址求平均。该例中
\[
c_0,\ldots,c_{10}=1,1,1,8,7,6,5,4,3,2,1,
\]
求和得 $39$，因此
\[
\mathrm{ASL}_{\text{不成功}}=\frac{39}{11}\approx3.55.
\]
这里分母是表长 $m$，不是记录数 $n$。如果散列函数只可能产生其中 $q$ 个地址（比如关键字都满足某个同余条件），分母才是 $q$。

链地址法的失败查找只需把对应链上的关键字全部比较一遍：空链比较 $0$ 次，长度 $L$ 的链比较 $L$ 次。上例中五条链的长度为 $1,0,3,2,0$，故
\[
\mathrm{ASL}_{\text{不成功}}=\frac{1+0+3+2+0}{5}=\frac{6}{5}=1.2.
\]
成功查找时，长度为 $L$ 的链各位置贡献 $1+2+\cdots+L=L(L+1)/2$，与链内顺序无关，所以上例
\[
\mathrm{ASL}_{\text{成功}}=\frac{1+6+3}{6}=\frac{5}{3}\approx1.67.
\]
如果题目把“走到空指针”也计一次比较，失败查找每个地址都要再加 $1$；先看清题干的计数口径。

在均匀散列假设下，还可以用装填因子估计平均代价：
\[
\begin{aligned}
\text{线性探测：}\quad &\mathrm{ASL}_{\text{成功}}\approx\frac12\left(1+\frac{1}{1-\alpha}\right),
&&\mathrm{ASL}_{\text{不成功}}\approx\frac12\left(1+\frac{1}{(1-\alpha)^2}\right),\\
\text{链地址法：}\quad &\mathrm{ASL}_{\text{成功}}\approx1+\frac{\alpha}{2},
&&\mathrm{ASL}_{\text{不成功}}\approx\alpha.
\end{aligned}
\]
这些是期望值，用来判断趋势；408 的计算题通常给出具体的表和探测规则，要求按表手算，不要直接把公式当答案。

\subsection{红黑树}

AVL 树要求左右子树高度差不超过 $1$，条件很严，插入删除时旋转较多。红黑树换了一种约束：给结点染红或黑，用颜色规则保证“最长路径不超过最短路径的两倍”，平衡稍松，但维护代价更低。

一棵红黑树满足：
\begin{enumerate}
  \item 每个结点是红色或黑色；
  \item 根结点是黑色；
  \item 每个叶结点（这里的叶结点指空指针 NIL）是黑色；
  \item 红结点的两个孩子都是黑色，即不存在连续的红色结点；
  \item 从任一结点到其所有后代 NIL 的路径上，黑色结点数目相同（称为黑高相等）。
\end{enumerate}

由这两条可以推出树高 $h\le 2\log_2(n+1)$。直观地说：黑高为 $b$ 的子树至少有 $2^b-1$ 个结点；红结点不能连续，所以根到叶子的路径上红结点数不超过黑结点数，树高不超过 $2b$。查找、插入、删除都是 $O(\log n)$。

插入时先把新结点染红，这样不会破坏黑高。若父结点是黑色，直接完成；若父结点是红色，看叔叔结点的颜色：
\begin{itemize}
  \item 叔叔为红：父、叔变黑，祖父变红，把可能的问题上移到祖父继续检查（若祖父就是根，最后再把它染黑）；
  \item 叔叔为黑或不存在：按 LL/RR/LR/RL 做旋转，再重新染色。
\end{itemize}
一次插入最多旋转两次。删除的修复更繁琐，但同样是 $O(\log n)$。

和 AVL 树相比：AVL 更严格，树更矮，查找略快，但插入删除旋转更多；红黑树平衡稍松，旋转少，适合插入删除频繁的场景。C++ 的 \texttt{map/set} 和 Java 的 \texttt{TreeMap} 底层多用红黑树。

\subsection{几种查找结构放在一起看}

\begin{tablebox}{查找结构的横向比较}
\centering
\footnotesize
\begin{tabularx}{\linewidth}{@{}lXX X@{}}
\toprule
结构 & 前提/存储 & 成功查找代价 & 插入、删除与适用场景\\
\midrule
顺序查找 & 任意表，顺序或链式 & $\dfrac{n+1}{2}$，$O(n)$ & 插入 $O(1)$（表尾），适合小表、无序表\\
折半查找 & 有序，顺序存储 & 最坏 $\lceil\log_2(n+1)\rceil$，平均约 $\log_2(n+1)-1$ & 插入删除 $O(n)$，适合静态表\\
分块查找 & 块间有序、块内任意，另建索引 & $\approx\log_2(b+1)-1+\dfrac{s+1}{2}$ 或 $\dfrac{b+s+2}{2}$ & 块内调整，适合索引顺序文件\\
二叉排序树 & 无额外要求 & 平均 $O(\log n)$，最坏 $O(n)$ & 插入删除 $O(h)$，形态依赖插入顺序\\
AVL 树 & BST，$|\mathrm{bf}|\le1$ & $O(\log n)$，最坏约 $1.44\log_2(n+1)$ & 插入至多一次旋转，删除可能多次；查多改少\\
B-树 & 外存，$m$ 阶多路平衡 & $O(\log_m n)$ 次结点访问 & 分裂、借/合；磁盘索引\\
B+ 树 & 外存，叶结点链接 & $O(\log_m n)$，范围查询沿叶链 & 数据库、文件系统索引\\
散列表 & 选好散列函数与冲突处理 & 平均 $O(1+\alpha)$，最坏 $O(n)$ & 平均 $O(1)$；不支持顺序/范围查找\\
\bottomrule
\end{tabularx}
\end{tablebox}

选择哪一种，先问三个问题：表是静态的还是频繁改动的；数据在内存还是磁盘；只需要等值查找，还是还要按关键字范围扫描。静态且有序，折半最省事；内存中频繁插入删除，用 AVL 或红黑树；数据在外存、要范围查询，用 B+树；只做等值查找且不要求顺序，散列表通常最快。
