\section{线性表}

\subsection{先把“排队”这件事说清楚}

把班里的成绩单按学号排成一行：第一行是 1 号，第二行是 2 号……这张表能做的操作很有限——取第 5 行、找学号为 2024003 的那一行、在第 3 行前插进一行、删掉第 7 行。注意这些操作只关心元素排成的\textbf{次序}，不关心每个元素具体是什么，也不关心它存在哪里。把“排成一队”这件事单独抽出来，就是线性表。

\begin{mydef}{线性表}{linear-list}
线性表是由 $n\ (n\geqslant 0)$ 个数据元素构成的有限序列 $a_1,a_2,\ldots,a_n$。除首元素外，每个元素有且只有一个直接前驱；除末元素外，每个元素有且只有一个直接后继。$n$ 称为表长，$n=0$ 时是空表。

元素在序列中的序号 $1,2,\ldots,n$ 称为\textbf{位序}，它从 1 开始；C 数组的下标从 0 开始，两者相差 1，这是后面大量边界错误的来源。
\end{mydef}

线性表是\textbf{逻辑结构}。真正放进内存时，硬件只提供两样东西：地址，以及该地址上存的内容。要让逻辑上相邻的两个元素在物理上也相邻，就把它们塞进连续的存储单元，这是\textbf{顺序表}；不要求物理相邻，而是在每个元素旁边记下下一个元素在哪里，这是\textbf{链表}。同一条逻辑上的线性表，可以有两种存法，后面所有“谁更快”的比较，本质上都是这两种映射方式的比较。

线性表的抽象数据类型把“能对它做什么”固定下来，与存法无关：

\begin{tablebox}{线性表的 ADT（C 风格）}
\centering
\begin{tabular}{l|l}
\toprule
操作 & 语义 \\
\midrule
\texttt{InitList(L)} & 构造一个空表 \\
\texttt{Length(L)} & 返回表长 \\
\texttt{GetElem(L, i)} & 取位序为 $i$ 的元素（按位查找） \\
\texttt{LocateElem(L, e)} & 找第一个值等于 $e$ 的元素（按值查找） \\
\texttt{Insert(L, i, e)} & 在第 $i$ 位之前插入 $e$ \\
\texttt{Delete(L, i)} & 删除第 $i$ 位元素 \\
\texttt{Empty(L)} & 判空 \\
\bottomrule
\end{tabular}
\end{tablebox}

表里有两个极容易混的操作：\texttt{GetElem} 是“按位置取”，\texttt{LocateElem} 是“按值找”。在顺序表上，前者 $O(1)$、后者 $O(n)$；在链表上，两者都是 $O(n)$。408 的选择题很喜欢在这里设陷阱，比如“顺序表查找的时间复杂度是 $O(1)$”——只有按位查找才成立。

\subsection{顺序表：让元素挨着放}

图里的关键信息是：每个单元的下标和地址都能直接读出，相邻单元的地址差固定为 4。因此第 $i$ 个元素的地址不必从头找，算一下就行：
\[
\mathtt{LOC}(a_i)=\mathtt{LOC}(a_1)+(i-1)\times s,\qquad 1\leqslant i\leqslant n,
\]
其中 $s$ 是单个元素占的字节数。例如 $a_4$ 的地址是 $2000+(4-1)\times4=2012$。这种“给定位置就能在常数时间内算出地址”的能力叫\textbf{随机存取}，是顺序表区别于链表的根本特征。

\begin{formula}{顺序表的类型定义}{seq-list-struct}
\begin{lstlisting}[language=C]
#define MaxSize 50
typedef int ElemType;
typedef struct {
    ElemType data[MaxSize];   // 静态分配的存储区
    int length;               // 当前元素个数，不是最大下标
} SqList;
\end{lstlisting}
静态数组版本在编译时就定死了容量。若把 \texttt{data} 改成指向动态数组的指针，并另记一个容量 \texttt{MaxSize}，初始化时用 \texttt{malloc} 申请空间、表满时用 \texttt{realloc} 换更大的一块并把旧数据拷过去，就是动态顺序表。扩容那一次是 $O(n)$，但容量按倍数增长，连续多次插入平摊下来每次仍是 $O(1)$。408 只需要知道“动态顺序表可以扩容，扩容要整体搬移”。
\end{formula}

\subsubsection{插入：从后往前搬}

在长度为 $n$ 的表中，把 $e$ 插到第 $i$ 位之前（$1\leqslant i\leqslant n+1$，$i=n+1$ 表示追加到表尾）。原来占着第 $i$ 位及之后的元素都必须往后挪一格，给 $e$ 腾位置。

图中四条斜箭头就是四次赋值。它们必须\textbf{从右往左}执行：先把 $a_6$ 放到第 7 格，再放 $a_5$……如果反过来从 $a_3$ 开始往右搬，$a_3$ 会先覆盖掉尚未搬走的 $a_4$，数据就丢了。代码里的循环变量从 \texttt{length} 递减到 \texttt{i}，正是这个道理。

\begin{lstlisting}[language=C]
bool ListInsert(SqList *L, int i, ElemType e) {
    if (i < 1 || i > L->length + 1) return false;  // 位序越界
    if (L->length >= MaxSize)       return false;  // 表满
    for (int j = L->length; j >= i; j--)           // 从后往前搬
        L->data[j] = L->data[j - 1];
    L->data[i - 1] = e;                            // 位序 i 对应下标 i-1
    L->length++;
    return true;
}
\end{lstlisting}

插在第 $i$ 位要移动 $n-i+1$ 个元素。若 $n+1$ 个合法位置等概率出现，平均移动次数为
\[
\frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1)
=\frac{n+(n-1)+\cdots+0}{n+1}
=\frac{n(n+1)/2}{n+1}
=\frac{n}{2}.
\]
最好情况是插在表尾，移动 0 个，$O(1)$；最坏情况是插在表头，整表后移，$O(n)$。

\subsubsection{删除：从前往后补}

删除第 $i$ 位（$1\leqslant i\leqslant n$）时方向相反：第 $i+1$ 到第 $n$ 个元素依次往前补一格，把空洞填上。这时循环必须从 $i$ 开始递增，否则前面的元素会覆盖还没读取的后继。

\begin{lstlisting}[language=C]
bool ListDelete(SqList *L, int i, ElemType *e) {
    if (i < 1 || i > L->length) return false;
    *e = L->data[i - 1];
    for (int j = i; j < L->length; j++)   // 从前往后补
        L->data[j - 1] = L->data[j];
    L->length--;
    return true;
}
\end{lstlisting}

删除第 $i$ 位要移动 $n-i$ 个元素，平均值是
\[
\frac{1}{n}\sum_{i=1}^{n}(n-i)=\frac{(n-1)+(n-2)+\cdots+0}{n}=\frac{n-1}{2}.
\]
它比插入的平均值少 $1/2$，原因有两个：删除只有 $n$ 个合法位置（没有“第 $n+1$ 位”），而且被删元素本身不用移动。

把两个公式放在同一张图里看，差异和趋势都很直观：

\subsubsection{按值查找}

按位取值是 $O(1)$，按值查找则要逐个比较：

\begin{lstlisting}[language=C]
int LocateElem(SqList L, ElemType e) {
    for (int i = 0; i < L.length; i++)
        if (L.data[i] == e) return i + 1;   // 返回位序
    return 0;                               // 0 表示未找到
}
\end{lstlisting}

若每个位置被查到的概率相同，查找成功时平均比较次数为 $(1+2+\cdots+n)/n=(n+1)/2$；查找失败则要把 $n$ 个元素全部比完。两种情况都是 $O(n)$。

\begin{attention}
顺序表代码里的边界，几乎都出在“位序”和“下标”的换算上：
\begin{itemize}
\item \texttt{length} 是元素个数。表空是 \texttt{length == 0}，表满是 \texttt{length == MaxSize}，最后一个元素的下标是 \texttt{length - 1}。
\item 插入的合法范围是 $1\leqslant i\leqslant n+1$，删除是 $1\leqslant i\leqslant n$。判断越界要用当前的 \texttt{length}，而不是 \texttt{MaxSize}。
\item 插入时先判 $i$ 再判满、删除时先判 $i$ 再判空，顺序反了虽然结果不错，但会给出误导性的返回值。
\end{itemize}
\end{attention}

\subsection{单链表：用指针把散落的结点串起来}

顺序表插入要搬半个表。如果表很长、又频繁在中间插队，搬移就成了主要开销。链表的想法很直接：元素不必挨着放，每个结点在存数据的同时，额外存一个指针，指向下一个结点在哪里。

\begin{mydef}{单链表}{linked-list}
每个结点含两个域：\textbf{数据域} \texttt{data} 存元素，\textbf{指针域} \texttt{next} 存直接后继结点的地址。最后一个结点的 \texttt{next} 为 \texttt{NULL}。结点在内存中的位置任意，逻辑次序完全由指针决定。
\end{mydef}

typedef struct LNode {
    ElemType data;
    struct LNode *next;
} LNode, *LinkList;
\end{lstlisting}

对比上下两组：带头结点时，即使表空，\texttt{L} 也始终指向一个真实结点，因此“在表头插入/删除”和“在中间插入/删除”可以用同一段代码；不带头结点时，空表是 \texttt{L == NULL}，在表头操作必须修改 \texttt{L} 本身（通常把 \texttt{LinkList *} 传进去，或让函数返回新的头指针）。题目没有明说时，按题设给出的类型和空表描述判断，不要默认某一套。

按位查找从\textbf{头结点}开始计数，头结点算第 0 个：

\begin{lstlisting}[language=C]
LNode *GetElem(LinkList L, int i) {
    if (i < 0) return NULL;
    LNode *p = L;                 // p 指向头结点（第 0 个）
    int j = 0;
    while (p != NULL && j < i) {  // 走 i 步后 p 指向第 i 个结点
        p = p->next;
        j++;
    }
    return p;                     // i 超过表长时返回 NULL
}
\end{lstlisting}

\texttt{GetElem(L, 0)} 返回头结点，\texttt{GetElem(L, 1)} 返回首元结点。循环每走一步只做一次指针赋值，走 $i-1$ 步，所以是 $O(i)$，最坏 $O(n)$。

\subsubsection{插入与删除：改指针，不搬数据}

要在第 $i$ 位插入 $e$，先找到第 $i-1$ 个结点 $p$，让新结点 $s$ 接住 $p$ 原来的后继，再让 $p$ 指向 $s$。

\begin{center}
\begin{tikzpicture}[>=stealth, font=\scriptsize]

图 (a) 中 (1) 是 \texttt{s->next = p->next}，(2) 是 \texttt{p->next = s}。(1) 先从 $p$ 那里读出 $q$ 的地址存进 $s$，(2) 再把 $p$ 的指针改成指向 $s$。顺序反过来，$p$ 的 \texttt{next} 一旦被改写，$q$ 的地址就无处可查，(b) 中那条虚线链接就断了，$q$ 及其后的所有结点全部丢失。

\begin{lstlisting}[language=C]
bool ListInsert(LinkList L, int i, ElemType e) {
    if (i < 1) return false;
    LNode *p = GetElem(L, i - 1);      // 找第 i-1 个结点
    if (p == NULL) return false;
    LNode *s = (LNode *)malloc(sizeof(LNode));
    if (s == NULL) return false;
    s->data = e;
    s->next = p->next;                 // (1) 新结点接住原后继
    p->next = s;                       // (2) 前驱改指新结点
    return true;
}
\end{lstlisting}

带头结点时 $i=1$ 的 $p$ 就是头结点，上面这段代码不用特判就能插在表头。找到 $p$ 花 $O(n)$，改指针只有常数次，所以“按位插入”整体仍是 $O(n)$——常说的“链表插入 $O(1)$”有个前提：已经拿到前驱指针。

删除同理，先找到第 $i-1$ 个结点，让它的 \texttt{next} 绕过第 $i$ 个结点，再释放后者：

\begin{lstlisting}[language=C]
bool ListDelete(LinkList L, int i, ElemType *e) {
    if (i < 1) return false;
    LNode *p = GetElem(L, i - 1), *q;
    if (p == NULL || p->next == NULL) return false;  // 无前驱或无第 i 个
    q = p->next;
    *e = q->data;
    p->next = q->next;
    free(q);
    return true;
}
\end{lstlisting}

\begin{attention}
\textbf{“删除指针 \texttt{p} 所指结点”是一个经典陷阱。} 如果只给 \texttt{p}、不给前驱，常规做法是把后继的数据复制到 \texttt{p}，再删掉后继：
\begin{lstlisting}[language=C]
q = p->next;
p->data = q->data;
p->next = q->next;
free(q);
\end{lstlisting}
它在 $O(1)$ 时间内完成，但有三个前提：\texttt{p} 不是尾结点（否则没有后继可供复制）；结点数据可以整体复制；外部没有别的指针还指着被删的那个后继结点。题目若问“能否在 $O(1)$ 时间内删除”，要连这些条件一起答。
\end{attention}

\subsubsection{建表：头插与尾插}

从空表开始逐个插入 $n$ 个元素，插的位置不同，得到的次序也不同。

头插法把每个新结点插到头结点之后：

\begin{lstlisting}[language=C]
LinkList List_HeadInsert(int n) {
    LinkList L = (LinkList)malloc(sizeof(LNode));
    L->next = NULL;                        // 头结点
    for (int i = 0; i < n; i++) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        scanf("%d", &s->data);
        s->next = L->next;                 // 新结点接住当前首元
        L->next = s;                       // 头结点改指新结点
    }
    return L;
}
\end{lstlisting}

每次插入都在表头，$n$ 次共 $O(n)$。输入 $1,2,3$，得到的是 $3,2,1$——次序正好相反。这个性质可以直接用来做就地逆置：把头结点摘下，再把原链表的结点依次头插回去。

尾插法要保持输入次序，必须记住尾结点，否则每插一个都要从头走到尾，总代价变成 $O(n^2)$：

\begin{lstlisting}[language=C]
LinkList List_TailInsert(int n) {
    LinkList L = (LinkList)malloc(sizeof(LNode));
    LNode *r = L;                          // r 始终指向尾结点
    for (int i = 0; i < n; i++) {
        LNode *s = (LNode *)malloc(sizeof(LNode));
        scanf("%d", &s->data);
        r->next = s;
        r = s;                             // 尾指针后移
    }
    r->next = NULL;                        // 收尾
    return L;
}
\end{lstlisting}

\subsection{双链表与循环链表}

单链表只能单向走。要删除结点 $p$，必须知道它的前驱，而找前驱又得从头再扫一遍。双链表给每个结点再加一个指向前驱的指针，把这个回头路省掉。

\begin{lstlisting}[language=C]
typedef struct DNode {
    ElemType data;
    struct DNode *prior, *next;
} DNode, *DLinkList;
\end{lstlisting}

在 $p$ 之后插入 $s$，一共要改四个指针：

上半部分是插入，青线是 \texttt{next} 方向，红线是 \texttt{prior} 方向，编号对应四条语句：
\begin{lstlisting}[language=C]
s->next = p->next;                    // (1) 先接住 p 原来的后继 q
if (p->next != NULL) p->next->prior = s;  // (2) q 回指 s
s->prior = p;                         // (3) s 指回 p
p->next = s;                          // (4) p 才指向 s
\end{lstlisting}

重要的是 (1)(2)(3) 都必须在 (4) 之前完成：(4) 一执行，\texttt{p->next} 就变成了 $s$，再去读“$p$ 原来的后继”就晚了，而 (2) 若拖到 (4) 之后，修改的会是 $s$ 自己的 \texttt{prior}。其中 (2) 要判空，因为 $p$ 可能是尾结点，此时 $q$ 不存在。若链表是循环双链表，\texttt{p->next} 永远非空，这个判断可以省掉。

删除 $q$ 只需两步：让 $p$ 的 \texttt{next} 指向 $r$，再让 $r$ 的 \texttt{prior} 指回 $p$，最后释放 $q$。图下半部分画的就是这两条新边；同样地，$q$ 是尾结点时要判空。

看图验证两个常用结论。第一，带头结点的循环单链表判空条件是 \texttt{L->next == L}：表空时头结点自己指向自己，环上只有头结点。第二，若只保存尾指针 \texttt{r}（指向 $a_3$），则 \texttt{r->next} 是头结点，\texttt{r->next->next} 是首元结点，所以在表头插入和在表尾插入都只要常数时间，不需要遍历。这正是“只设尾指针的循环单链表”常被考的原因。

循环双链表再多一条：头结点的 \texttt{prior} 指向尾结点，于是从表头可以 $O(1)$ 找到表尾。判空条件写成 \texttt{L->next == L}（此时也必有 \texttt{L->prior == L}）。由于任何结点的两个指针都非空，插入删除不需要判空分支。

插入时从空闲分量中取一个，改两个 \texttt{next}；删除时把被删分量挂回空闲链。整个过程一个元素都不移动，这是它的优点。代价是容量固定、按位查找仍要沿 \texttt{next} 走 $O(n)$ 步，而且 \texttt{next} 存的是下标，写错一位不会报错，只会悄悄指到别处。

\subsection{双指针：把两趟扫描压成一趟}

双指针不是一种存储结构，而是一类扫描技巧：用两个指针在同一条序列上以不同速度、或从不同起点移动，让它们各自负责一件事，从而避免嵌套循环。下面四种用法覆盖了 408 的绝大多数考法。

\subsubsection{快慢指针找倒数第 $k$ 个}

让 \texttt{fast} 先走 $k$ 步，然后两个指针同步后移。由于间距始终是 $k$，当 \texttt{fast} 停在尾结点时，\texttt{slow} 恰好停在倒数第 $k$ 个结点的前驱上。

图中 $n=7$、$k=2$：\texttt{fast} 先走 2 步到 $a_2$，同步移动 5 步后停在 $a_7$，\texttt{slow} 从第 0 个位置（头结点）走到 $a_5$，而待删的倒数第 2 个是 $a_6$，正好是 \texttt{slow->next}。两个指针的间距在整段移动中保持为 2，这就是“倒数第 $k$ 个”与“前驱”之间的换算依据。

对应的代码只有两段循环：

\begin{lstlisting}[language=C]
bool DeleteKthFromEnd(LinkList L, int k, ElemType *e) {
    if (k < 1) return false;
    LNode *fast = L, *slow = L;
    for (int i = 0; i < k; i++) {
        if (fast == NULL) return false;   // k 超过表长
        fast = fast->next;
    }
    if (fast == NULL) return false;
    while (fast->next != NULL) {          // fast 停在尾结点
        fast = fast->next;
        slow = slow->next;
    }
    LNode *q = slow->next;
    *e = q->data;
    slow->next = q->next;
    free(q);
    return true;
}
\end{lstlisting}

两处边界决定成败：$k=n$ 时 \texttt{fast} 恰好停在尾结点，第二段循环一次也不执行，\texttt{slow} 仍在头结点，删的是首元结点；$k>n$ 时 \texttt{fast} 在走的过程中变成 \texttt{NULL}，必须提前返回。另外，起点不同结论会平移一位：若从首元结点出发走 $k$ 步，最终 \texttt{slow} 指的就是待删结点本身，而不是它的前驱。答题时要写清楚从头结点还是首元结点开始。

\subsubsection{找中间结点}

\texttt{slow} 每次走 1 步，\texttt{fast} 每次走 2 步。\texttt{fast} 走到 \texttt{NULL}（偶数个结点）或 \texttt{fast->next == NULL}（奇数个）时，\texttt{slow} 就在中间：$n$ 为奇数时是第 $(n+1)/2$ 个；$n$ 为偶数时是第 $n/2+1$ 个，即后半段的第一个。循环条件必须写成 \texttt{fast != NULL \&\& fast->next != NULL}，因为循环体里要访问两次 \texttt{next}。若题目要求偶数时取前半段的最后一个，把循环体末尾的判断提前一步即可，结论整体左移一位——答题时先看清题目要哪一个中位数。

\subsubsection{判环与找环入口}

Floyd 判环仍然是一快一慢：\texttt{slow} 一步、\texttt{fast} 两步，有环必相遇，无环则 \texttt{fast} 先撞到 \texttt{NULL}。

\begin{center}
\begin{tikzpicture}[>=stealth, font=\scriptsize]
  \node[draw=RuleGray, fill=SoftBlue, minimum width=0.8cm, minimum height=0.45cm] (v1) at (0,-2.2) {1};

图中 1、2 是环外的前缀，3、4、5 构成环，5 的 \texttt{next} 指回 3。两个指针进入环后，\texttt{fast} 每轮比 \texttt{slow} 多走一步，二者在环上的距离每轮缩小 1，所以最多绕一圈就会相遇。

相遇之后要找入口：把 \texttt{slow} 放回头结点，两个指针都改成每次走 1 步，再次相遇的位置就是环入口。设头到入口为 $a$ 步，入口到相遇点为 $b$ 步，环长为 $L$。相遇时 \texttt{slow} 走了 $a+b$，\texttt{fast} 走了 $a+b+kL$，而 \texttt{fast} 的路程是 \texttt{slow} 的两倍：
\[
2(a+b)=a+b+kL \;\Longrightarrow\; a=kL-b=(k-1)L+(L-b).
\]
也就是说，从头走 $a$ 步、从相遇点走 $L-b$ 步，会在同一时刻到达入口。

\begin{lstlisting}[language=C]
bool HasCycle(LinkList L) {
    LNode *slow = L, *fast = L;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;          // 一步
        fast = fast->next->next;    // 两步
        if (slow == fast) return true;
    }
    return false;
}
\end{lstlisting}

判环时两个指针从同一个结点出发即可（通常取表头）；进入环后它们的距离每轮缩小 1，所以有环一定会相遇。求环长则更简单：相遇后让一个指针不动、另一个每次走一步，再次回到相遇点所走的步数就是 $L$。

\subsubsection{顺序表上的双指针}

顺序表虽然支持随机存取，双指针仍然能把 $O(n^2)$ 降成 $O(n)$：

\begin{itemize}
\item \textbf{归并两个有序表}：$i$、$j$ 各指一个表，每次把较小的那个放进结果表并移动对应指针。每比较一次至少确定一个元素，最坏比较 $m+n-1$ 次。
\item \textbf{有序表去重}：读指针 $i$ 扫描整个数组，写指针 $k$ 指向已保留部分的末尾。只有当前元素与最后一个已保留元素不同时，才写入 \texttt{data[k]} 并让 $k$ 前移。$k$ 永远不超过 $i$，所以不会覆盖尚未读取的元素。
\item \textbf{按值划分}：左右指针从两端向中间夹，把满足条件的元素换到左边、不满足的换到右边，只扫描一趟。
\end{itemize}

这类题的两个易错点：循环条件用 \texttt{i < j} 还是 \texttt{i <= j}（决定中间那个元素要不要处理），以及写指针与读指针重合时能否安全赋值（能，因为写指针从不超前于读指针）。

\subsection{顺序表与链表怎么选}

把两种存法的代价列在一起，比较才有意义：

\begin{tablebox}{顺序表与链表的操作代价}
\centering
\begin{tabular}{lcc}
\toprule
操作 & 顺序表 & 单链表 \\
\midrule
按位取第 $i$ 个 & $O(1)$（随机存取） & $O(n)$（顺序存取） \\
按值查找 & $O(n)$，平均 $(n+1)/2$ 次比较 & $O(n)$，平均 $(n+1)/2$ 次比较 \\
在第 $i$ 位插入 & $O(n)$，平均移动 $n/2$ 个 & 定位 $O(n)$，改指针 $O(1)$ \\
删除第 $i$ 个 & $O(n)$，平均移动 $(n-1)/2$ 个 & 定位 $O(n)$，改指针 $O(1)$ \\
已知前驱指针后插入 & 仍需搬移，$O(n)$ & $O(1)$ \\
空间 & 预分配，可能留空位 & 每结点多一个指针域 \\
扩容 & 需整体搬移，均摊 $O(1)$ & 单个结点申请，无整体搬移 \\
\bottomrule
\end{tabular}
\end{tablebox}

“链表插入是 $O(1)$”这句话只有在\textbf{已经拿到插入位置的前驱指针}时才成立。若题目要求“在第 $i$ 位插入”，链表仍要先花 $O(n)$ 定位，总时间与顺序表同阶；只是两边的钱花在不同地方：

\begin{center}
\begin{tikzpicture}[>=stealth, font=\scriptsize]
  \node[anchor=east, MutedText] at (-0.2,1.4) {链表，按位插入};
  \node[anchor=east, MutedText] at (-0.2,0.5) {顺序表，按位插入};
  % 链表：定位 + 改指针
  \draw[fill=SoftBlue, draw=RuleGray] (0,1.15) rectangle (6.0,1.65);
  \node at (3.0,1.4) {定位：沿 \texttt{next} 走 $i-1$ 步，$O(n)$};
  \draw[fill=SoftAmber, draw=RuleGray] (6.0,1.15) rectangle (7.4,1.65);
  \node at (6.7,1.4) {改指针 $O(1)$};
  % 顺序表：算地址 + 搬移
  \draw[fill=SoftAmber, draw=RuleGray] (0,0.25) rectangle (1.1,0.75);
  \node at (0.55,0.5) {$O(1)$};
  \draw[fill=SoftBlue, draw=RuleGray] (1.1,0.25) rectangle (7.4,0.75);
  \node at (4.25,0.5) {搬移 $n-i+1$ 个元素，$O(n)$};
  \node[font=\scriptsize, MutedText, anchor=north] at (3.7,-0.1)
    {两条色带总长相同：都是 $O(n)$，主要开销不在同一处};
\end{tikzpicture}
\end{center}

图中蓝色部分一边是“沿指针找位置”，一边是“在连续内存里搬元素”。这也解释了为什么表很长时顺序表反而常常更快：搬移是顺序访问，硬件预取友好，而链表每走一步都可能是一次缓存缺失。反过来，若已经持有某个结点的指针、要在它后面反复插入，链表才是真正的 $O(1)$。

空间上，\textbf{存储密度}指数据本身占的字节数与整个结点占的字节数之比。单链表的结点是“数据 + 一个指针”：若 \texttt{ElemType} 为 4 字节、指针 4 字节，密度为 $4/8=0.5$；64 位系统指针 8 字节，则降到 $4/12\approx0.33$。双链表还要再乘一次折扣。顺序表除了末尾可能浪费的预留空间，密度接近 1，但表满时要么扩容、要么失败。

选择的原则并不复杂：需要频繁按位访问、表长变化不大、内存连续，用顺序表；需要频繁在已知位置插入删除、表长难以预估、单元素较大而指针开销可接受，用链表。考试里更常见的不是选型，而是判断某句“顺序表一定比链表快”或“链表插入一定是 $O(1)$”对不对——判断的依据就是上面这张表，以及“定位”是否已经完成。
