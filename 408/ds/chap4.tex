\section{树与二叉树}

家族谱、文件目录、算术表达式，画出来都是“一层套一层”的结构：一个人有父母，一个目录里有子目录，一个运算符有两个运算对象。它们共同的特征是\textbf{分叉}——一个结点可以带多个后继，而不是像线性表那样只有一个。把这种结构抽象出来，就是树。

\subsection{树的形状与几条计数规律}

先看一个具体的组织图：总经理 A 下面有三位部门经理 B、C、D；B 手下有组长 E、F；C 手下有组长 G；D 手下有组长 H、I。把每个人画成一个结点，把“直接领导”画成一条有向边，就得到下图的形状。它没有环，任意两个结点之间有且只有一条简单路径，这正是树的特征。

\begin{mydef}{树}{tree-def}
树是 $n\ (n\geqslant 0)$ 个结点的有限集合。$n=0$ 时称为空树；$n>0$ 时满足：
\begin{enumerate}
  \item 有且仅有一个特殊的结点称为\textbf{根}；
  \item 其余结点可以分成 $m\ (m>0)$ 个互不相交的集合 $T_1,\ldots,T_m$，每个集合本身又是一棵树，称为根的\textbf{子树}。
\end{enumerate}
定义是递归的：树由根和若干棵子树组成，子树仍是树。正因为如此，后面几乎所有操作都写成递归形式。
\end{mydef}

有了图，几个术语可以一次说清。结点的\textbf{度}是它的孩子个数，所有结点度的最大值称为\textbf{树的度}。根所在的层号为 1；从根到某结点的边数加 1 就是该结点的\textbf{深度}（层号），树中最大的层号称为\textbf{高度}。从根到某结点经过的边数称为\textbf{路径长度}。同一个双亲的孩子互为\textbf{兄弟}。如果结点的孩子区分左右次序，这棵树称为\textbf{有序树}，否则称为\textbf{无序树}；二叉树可以看成每个结点有两个固定位置（左、右）的有序树：位置为空也算一种状态，所以只有一个孩子时仍要区分左右。

从图中还能数出一个恒等式。除根以外，每个结点恰好有一条边连向它的双亲，所以 $n$ 个结点共有 $n-1$ 条边；换一个方向数，每条边都是某个结点连向它的一个孩子，所以边数又等于所有结点度数之和。设度为 $i$ 的结点有 $n_i$ 个，就有
\[
n-1=\sum_{i\geqslant 1} i\,n_i,\qquad n=\sum_{i\geqslant 0} n_i .
\]
两式相减，得到只含叶子数的式子
\[
n_0=1+\sum_{i\geqslant 2}(i-1)\,n_i .
\]
它的用法很直接：题目给出各种非叶结点的个数，叶子数不用画图就能算出来。比如图中有 $n_3=1$、$n_2=2$、$n_1=1$，则 $n_0=1+2\times1+1\times2=5$，与图上的五个叶子一致。

\begin{attention}
\textbf{“度”在两套语言里含义不同。}树里说结点的度，指它有几个孩子，$\sum \deg(v)=n-1$；把树当无向图看时，图的度还要把连向双亲的那条边算上，于是 $\sum \deg_{\text{图}}(v)=2(n-1)$。408 的选择题常用这一点做干扰项。

另外，深度从 1 还是从 0 开始，各教材约定不同。本章与 408 常用约定一致：根的层号（深度）为 1，树的高度等于最大层号。做题时以题干约定为准。
\end{attention}

\subsection{二叉树：左右必须分清}

二叉树常被误解成“每个结点最多两个孩子”。真正的限制更强：\textbf{左右子树是有次序的}。一个结点只有一个孩子时，也必须说明它是左孩子还是右孩子。这个区别不是文字游戏——中序遍历的“左、根、右”，二叉排序树的“小在左、大在右”，Huffman 编码的 0 和 1，全都依赖左右之分。

\begin{mydef}{二叉树}{binary-tree-def}
二叉树是 $n\ (n\geqslant0)$ 个结点的有限集合，它或者为空，或者由一个根结点和两棵互不相交的、分别称为\textbf{左子树}和\textbf{右子树}的二叉树组成。
\end{mydef}

因此，二叉树不是“度为 2 的树”：度为 2 的树至少含有一个度为 2 的结点，而二叉树可以一个都没有（例如每个结点只有左孩子的单支树）。

\subsubsection{满二叉树与完全二叉树}

满二叉树要求每一层都排满；完全二叉树放宽了最后一层，但要求结点从左到右连续排列，中间不能空。

\begin{mydef}{满二叉树与完全二叉树}{full-complete}
高度为 $h$ 的二叉树，若第 $i$ 层恰有 $2^{i-1}$ 个结点（$1\leqslant i\leqslant h$），称为\textbf{满二叉树}，结点总数为 $2^h-1$。

若一棵 $n$ 个结点的二叉树，按满二叉树的层序编号后，其结点恰好占据编号 $1\sim n$，称为\textbf{完全二叉树}。等价地说：除最后一层外每层都满，最后一层的结点从左到右连续。
\end{mydef}



\subsubsection{二叉树的基本性质}

设二叉树中度为 0、1、2 的结点数分别为 $n_0,n_1,n_2$。

\begin{formula}{二叉树的计数性质}{binary-count}
\begin{enumerate}
  \item 第 $i$ 层至多有 $2^{i-1}$ 个结点（$i\geqslant1$）；高度为 $h$ 的二叉树至多有 $2^h-1$ 个结点。
  \item $n_0=n_2+1$。
  \item $n$ 个结点的二叉树，高度至少为 $\lceil\log_2(n+1)\rceil$，至多为 $n$。
\end{enumerate}
\end{formula}

第一条按层数归纳即可：根是 $2^0$，每个结点至多带两个孩子，下一层至多翻倍。

第二条是 408 出现频率最高的公式，证明只用数边：结点总数 $n=n_0+n_1+n_2$；除根外每个结点有一条入边，故边数为 $n-1$；另一方面，度为 1 的结点贡献 1 条出边，度为 2 的贡献 2 条，所以
\[
n-1=n_1+2n_2 .
\]
两式联立消去 $n_1$：
\[
n_0+n_1+n_2-1=n_1+2n_2\;\Longrightarrow\;n_0=n_2+1 .
\]
这个等式与树的形状无关，只要求每个结点至多两个孩子。做题时若给出 $n_0$ 和 $n_2$ 中的一个，另一个立刻确定；若给出总结点数，还要用 $n_1$ 的取值补足。

对完全二叉树，$n_1$ 只能取 0 或 1（最后一层不会出现“有右孩子却没有左孩子”的结点）。由 $n=2n_0+n_1-1$ 可得
\[
n_0=\left\lceil\frac n2\right\rceil,\qquad
n_1=\begin{cases}1,&n\text{ 为偶数},\\0,&n\text{ 为奇数}.\end{cases}
\]
高度则满足
\[
h=\lceil\log_2(n+1)\rceil=\lfloor\log_2 n\rfloor+1 .
\]
例如 $n=1000$ 时，$n_1=1$，$n_0=500$，$h=\lceil\log_2 1001\rceil=10$。

\subsection{二叉树的两种存储布局}

\subsubsection{顺序存储}

完全二叉树的编号已经给出了下标，直接把结点按编号放进一维数组即可：\texttt{T[i]} 存编号为 $i$ 的结点，\texttt{T[0]} 闲置。下标关系就是上一节的三条公式。

非完全二叉树也能这样存，但必须按完全二叉树的编号留空。下图对比了两种情况：十个结点的完全树恰好占十个单元；而四个结点的右单支树，编号依次是 1、3、7、15，要占十五个单元，其中十一个是空位。

\subsubsection{二叉链表}

一般二叉树更常用链式存储。每个结点存数据域和两个指针域：

\begin{lstlisting}[language=C]
typedef struct BiTNode {
    ElemType data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;
\end{lstlisting}

$n$ 个结点一共有 $2n$ 个指针域，其中 $n-1$ 个用来指向孩子（每条边对应一个指针），剩下的
\[
2n-(n-1)=n+1
\]
个是空指针。这个数字很关键：下一节的线索二叉树，就是把这 $n+1$ 个空指针利用起来。

\subsection{遍历：三种深度优先与一种广度优先}

遍历是把每个结点访问一次，且只访问一次。“访问”具体做什么不影响次序：可以打印、累加、求高度。三种深度优先遍历的差别只有一句话：\textbf{访问根结点的时机}。

\begin{formula}{先序、中序、后序}{three-orders}
以根为参照：
\begin{itemize}
  \item \textbf{先序}（根左右）：先访问根，再先序遍历左子树，最后先序遍历右子树；
  \item \textbf{中序}（左根右）：先中序遍历左子树，再访问根，最后中序遍历右子树；
  \item \textbf{后序}（左右根）：先后序遍历左子树，再后序遍历右子树，最后访问根。
\end{itemize}
把“访问根”这一行在递归代码中挪动位置，就得到三种算法：
\begin{lstlisting}[language=C]
void PreOrder(BiTree T) {
    if (T) {
        visit(T);              // 根
        PreOrder(T->lchild);   // 左
        PreOrder(T->rchild);   // 右
    }
}
void InOrder(BiTree T) {
    if (T) {
        InOrder(T->lchild);    // 左
        visit(T);              // 根
        InOrder(T->rchild);    // 右
    }
}
void PostOrder(BiTree T) {
    if (T) {
        PostOrder(T->lchild);  // 左
        PostOrder(T->rchild);  // 右
        visit(T);              // 根
    }
}
\end{lstlisting}
\end{formula}

\subsubsection{非递归遍历与栈}

递归能工作，是因为系统栈替我们记住了“还没有做完的结点”。自己用栈模拟，就能把过程展开。以中序为例，反复做两件事：沿着左孩子一路压栈，直到空；然后弹栈访问，转向右子树。

\begin{lstlisting}[language=C]
void InOrderNR(BiTree T) {
    Stack S; InitStack(&S);
    BiTree p = T;
    while (p || !StackEmpty(S)) {
        if (p) {
            Push(&S, p);         // 沿左链走到底，边走边压
            p = p->lchild;
        } else {
            Pop(&S, &p);         // 左边走不动了，弹出栈顶
            visit(p);
            p = p->rchild;       // 转向右子树
        }
    }
}
\end{lstlisting}

先序只是把 \texttt{visit(p)} 挪到压栈之前；后序麻烦一些，因为弹出栈顶时可能只是“左子树刚做完”，右子树还没访问。解决办法是记一个 \texttt{lastVisited}：只有右孩子为空或已经访问过，才真正弹出并访问。

\begin{lstlisting}[language=C]
void PostOrderNR(BiTree T) {
    Stack S; InitStack(&S);
    BiTree p = T, last = NULL;
    while (p || !StackEmpty(S)) {
        if (p) {
            Push(&S, p);
            p = p->lchild;
        } else {
            GetTop(S, &p);
            if (p->rchild && p->rchild != last)
                p = p->rchild;        // 右子树还没做，先去右边
            else {
                Pop(&S, &p);
                visit(p);
                last = p;             // 记录刚访问的结点
                p = NULL;
            }
        }
    }
}
\end{lstlisting}

\subsubsection{层次遍历与队列}

层次遍历按“从上到下、同层从左到右”访问。它不用栈，而用队列：根先入队；每次出队一个结点并访问，然后把它的左、右孩子依次入队。

\begin{lstlisting}[language=C]
void LevelOrder(BiTree T) {
    Queue Q; InitQueue(&Q);
    if (T) EnQueue(&Q, T);
    while (!QueueEmpty(Q)) {
        BiTree p;
        DeQueue(&Q, &p);
        visit(p);
        if (p->lchild) EnQueue(&Q, p->lchild);
        if (p->rchild) EnQueue(&Q, p->rchild);
    }
}
\end{lstlisting}

\subsection{由遍历序列还原二叉树}

\begin{conclusion}{哪些序列组合能唯一确定二叉树}{reconstruct-theorem}
在结点关键字互异、序列合法的前提下：
\begin{itemize}
  \item 先序 + 中序：唯一确定；
  \item 后序 + 中序：唯一确定；
  \item 层次 + 中序：唯一确定；
  \item 先序 + 后序：\textbf{不能}唯一确定。
\end{itemize}
\end{conclusion}

先序 + 中序的做法只有一句话：先序的第一个是根，拿这个根去中序里切出左右两段，再按段长回到先序切分，递归处理。

BiTree Build(char pre[], char in[], int pl, int pr, int il, int ir) {
    if (pl > pr) return NULL;
    BiTree root = (BiTree)malloc(sizeof(BiTNode));
    root->data = pre[pl];
    int k = il;
    while (k <= ir && in[k] != pre[pl]) k++;

    root->rchild = Build(pre, in, pl+leftLen+1, pr, k+1, ir);
    return root;
}

\subsection{线索二叉树：把空指针用起来}

二叉链表有 $n+1$ 个空指针。遍历时我们常常需要“下一个是谁”“上一个是谁”，而递归或栈都在额外花空间。线索二叉树的做法是：把空着的左指针改为指向该遍历次序下的\textbf{前驱}，空着的右指针改为指向\textbf{后继}。指针现在有两种身份，必须加标记区分。

\begin{mydef}{线索二叉树}{thread-tree}
结点增加两个标志位 \texttt{ltag}、\texttt{rtag}：
\begin{itemize}
  \item \texttt{ltag=0}：\texttt{lchild} 指向左孩子；\texttt{ltag=1}：\texttt{lchild} 指向前驱线索。
  \item \texttt{rtag=0}：\texttt{rchild} 指向右孩子；\texttt{rtag=1}：\texttt{rchild} 指向后继线索。
\end{itemize}
按某种遍历次序建立的线索，分别称为先序、中序、后序线索二叉树。
\end{mydef}

\begin{lstlisting}[language=C]
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;          // 0: 孩子; 1: 线索
} ThreadNode, *ThreadTree;
\end{lstlisting}

中序线索化的过程就是中序遍历，只是把“访问”换成“修改空指针”。需要用一个 \texttt{pre} 记住刚刚访问的结点，才能把前驱的后继线索接上：

\begin{lstlisting}[language=C]
ThreadNode *pre = NULL;            // 全局变量，指向刚访问的结点

void InThread(ThreadTree T) {
    if (T) {
        InThread(T->lchild);
        if (T->lchild == NULL) {   // 左空，指向前驱
            T->lchild = pre;
            T->ltag = 1;
        }
        if (pre != NULL && pre->rchild == NULL) {  // 前驱的右空，指向后继
            pre->rchild = T;
            pre->rtag = 1;
        }
        pre = T;
        InThread(T->rchild);
    }
}
\end{lstlisting}

找前驱、后继分两种情况。以中序为例，结点 $p$ 的后继：
\begin{itemize}
  \item 若 \texttt{rtag=1}，右指针本身就是后继；
  \item 若 \texttt{rtag=0}，说明有右子树，中序下下一个访问的是右子树的\textbf{最左下}结点。
\end{itemize}
前驱完全对称：\texttt{ltag=1} 时左指针就是前驱；否则是左子树的\textbf{最右下}结点。

\begin{lstlisting}[language=C]
ThreadNode *InSucc(ThreadNode *p) {
    if (p->rtag == 1) return p->rchild;
    ThreadNode *q = p->rchild;
    while (q->ltag == 0) q = q->lchild;   // 右子树最左下
    return q;
}
ThreadNode *InPred(ThreadNode *p) {
    if (p->ltag == 1) return p->lchild;
    ThreadNode *q = p->lchild;
    while (q->rtag == 0) q = q->rchild;   // 左子树最右下
    return q;
}
\end{lstlisting}

\begin{attention}
线索只对建立它的那种次序有效。三种次序下“就地找前驱/后继”的难易正好相反：
\begin{itemize}
  \item 中序：前驱、后继都能就地找到，不需要双亲或栈；当线索指针不可用时，要沿子树走到最左下或最右下，最坏 $O(h)$；
  \item 先序：后继容易（有左孩子就是左孩子，否则是右孩子或线索），\textbf{前驱}可能在祖先方向，通常要借助双亲指针；
  \item 后序：前驱容易，\textbf{后继}可能在祖先方向，通常要借助双亲指针。
\end{itemize}
另外，判断 \texttt{lchild} 到底指孩子还是线索，必须看 \texttt{ltag}，不能看它是否为空。
\end{attention}

\subsection{树、森林与二叉树的互相表示}

一般树每个结点可以有任意多个孩子，直接用“左孩子、右孩子”两个指针存不下。常见办法有三种。

\textbf{双亲表示法}用数组存每个结点和它的双亲下标，求双亲 $O(1)$，求孩子要扫描整个数组。\textbf{孩子表示法}把每个结点的孩子串成链表。408 最常用的是\textbf{孩子兄弟表示法}：每个结点两个指针，\texttt{firstchild} 指向第一个孩子，\texttt{nextsibling} 指向下一个兄弟。

\begin{lstlisting}[language=C]
typedef struct CSNode {
    ElemType data;
    struct CSNode *firstchild, *nextsibling;
} CSNode, *CSTree;
\end{lstlisting}

这两个指针恰好就是二叉树的左、右指针，于是任何树都能唯一地转成二叉树，规则叫“\textbf{左孩子右兄弟}”：

\begin{enumerate}
  \item 每个结点只保留与第一个孩子的连线，作为左孩子；
  \item 结点原来的兄弟，依次连成右孩子链；
  \item 原先向下的边因此变成向左下或向右下的边。
\end{enumerate}

遍历的对应关系常考，而且很好记：
\begin{itemize}
  \item 树的\textbf{先根遍历} = 对应二叉树的\textbf{先序}；

\end{itemize}
树没有“中根遍历”，因为一个结点有多个孩子，“中间”没有定义。

\subsection{Huffman 树：让总码长最短}

设四个字符出现的次数是 $2,4,5,7$，总共 18 个字符。若用等长编码，每个字符 2 位，共需 $18\times2=36$ 位。能不能更短？把出现多的字符编短一些、出现少的编长一些，总长度就会下降。Huffman 树给出的是一种最优的变长前缀编码，本例可以做到 35 位。

衡量一棵带权二叉树好坏的量是\textbf{带权路径长度}：
\[
\mathrm{WPL}=\sum_{i=1}^{n} w_i\,l_i ,
\]
其中 $w_i$ 是第 $i$ 个叶子的权值，$l_i$ 是它到根的边数（也就是深度减一）。WPL 越小，平均码长越短。

\begin{mydef}{Huffman 树}{huffman-def}
给定 $n$ 个权值 $w_1,\ldots,w_n$ 作为 $n$ 个叶子的权，若某棵二叉树的 WPL 达到最小，称它为\textbf{最优二叉树}或 \textbf{Huffman 树}。
\end{mydef}

构造方法是贪心的，每一步都合并当前最小的两个：
\begin{enumerate}
  \item 把 $n$ 个权值各自看成一棵单结点树，组成森林；
  \item 取出根权值最小的两棵树，作为左右子树合并，新根的权值为两者之和；
  \item 把新树放回森林，重复，直到只剩一棵树。
\end{enumerate}
用最小堆实现，每次取两个最小值、压回一个和，复杂度 $O(n\log n)$。

Huffman 树有几条常用性质，都可以从构造过程直接看出来：
\begin{enumerate}
  \item 没有度为 1 的结点。每次合并都是“左、右各一棵”，不会产生单孩子结点。于是 $n_1=0$，由 $n_0=n_2+1$ 得总结点数 $n=2n_0-1$。
  \item 权值大的叶子不会比权值小的叶子更深。否则交换这两个叶子的权值，树形不变而 WPL 下降，与最优性矛盾。
  \item 树不唯一：左右子树可以交换，等权权值的合并次序也可以不同。但 \textbf{WPL 唯一}。
  \item WPL 等于所有内部结点权值之和。每个叶子权值在它到根的每条边上被计一次，累加起来正好等于所有祖先内部结点的权值和。
\end{enumerate}

把 Huffman 树的左分支记 0、右分支记 1，从根到叶子的 0/1 串就是该字符的编码。由于字符只放在叶子上，任何一个编码都不会是另一个编码的前缀——这就是\textbf{前缀编码}，解码时不必预先知道码长，从根出发逐位下行，到叶子就输出一个字符，再回到根继续。

\begin{attention}
Huffman 编码是“前缀码中最优”的，不是“所有编码中最优的”。如果允许编码之间互为前缀，虽然平均长度可能更短，但无法唯一解码，实际不能用。

计算题里常见的口径要写清楚：平均码长 $=\mathrm{WPL}/\sum w_i$；等长编码位数 $=\lceil\log_2 n\rceil$；压缩率按“节省的位数 / 原位数”计算。此外，给定一组编码判断是否为前缀码，只需检查有没有一个码是另一个码的前缀。
\end{attention}

\subsection{二叉排序树}

二叉排序树（BST）把“左小右大”写进结构里，借它可以在 $O(h)$ 时间内完成查找、插入、删除。$h$ 是树高，理想情况 $O(\log n)$，退化成单支树时 $O(n)$。

\begin{mydef}{二叉排序树}{bst-def}
一棵二叉树是二叉排序树，当且仅当：对任意结点，其左子树（若存在）中所有关键字都小于该结点的关键字，其右子树中所有关键字都大于该结点的关键字，且左右子树本身也是二叉排序树。
\end{mydef}

注意定义要求的是“整棵左子树都小”，不是“左孩子小”。因此判断一棵树是否为 BST，不能只比较父子，正确做法是中序遍历，检查序列是否严格递增；或者递归时把每个结点限制在一个开区间 $(lo,hi)$ 内。

查找的过程就是不断缩小可行区间：比当前结点小就往左，区间上界改为当前关键字；大就往右，下界改为当前关键字。

\begin{lstlisting}[language=C]
BiTree BSTSearch(BiTree T, KeyType key) {
    while (T != NULL && T->data != key)
        T = (key < T->data) ? T->lchild : T->rchild;
    return T;                        // 找不到时返回 NULL
}

int BSTInsert(BiTree *T, KeyType key) {
    if (*T == NULL) {
        *T = (BiTree)malloc(sizeof(BiTNode));
        (*T)->data = key;
        (*T)->lchild = (*T)->rchild = NULL;
        return 1;
    }
    if (key == (*T)->data) return 0; // 已存在，不重复插入
    return (key < (*T)->data)
         ? BSTInsert(&((*T)->lchild), key)
         : BSTInsert(&((*T)->rchild), key);
}
\end{lstlisting}

插入的落点一定是某个空指针，新结点总是成为叶子，不需要移动已有结点。删除分三种情况：
\begin{enumerate}
  \item 被删结点是叶子：直接摘掉，把双亲对应指针置空；
  \item 只有一个孩子：用这个孩子顶替它的位置；
  \item 有两个孩子：用中序前驱（左子树最右下的结点）或中序后继（右子树最左下的结点）顶替它的关键字，再删除那个替身。替身至多只有一个孩子，于是归入前两种情况。
\end{enumerate}

\subsection{AVL 树：把树高压住}

AVL 树是最早的自平衡二叉排序树。它在每个结点上记录左右子树的高度差，一旦某个结点的平衡因子超出 $\{-1,0,1\}$，就通过旋转把局部结构调整回来。

\begin{mydef}{AVL 树}{avl-def}
二叉排序树中，若每个结点的\textbf{平衡因子}
\[
\mathrm{BF}(v)=h(v\text{ 的左子树})-h(v\text{ 的右子树})
\]
都满足 $|\mathrm{BF}(v)|\leqslant1$，称为 \textbf{AVL 树}。这里叶子高度为 1，空树高度为 0，因此叶子 $\mathrm{BF}=0$。
\end{mydef}

插入一个结点后，只有从插入点到根这条路径上的平衡因子会变。从插入点往上找，第一个失衡的结点记为 $z$；沿 $z$ 到插入点的路径取下面两层的结点 $y$ 和 $x$，根据 $z,y,x$ 的相对位置分成四种情况：

\begin{itemize}
  \item \textbf{LL}：$x$ 在 $z$ 的左子树的左子树，对 $z$ 做一次\textbf{右旋}；
  \item \textbf{RR}：$x$ 在 $z$ 的右子树的右子树，对 $z$ 做一次\textbf{左旋}；
  \item \textbf{LR}：$x$ 在 $z$ 的左子树的右子树，先对 $y$ 左旋，再对 $z$ 右旋；
  \item \textbf{RL}：$x$ 在 $z$ 的右子树的左子树，先对 $y$ 右旋，再对 $z$ 左旋。
\end{itemize}

单旋转的代码以 LL 为例：把 $y$ 的右子树挂到 $z$ 的左边，再让 $z$ 成为 $y$ 的右孩子。

\begin{lstlisting}[language=C]
void RotateRight(BiTree *z) {      // LL
    BiTree y = (*z)->lchild;
    (*z)->lchild = y->rchild;      // y 的右子树改挂到 z 左边
    y->rchild = *z;
    *z = y;                        // y 上位
}
void RotateLeft(BiTree *z) {       // RR
    BiTree y = (*z)->rchild;
    (*z)->rchild = y->lchild;
    y->lchild = *z;
    *z = y;
}
\end{lstlisting}

AVL 的插入最多做一次旋转（单旋或双旋）就能恢复整棵树；删除则可能沿路径一直往上，需要 $O(\log n)$ 次旋转。无论哪种，查找、插入、删除都是 $O(\log n)$。

为什么高度能压到对数级？考虑高度为 $h$ 的 AVL 树最少需要多少个结点，记为 $N_h$（叶子高度为 1，空树 $h=0$）。根的两棵子树高度最多差 1，为了让结点最少，一边取 $h-1$，另一边取 $h-2$：
\[
N_h=N_{h-1}+N_{h-2}+1,\qquad N_0=0,\ N_1=1 .
\]
数列是 $1,2,4,7,12,20,\ldots$，恰好 $N_h=F_{h+2}-1$（$F_1=F_2=1$）。由 Fibonacci 数的增长可得 $h<1.44\log_2(n+2)$，所以 $h=O(\log n)$。

\subsection{并查集：只关心“谁和谁一伙”}

并查集管理若干个不相交的集合，只支持两种操作：查某个元素属于哪个集合（\texttt{Find}），把两个集合合并（\texttt{Union}）。它底层就是一片森林，用双亲表示法存：数组 \texttt{parent[i]} 记录 $i$ 的双亲，根结点的 \texttt{parent} 存负数，绝对值表示集合大小。

\begin{lstlisting}[language=C]
int parent[MaxSize];

int Find(int x) {                    // 路径压缩
    if (parent[x] < 0) return x;
    return parent[x] = Find(parent[x]);
}

void Union(int x, int y) {           // 按大小合并
    int rx = Find(x), ry = Find(y);
    if (rx == ry) return;
    if (parent[rx] > parent[ry]) {   // rx 集合更小（负数的绝对值小）
        parent[ry] += parent[rx];
        parent[rx] = ry;
    } else {
        parent[rx] += parent[ry];
        parent[ry] = rx;
    }
}
\end{lstlisting}

只按大小合并，树高是 $O(\log n)$；只做路径压缩，单次操作可能很慢但摊还也不差；两者一起用，摊还复杂度是 $O(\alpha(n))$，其中 $\alpha$ 是反 Ackermann 函数，在实际规模内不超过 4。408 里它常与 Kruskal 算法一起出现：判断加入一条边会不会成环，就是判断两个端点是否已经在同一个集合。
