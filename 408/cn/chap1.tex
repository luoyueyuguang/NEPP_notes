\section{计算机网络体系结构}

在浏览器地址栏输入一个网址，回车，几十毫秒后页面出现。这段时间里，浏览器只负责组织 HTTP 请求，操作系统里的 TCP 负责分段、编号和重传，网卡把比特变成电信号或光信号，交换机按 MAC 地址转发帧，路由器按 IP 地址选路。没有任何一个部件理解整个过程，但每一层都把自己的事情做完，把结果交给下一层。这种“各管一段、上下衔接”的组织方式就是分层。本章要建立的，就是这套分工的语言：协议、服务、封装、PDU，以及衡量网络快慢的几个基本指标。

按覆盖范围，网络分为广域网 WAN、城域网 MAN、局域网 LAN 和个域网 PAN；按交换方式，分为电路交换、报文交换和分组交换。408 的题目主要在这两个维度上展开，其中交换方式会直接影响时延的计算。

\subsection{分层：一次网页访问拆开来看}

假设主机 A 通过一个交换机和一个路由器访问主机 B。A 的应用层生成一条 HTTP 请求；传输层给它加上源端口、目的端口和序号，交给网络层；网络层加上源 IP、目的 IP，交给数据链路层；数据链路层加上帧头和帧尾，交给物理层；物理层把比特逐个送上介质。

中间设备并不是七层全做。交换机收到帧后，只看目的 MAC 地址，查表转发，根本不拆开 IP 首部；路由器收到帧后，剥掉帧头，取出 IP 分组，查路由表决定下一跳，再给分组套上新的帧头转发出去。也就是说，交换机工作在数据链路层，路由器工作到网络层，它们各自只理解自己那一层及以下的内容。

第 $n$ 层向上层提供服务的逻辑接口叫\textbf{服务访问点}（SAP，Service Access Point）。在 408 的语境下常记：数据链路层的 SAP 是 MAC 地址，网络层的 SAP 是 IP 地址，传输层的 SAP 是端口号。SAP 是层间交往的“门牌号”，上层把数据送到这个门牌号，下层就知道该交给哪个实体。

分层不是免费的：每层都要加首部，层间调用也要花时间。但它带来的独立性很值钱。IPv4 升级到 IPv6，应用层的 HTTP 不用改；以太网从 10 Mb/s 升到 100 Gb/s，IP 也不用改。只要下层向上提供的服务不变，上层的实现就可以不动。所谓\textbf{网络体系结构}，就是分层方式和各层协议的集合；它是抽象定义，不是具体实现，同一种体系结构可以有多种实现。

协议是通信双方必须遵守的规则，包含三个要素：
\begin{itemize}
  \item \textbf{语法}：数据和控制信息长什么样。例如 HTTP 请求行由方法、URL、版本三段组成，字段之间用空格分隔。
  \item \textbf{语义}：每个字段是什么意思、收到后要做什么。例如状态码 404 表示资源不存在，TCP 的 SYN 表示请求建立连接。
  \item \textbf{时序}：事件谁先谁后、什么时候重发。例如 TCP 三次握手的报文顺序，以及超时计时器的设置。
\end{itemize}

\begin{attention}
语法管“长什么样”，语义管“是什么意思、做什么”，时序管“什么时候做”。408 喜欢把这三者和“服务、接口、协议”混在一起出选择题；判断时先问：这句话描述的是格式、含义，还是顺序？
\end{attention}

\subsection{封装：首部是怎样一层层加上的}

仍以上面的 HTTP 请求为例。假设应用层交给 TCP 的数据是 $1000$ B。TCP 加上 $20$ B 首部（源端口、目的端口、序号、确认号等），得到 $1020$ B 的报文段；IP 再加上 $20$ B 首部（源 IP、目的 IP、协议号、生存时间等），得到 $1040$ B 的分组；以太网加上 $14$ B 帧首部（目的 MAC、源 MAC、类型）和 $4$ B 尾部 FCS，得到 $1058$ B 的帧。首部开销是 $58$ B，约占原数据的 $5.8\%$。数据越短，首部占比越大，这也是小包效率低的原因之一。

这个过程叫\textbf{封装}（encapsulation）：本层把上层交下来的 PDU 当作自己的服务数据单元（SDU），在前面加上本层首部（有时还在后面加尾部），形成本层的 PDU。首部里的地址、序号、长度、校验等控制信息，只对本层有意义；上层数据对下层来说只是一串字节，下层不关心它的内容。接收方的过程相反，叫\textbf{解封装}：每层检查并去掉本层首部，把剩下的数据交给上一层。

各层 PDU 的名称要能对号入座：应用层叫\textbf{报文}（message），传输层 TCP 叫\textbf{报文段}（segment）、UDP 叫\textbf{用户数据报}（user datagram），网络层叫\textbf{分组}或\textbf{数据报}（packet/datagram），数据链路层叫\textbf{帧}（frame），物理层是\textbf{比特}（bit）。408 的选择题经常用“报文段/分组/帧”来定位层，看到名字就要能反应出它属于哪一层。

封装也不等于“把数据复制一遍”。实际实现中，协议栈往往在缓冲区头部预留空间，逐层向前移动指针填写首部，避免整块数据的搬移；但概念上，仍然是“上层 PDU 加本层控制信息”这个模型。

\subsection{三种交换方式：电路、报文、分组}

两台主机之间往往隔着多个交换结点。数据以什么单位、按什么方式通过这些结点，直接决定了时延和线路利用率。

\textbf{电路交换}先建立一条端到端的通路（拨号、信令），建立后双方独占这条通路，数据像流水一样连续通过，中间结点不做存储转发。传统电话网是典型例子。设建立时间为 $s$，报文长为 $M$ bit，链路速率为 $R$，共 $k$ 段链路，每段传播时延为 $d_{\mathrm{prop}}$，忽略处理时延，则
\[
T_{\mathrm{c}} = s + \frac{M}{R} + k\,d_{\mathrm{prop}}.
\]
建立时间可能很长；但一旦建立，数据在中间结点没有“收完再发”的等待。

\textbf{报文交换}把整个报文作为一个单位。结点必须收完整个报文、做完校验，才能把它转发到下一跳。因此每个结点都需要能缓存整个报文的缓冲区，长报文会长时间占用链路。总时延为
\[
T_{\mathrm{m}} = k\frac{M}{R} + k\,d_{\mathrm{prop}},
\]
因为报文在 $k$ 段链路上各被完整发送了一次。

\textbf{分组交换}把报文切成若干等长分组，每个分组独立地存储转发。关键变化是流水线：第 1 个分组在第 2 条链路上传输时，第 2 个分组已经在第 1 条链路上传输，不必等整个报文传完。设报文长 $M$ bit，分成 $n$ 个长为 $L=M/n$ 的分组，链路数仍为 $k$，则第 1 个分组到达终点需要 $k(L/R+d_{\mathrm{prop}})$；此后每隔 $L/R$ 到达一个分组，共 $n$ 个，所以
\[
T_{\mathrm{p}} = k\left(\frac{L}{R}+d_{\mathrm{prop}}\right) + (n-1)\frac{L}{R}
= \frac{(n+k-1)L}{R} + k\,d_{\mathrm{prop}}.
\]
当 $n$ 很大、$L$ 很小时，$T_{\mathrm{p}} \approx M/R + k d_{\mathrm{prop}}$，与电路交换在数据传输阶段所需的时间基本相同，只多了 $(k-1)L/R$ 的流水线填充；而报文交换是 $kM/R$，差距随链路数 $k$ 线性扩大。

分组交换的代价是每个分组都要带首部，开销随分组数增加；结点排队还会带来排队时延和时延抖动，所以实时语音不一定适合分组交换。它的好处是线路可以统计复用，多个用户共享链路，空闲时不会像电路交换那样浪费带宽。

还要区分“分组交换”和“服务类型”。分组交换是交换方式；在网络层，它既可以提供无连接的\textbf{数据报服务}（IP），也可以提供面向连接的\textbf{虚电路服务}（X.25、帧中继）。虚电路不是电路交换：它仍然是分组交换，分组仍然要在结点存储转发，只是沿着预先建立的逻辑路径走，省去了每个分组的独立选路。

\subsection{带宽、时延与“管道”}

“带宽”这个词有两种用法。模拟通信里，带宽指信道能通过的频率范围，单位是 Hz；数字通信里，带宽指链路能达到的最高数据率，单位是 b/s。408 题目说“链路带宽为 100 Mb/s”通常指后者，说“电话线带宽为 3 kHz”指前者。看到单位就能判断说的是哪一种。

速率的进位是十进制：$1$ kb/s $=10^3$ b/s，$1$ Mb/s $=10^6$ b/s，$1$ Gb/s $=10^9$ b/s。存储容量却常用二进制：$1$ KB $=2^{10}$ B $=1024$ B。题目里“一个 1 MB 的文件在 1 Mb/s 的链路上传输”不是简单的 $1/1=1$ 秒，必须先把字节换成比特，再按十进制速率计算。

\begin{formula}{时延与两个常用乘积}{delay-formulas}
\begin{itemize}
  \item 发送时延：$d_{\mathrm{trans}}=\dfrac{L}{R}$，$L$ 为数据长度（bit），$R$ 为发送速率（b/s）。
  \item 传播时延：$d_{\mathrm{prop}}=\dfrac{D}{v}$，$D$ 为链路长度（m），$v$ 为信号在介质中的传播速率（m/s）。
  \item 结点总时延：$d=d_{\mathrm{proc}}+d_{\mathrm{queue}}+d_{\mathrm{trans}}+d_{\mathrm{prop}}$。
  \item 时延带宽积：$R\,d_{\mathrm{prop}}$，单位是 bit，表示链路“管道”中最多能容纳的比特数。
  \item 利用率 $U$ 与空载时延 $D_0$ 的排队论近似：$D=\dfrac{D_0}{1-U}$。
\end{itemize}
\end{formula}

处理时延 $d_{\mathrm{proc}}$ 是结点检查首部、查表、做差错检测的时间；排队时延 $d_{\mathrm{queue}}$ 取决于队列长度和当前负载，是最不确定的一项。考试里如果题目没有特别说明，通常忽略这两项，只算发送和传播。

这里最重要的是两个“与什么有关”。发送时延由数据量 $L$ 和发送速率 $R$ 决定，与距离无关；传播时延由距离 $D$ 和传播速率 $v$ 决定，与发送速率无关。把带宽从 100 Mb/s 提高到 1 Gb/s，只能缩短发送时延，不能改变信号在光纤里跑 1000 km 的时间。反过来，链路拉长也不会让网卡把数据推上介质的速度变慢。

举个具体的数：$1000$ B $=8000$ bit 的数据在 $100$ Mb/s 的链路上发送，
\[
d_{\mathrm{trans}}=\frac{8000}{10^8}=80\ \mu\mathrm{s}.
\]
若链路长 $1000$ km，信号速率为 $2\times10^8$ m/s，则
\[
d_{\mathrm{prop}}=\frac{10^6}{2\times10^8}=5\ \mathrm{ms}.
\]
传播时延是发送时延的 $60$ 多倍。长距离链路上，决定“快不快”的往往不是带宽，而是光跑得不够快。

用刚才的数：$100$ Mb/s 的链路，单向传播时延 $5$ ms，时延带宽积为
\[
100\times10^6 \times 5\times10^{-3}=5\times10^5\ \mathrm{bit},
\]
也就是 $500$ kbit，约 $62.5$ kB。这条链路“装满”时，有 $500$ kbit 的数据正在路上，还没有到达接收端。

\textbf{往返时间}（RTT）是从发送端发出数据到收到确认的时间，包含往返的传播、发送、处理和排队。除非题目明确忽略其他项，不能只按 $2D/v$ 计算。RTT 在后面的可靠传输和拥塞控制里会反复出现。

\textbf{吞吐量}是单位时间内实际通过网络的数据量，受瓶颈链路限制：端到端吞吐量约为 $\min(R_1,R_2,\ldots,R_k)$。它可能远小于带宽，因为协议首部、确认、重传和等待都会占时间。\textbf{信道利用率} $U$ 是有数据通过的时间占总时间的比例；排队论给出的近似 $D=D_0/(1-U)$ 说明，利用率接近 $1$ 时分母趋近 $0$，时延会急剧上升。这就是网络“跑满”时体验明显变差的原因。

\subsection{OSI 七层与 TCP/IP 四层}

OSI 七层模型是 ISO 在 20 世纪 80 年代提出的参考模型，是法律上的国际标准，但实际部署并不成功。TCP/IP 是互联网真正使用的协议族，是事实标准。408 教学采用五层模型：把 OSI 的上三层合并为应用层，下两层保留，既保留了分层的清晰性，又贴近实际协议。

七层从下往上依次是：
\begin{itemize}
  \item \textbf{物理层}：在传输介质上传输比特，规定接口的机械、电气、功能、规程特性。它不关心比特的含义，只关心“0 和 1 能不能可靠地送出去”。
  \item \textbf{数据链路层}：把比特流组织成帧，处理相邻结点之间的差错控制、流量控制和介质访问控制。它关心“这一跳”。
  \item \textbf{网络层}：把分组从源主机送到目的主机，负责路由选择、分组转发、拥塞控制和网际互连。它关心“走哪条路”。
  \item \textbf{传输层}：为两台主机的进程提供端到端通信，负责复用与分用、可靠传输和流量控制。它关心“哪个进程”。
  \item \textbf{会话层}：建立、管理和终止会话，在数据流中插入同步点，使长传输中断后可以从同步点继续。
  \item \textbf{表示层}：做数据格式转换、加密解密和压缩，解决不同主机表示方法不一致的问题。
  \item \textbf{应用层}：直接为用户应用提供网络服务。
\end{itemize}

网络层提供的是主机到主机的逻辑通信，传输层提供的是进程到进程的通信，数据链路层只负责相邻结点之间。三者范围不同，这是选择题的常见考点。

TCP/IP 四层把 OSI 的物理层和数据链路层合并为\textbf{网络接口层}，把会话层、表示层、应用层合并为\textbf{应用层}，中间保留\textbf{网际层}和\textbf{传输层}。网络接口层不规定具体协议，实际使用以太网、PPP、Wi-Fi 等；网际层的核心是 IP，辅以 ICMP、ARP、IGMP 和路由协议；传输层是 TCP 和 UDP；应用层是 HTTP、DNS、SMTP、FTP、DHCP 等。

\subsection{协议、服务与 SAP}

协议和服务是分层体系里最容易说反的一对概念。协议是\textbf{水平}的：它只规定对等层之间如何通信，A 的 TCP 和 B 的 TCP 按 TCP 协议交换报文段，A 的 HTTP 和 B 的 HTTP 按 HTTP 协议交换请求和响应。服务是\textbf{垂直}的：下层通过层间接口向上层提供功能，上层只管调用，不关心下层怎么实现。

这个区别的实际意义是：第 $n$ 层协议的实现可以换，只要它向上提供的服务不变，第 $n+1$ 层就不受影响。例如，底层从以太网换成 Wi-Fi，IP 层看到的仍然是一个能发送和接收分组的接口，IP 协议本身不需要改。

SAP 是服务访问点，是相邻层之间交换信息的逻辑接口。数据链路层的 SAP 是 MAC 地址，网络层的 SAP 是 IP 地址，传输层的 SAP 是端口号。上层把数据送到 SAP，下层就知道该交给哪个实体；这就像寄信时写清楚门牌号，邮递员不需要知道屋里的人是谁。

服务原语描述上层和下层如何交互，常见的有四类：
\begin{itemize}
  \item \textbf{请求}（request）：服务用户要求服务提供者做某件事，方向是上层到下层的。
  \item \textbf{指示}（indication）：服务提供者通知服务用户有事件发生，方向是下层到上层的。
  \item \textbf{响应}（response）：服务用户对指示做出答复，方向是上层到下层的。
  \item \textbf{确认}（confirm）：服务提供者报告请求的结果，方向是下层到上层的。
\end{itemize}
有确认的服务四类原语都会出现；无确认的服务通常只有请求和指示。注意“请求”是上层发出的，“指示”才是下层通知上层，二者方向相反，选择题常在这里设陷阱。

服务还分为面向连接和无连接两类。面向连接服务在数据交换前建立连接、交换后释放连接，数据按顺序传送；无连接服务每个报文独立选路，不保证顺序。TCP 提供面向连接的传输服务，UDP 提供无连接的传输服务；IP 在网络层提供无连接的数据报服务，虚电路则在网络层提供面向连接的服务。面向连接不等于可靠：连接只是建立了路径和状态，可靠性还要靠确认、重传和序号来保证，这两件事要分开看。
