\section{应用层}

应用层是协议栈里离用户最近的一层。浏览器地址栏里的一次回车、邮件客户端的一次发送、文件传输工具的一次下载，背后都是应用层协议在约定报文长什么样、谁先发、收到什么算成功。应用层不负责把比特送到对端，那是下面几层的事；它只定义通信双方交换的消息和动作。传输层用端口号把数据交给正确的进程，所以每种应用协议都要选定 TCP 或 UDP，并占用一个（或一组）端口。

应用层协议可以直接架在 TCP 上，也可以直接用 UDP。图里把常见的几种协议按传输层分了组，端口号写在协议名下面。DNS 的普通查询走 UDP 53，只有在响应被截断或者做区域传送时才改用 TCP 53；DHCP 则完全依赖 UDP 广播，因为客户端开口问的时候还没有 IP 地址。HTTP、FTP、SMTP、POP3/IMAP 都要求可靠传输，所以用 TCP。

大多数应用协议采用客户/服务器模型：客户主动发起请求，服务器被动等待。DNS 存根解析器、浏览器、FTP 客户端、邮件用户代理都是客户；DNS 权限服务器、Web 服务器、FTP 服务器、邮件服务器都是服务器。P2P 应用则把每个节点同时当作客户和服务器，文件分发和区块链是典型例子。

\subsection{DNS：把域名换成 IP 地址}

在浏览器里输入 \texttt{www.example.com}，浏览器并不知道它的 IP。操作系统里的存根解析器（stub resolver）会把这个问题交给本地域名服务器，本地服务器可能还要去问根、顶级域和权限服务器。整个系统要做的事情不止“域名换 IP”：它还要保存邮件路由（MX）、别名（CNAME）、反向解析（PTR）等信息。DNS 就是这些记录的分布式数据库。

\subsubsection{域名空间是一棵树}

域名从右往左读。\texttt{www.example.com.} 最后那个点代表根，\texttt{com} 是顶级域，\texttt{example} 是二级域，\texttt{www} 是主机名。每个标号（label）不超过 63 个字符；整个域名的文本表示不超过 253 个字符，DNS 线上编码不超过 255 字节。域名不区分大小写，但保留原始大小写方便显示。

域和区不是一回事。域是名字空间里的一棵子树；区（zone）是某台权限域名服务器实际管辖的那一部分。一个域可以划分成多个区，把子域委派给下级服务器；一个区只属于一个域，不能跨域。图里虚线框标出的就是 \texttt{example.com} 区：它包含 \texttt{example.com} 本身和下面的主机 \texttt{www}，而 \texttt{com} 区只保留指向它的 NS 委派记录和必要的 glue 记录。

\subsubsection{四类服务器各管一段}

根域名服务器不保存所有域名。它只保存根区：每个顶级域的 NS 记录，以及必要的 glue A/AAAA 记录（比如 \texttt{com} 的服务器地址）。根服务器有 13 个标识（\texttt{a.root-servers.net} 到 \texttt{m.root-servers.net}），通过任播在全球部署大量实例，所以“13 台机器”是误解。

顶级域服务器管 \texttt{.com}、\texttt{.org}、\texttt{.cn} 这些顶级域，返回下一级区的权限服务器地址。权限域名服务器保存某个区的完整数据，能给出最终答案。本地域名服务器（也叫递归解析器）是主机访问 DNS 的第一站，它替主机完成后续查询并缓存结果；它不属于“根—顶级—权限”的层次结构，但通常离主机很近。

\subsubsection{递归查询和迭代查询}

递归查询是“你替我查到底”：被问的服务器如果不知道答案，必须自己再去问别的服务器，最后把最终结果或者失败返回给请求者，不能只给一个“去问某某”的转介。迭代查询是“你告诉我下一步问谁”：被问的服务器只返回下一台服务器的地址（转介），由请求者自己继续问。

主机到本地域名服务器通常用递归，因为主机不想承担逐级查询的负担；本地域名服务器到根、顶级、权限服务器通常用迭代，因为递归解析器自己有能力继续问，而且这样根服务器不用替每个客户跑完全程。这不是协议强制的：服务器可以在响应里把递归可用（RA）标志置 0，拒绝递归请求；实际使用哪种方式取决于配置。

\subsubsection{缓存、报文格式与传输层选择}

DNS 的每条记录都有 TTL（生存时间）。本地服务器拿到记录后缓存一段时间，TTL 到期就删除；它也可以缓存否定答案（域名不存在），但否定缓存的 TTL 通常更短。缓存能加快解析、减轻根服务器压力，代价是记录变更后旧值可能在一段时间内仍然生效。主机的 \texttt{hosts} 文件是本地静态配置，查询时先于 DNS 使用，但它不是 DNS 缓存。

DNS 查询和响应共用一种报文格式：12 字节首部（事务 ID、标志、问题数、回答数、授权数、附加数），后面是问题区、回答区、授权区和附加区。事务 ID 用来把响应和请求配对。普通查询走 UDP 53；响应超过 UDP 允许的长度被截断（TC 标志置 1）时，客户端改用 TCP 53 重查；区域传送（AXFR/IXFR）也走 TCP 53。EDNS0 允许更大的 UDP 载荷，所以“超过 512 字节一定用 TCP”是旧模型的简化说法。

\subsection{HTTP：一次请求到底发生了什么}

在地址栏输入 \texttt{http://www.example.com/index.html}，浏览器先做 DNS，再和服务器建立 TCP 连接，然后发一条 HTTP 请求，服务器返回响应。HTTP 只规定报文格式和交互规则，不规定浏览器怎么渲染页面，也不规定服务器用什么编程语言。

URL 的一般形式是 \texttt{scheme://host:port/path?query\#fragment}。HTTP 默认端口 80，HTTPS 默认 443，省略端口就用默认值；片段（fragment）只在浏览器内部使用，不会发给服务器。URL 里的非 ASCII 字符和保留字符要做百分号编码。

\subsubsection{请求报文和响应报文}

请求报文和响应报文都是四段：起始行、首部行、空行、实体主体。空行不能省；没有主体时，空行后面直接结束。请求行是“方法 + 请求目标 + 版本”，响应状态行是“版本 + 状态码 + 原因短语”。首部行是“字段名: 值”，字段名大小写不敏感。图里左边是一个请求，右边是一个响应，颜色区分了四段。

\subsubsection{非持久连接、持久连接与流水线}

HTTP/1.0 默认非持久连接：每个对象一条 TCP 连接，传完就关。HTTP/1.1 默认持久连接：一条 TCP 连接可以依次传多个对象，除非请求或响应里写了 \texttt{Connection: close}。持久连接省掉了反复建立和释放 TCP 连接的开销，是 HTTP/1.1 最重要的改进之一。

图里用三个时间轴对比三种方式。假设页面有 1 个基本 HTML 文件和 2 幅图像，忽略传输时间，每个小格是 1 RTT。非持久方式下每个对象都要“1 RTT 建连接 + 1 RTT 请求响应”，3 个对象共 6 RTT；持久非流水线方式只建一次连接，然后 HTML、图 1、图 2 依次各用 1 RTT，共 4 RTT；流水线方式在收到 HTML、知道图像 URL 后，一次性把两个图像请求都发出去，图像阶段只等 1 RTT，共 3 RTT。

把对象数推广一下。设页面共有 $M$ 个对象（1 个基本 HTML 加 $n$ 个内嵌对象，$M=n+1$），忽略传输时间：

\begin{itemize}
  \item 非持久、串行：每个对象 $2$ RTT，共 $2M=2(n+1)$ RTT。
  \item 持久、非流水线，且必须先取到 HTML 才知道对象 URL：建连接 $1$ RTT，取 HTML $1$ RTT，再逐个取 $n$ 个对象 $n$ RTT，共 $n+2$ RTT。
  \item 持久、流水线：建连接 $1$ RTT，取 HTML $1$ RTT，所有内嵌对象一起请求、一起响应 $1$ RTT，共 $3$ RTT（$n\ge 1$）。
  \item 如果客户端在建连接前就已经知道所有对象 URL，持久非流水线是 $1+M$ RTT，流水线是 $2$ RTT（建连接 $1$ RTT，所有请求-响应 $1$ RTT）。
\end{itemize}

这些式子都假设服务器按序响应、每个请求-响应恰好 $1$ RTT、传输时间可以忽略。题目如果给出并行连接数 $k$，对象阶段要按并行度分摊；如果给出带宽和对象大小，就把传输时间单独加在 RTT 之外。实际浏览器通常开多个并行连接，所以“非持久串行”是理论上的最坏情况。HTTP/2 在一条 TCP 连接上多路复用多个请求，HTTP/3 则改用基于 UDP 的 QUIC，但 408 的时间计算仍以 HTTP/1.1 的模型为主。

\subsubsection{Cookie 与 Web 缓存}

HTTP 本身是无状态协议：服务器处理完一个请求就忘了是谁来过。Cookie 是在应用层补上会话状态的机制。图里第一次访问时，服务器在响应里用 \texttt{Set-Cookie} 下发一个标识；浏览器把它存进 Cookie 文件；之后每次访问同一站点，浏览器自动在请求里用 \texttt{Cookie} 首部带回这个标识；服务器拿它去数据库里查用户状态。

Cookie 的常用属性有：\texttt{Expires} 或 \texttt{Max-Age} 控制过期时间，不设就是会话 Cookie，关浏览器即失效；\texttt{Domain} 和 \texttt{Path} 控制作用域；\texttt{Secure} 表示只在 HTTPS 下发送；\texttt{HttpOnly} 表示 JavaScript 读不到，能降低 XSS 窃取风险；\texttt{SameSite} 限制跨站请求是否携带 Cookie，用于缓解 CSRF。Cookie 不是认证协议本身，它只是携带标识，服务器仍要校验这个标识对应的会话是否有效。

Web 缓存（代理缓存）放在客户端和源服务器之间。缓存命中就直接返回；未命中就替客户端向源服务器取，再存一份。客户端可以用条件 GET 检查缓存是否还新鲜：请求里带 \texttt{If-Modified-Since} 或 \texttt{If-None-Match}，服务器判断没变就回 304，不传主体。\texttt{Cache-Control: max-age=...} 给出新鲜期，\texttt{no-store} 表示不允许缓存。HTTPS 就是 HTTP over TLS，默认端口 443；TLS 握手会增加 RTT，但 HTTP 报文本身的格式不变。

\subsection{FTP：两条连接分工}

用户用 FTP 登录服务器，先看到目录列表，再下载一个文件。目录列表和文件内容都走数据连接，登录、切换目录、请求文件的命令和应答走控制连接。FTP 的特别之处就在这里：它同时使用两条 TCP 连接，一条传命令，一条传数据，这种把控制信息带外（out-of-band）传送的方式，和 HTTP 把命令和数据放在同一条连接里的做法形成对比。

控制连接由客户端主动发起，连到服务器的 21 端口，在整个会话期间保持。数据连接每传一个文件或一份目录列表时单独建立，传完就关闭；下一次传输再建一条新的。控制连接上传的是 NVT ASCII 命令和三位数字应答：1xx 表示准备就绪，2xx 表示成功，3xx 表示需要更多信息，4xx 表示暂时失败，5xx 表示永久失败。

数据连接由谁发起，决定了 FTP 的两种模式。主动模式（PORT）下，客户端告诉服务器自己的 IP 和监听端口 $N$，服务器从默认的 20 端口主动连到 $N$。问题在于客户端常常在 NAT 或防火墙后面，外来的连接会被挡住。被动模式（PASV）下，客户端发 \texttt{PASV}，服务器返回一个临时端口 $M$，由客户端主动连到服务器的 $M$ 端口；所有连接都由客户端发起，防火墙友好，所以现代客户端默认用被动模式。

区分两种模式的关键是“数据连接由谁发起”，不是“用哪个端口”。主动模式下服务器用 20 端口作为源端口；被动模式下服务器用临时端口，客户端用临时端口。控制连接始终是客户端连服务器的 21 端口。

FTP 是有状态的：服务器记得当前登录用户、当前目录、传输类型。\texttt{TYPE A} 是文本模式，会做行尾转换；\texttt{TYPE I} 是二进制模式，不做转换。FTP 用明文传用户名、密码和文件，不安全；FTPS 是 FTP over TLS，给控制连接和数据连接加密；SFTP 是 SSH 的文件传输子系统，完全是另一套协议，默认走 22 端口，不是 FTP 的扩展。

\subsubsection{SMTP 的命令与应答}

SMTP 是命令/应答协议。一个会话大致是：服务器先回 220；客户端用 EHLO（或老式的 HELO）打招呼；用 MAIL FROM 给出信封发件人；用 RCPT TO 给出信封收件人，可以有多个；用 DATA 进入邮件内容，内容以单独一行句点结束；最后 QUIT。下面是一个简化会话，省略了扩展协商的多行应答。

\begin{lstlisting}
S: 220 mail.example.com ESMTP
C: EHLO client.example.com
S: 250 OK
C: MAIL FROM:<alice@example.com>
S: 250 OK
C: RCPT TO:<bob@example.net>
S: 250 OK
C: DATA
S: 354 End data with CRLF.CRLF
C: From: Alice <alice@example.com>
C: To: Bob <bob@example.net>
C: Subject: Hello
C:
C: This is the message body.
C: .
S: 250 OK
C: QUIT
S: 221 Bye
\end{lstlisting}

信封和首部是两回事。\texttt{MAIL FROM} 和 \texttt{RCPT TO} 是投递用的信封，决定邮件送到哪里、退信退给谁；\texttt{From:} 和 \texttt{To:} 是显示在邮件里的首部，可以和信封不同。密送（Bcc）只出现在 \texttt{RCPT TO} 里，不会写进首部。SMTP 允许在同一条 TCP 连接上连续发多封邮件，不必每封都重新建连接；扩展 SMTP 还支持流水线，把多个命令一次发出。

传统 SMTP 只传 7 位 ASCII，行尾是 CRLF，行长也有限制。二进制附件和中文不能直接塞进去，需要 MIME 扩展。MIME 不改 SMTP 的命令，只在邮件首部增加字段，把内容重新编码成 ASCII。

\subsubsection{MIME：让邮件装下二进制和中文}

MIME 主要增加三类首部。\texttt{MIME-Version: 1.0} 声明使用 MIME。\texttt{Content-Type} 说明内容的类型和参数，例如 \texttt{text/plain}、\texttt{image/png}、\texttt{multipart/mixed}。\texttt{Content-Transfer-}\allowbreak\texttt{Encoding} 说明内容如何编码成 ASCII，常见的是 \texttt{base64} 和 \texttt{quoted-printable}。图里是一封“正文 + 图片附件”的邮件结构。

{\scriptsize\color{MutedText}\parbox{0.92\linewidth}{\centering 图中三个阶段是顺序进行的：没有登录不能取信，没有 QUIT 不会真正删除。POP3 默认下载后删除，也可以配置保留副本，但它没有服务器端文件夹和多设备状态同步。}}
\end{center}

IMAP 则以服务器端邮箱为准：支持文件夹、邮件标志（已读、已删、已标记）、只取首部或部分内容、服务器端搜索、多客户端同步。POP3 适合单设备收信，IMAP 适合手机、平板、电脑同时看同一个邮箱。

\begin{tablebox}{POP3 与 IMAP 的分工}
\centering
\begin{tabularx}{\linewidth}{|p{0.22\linewidth}|X|X|}
\hline
 & \textbf{POP3} & \textbf{IMAP} \\
\hline
默认端口 & 110（明文），995（TLS） & 143（明文），993（TLS） \\
\hline
存储模型 & 下载到本地为主 & 邮件留在服务器，客户端缓存 \\
\hline
文件夹 & 协议本身不提供服务器端多文件夹 & 支持服务器端文件夹和层次结构 \\
\hline
多设备 & 状态难同步 & 标志和文件夹在服务器端同步 \\
\hline
典型命令 & USER、PASS、LIST、RETR、DELE & LOGIN、SELECT、FETCH、STORE、SEARCH \\
\hline
适用场景 & 单设备、离线阅读 & 多设备、在线协作 \\
\hline
\end{tabularx}
\end{tablebox}

网页邮箱是另一回事：浏览器和 Web 服务器之间用 HTTP，Web 服务器背后再用 SMTP、IMAP 和邮件系统交互。所以“网页邮箱用 HTTP 打开”不等于 SMTP 被 HTTP 取代，邮件服务器之间仍然说 SMTP。

\subsection{DHCP：主机怎样拿到地址}

一台新笔记本连上 Wi-Fi，没有 IP 地址，不能上网。它需要四样东西：自己的 IP 地址、子网掩码、默认网关、DNS 服务器地址。DHCP 自动把这些参数发给它，并且只租一段时间，这就是“动态主机配置”。

DHCP 用 UDP：客户端 68 端口，服务器 67 端口。客户端开口问的时候还没有 IP，所以源地址填 \texttt{0.0.0.0}，目的地址填受限广播地址 \texttt{255.255.255.255}。DHCP 是应用层协议，但它配置的是网络层参数；配置完成后，主机才能正常发 IP 数据报。

\subsubsection{四步交互：D-O-R-A}

DHCP 的典型四步是 DISCOVER、OFFER、REQUEST、ACK，简称 D-O-R-A。图里画了一个客户端和两台服务器：客户端广播发现，两台服务器都可能给 offer，客户端选一个并广播请求，被选中的服务器回 ACK。

\end{center}

各报文的含义如下。DHCP 服务器不一定对每个 DISCOVER 都回应，所以客户端可能收到零个、一个或多个 OFFER。

\begin{tablebox}{DHCP 报文}
\centering
\begin{tabularx}{\linewidth}{|c|X|}
\hline
\textbf{报文} & \textbf{作用} \\
\hline
DHCPDISCOVER & 客户端广播寻找可用的 DHCP 服务器 \\
DHCPOFFER & 服务器提供一个可用地址、租期和配置参数 \\
DHCPREQUEST & 客户端选择一个 OFFER，广播确认并通知其他服务器 \\
DHCPACK & 被选中的服务器确认分配，客户端开始使用 \\
DHCPNAK & 服务器拒绝请求，客户端需要重新 DISCOVER \\
DHCPDECLINE & 客户端发现地址冲突，拒绝使用该地址 \\
DHCPRELEASE & 客户端提前释放地址 \\
DHCPINFORM & 客户端已有地址，只请求其他配置参数 \\
\hline
\end{tabularx}
\end{tablebox}

如果 DHCP 服务器和客户端不在同一个广播域，广播到不了服务器，需要 DHCP 中继代理（relay agent）。中继通常由路由器担任：它把 DISCOVER 转发给服务器，并在 \texttt{giaddr} 字段里填上客户端所在子网的地址；服务器根据 \texttt{giaddr} 选择地址池，把 OFFER/ACK 发回中继，由中继转给客户端。没有中继，跨网段的客户端就拿不到地址。

\subsubsection{租约、续租与地址冲突}

DHCP 分配的地址有租期 $T$，不是永久的。图里画出了租约的时间轴：$T_1=0.5T$ 时客户端进入续租状态（RENEWING），单播 DHCPREQUEST 给原服务器；续租成功，租期重新计时。如果到 $T_2=0.875T$ 还没成功，客户端进入重绑定状态（REBINDING），广播 DHCPREQUEST 找任何一台服务器；成功就继续用，失败就等到 $T$ 到期。如果服务器回 DHCPNAK，客户端必须立即停止使用该地址，重新走 D-O-R-A。

    \draw[thick] (\x,0.12) -- (\x,-0.12);
    \node[below] at (\x,-0.15) {\lab};
  }
  \filldraw[fill=SoftTeal,draw=Teal!60] (0,0.35) rectangle (5,0.95); \node[font=\tiny] at (2.5,0.65) {BOUND};

DHCP 不保证地址一定唯一。客户端拿到地址后可以用免费 ARP（gratuitous ARP）探测一下，发现冲突就发 DHCPDECLINE 拒绝这个地址，重新申请。恶意 DHCP 服务器可以给客户端发错误的网关或 DNS，这叫 DHCP 欺骗；防范手段包括 DHCP snooping、端口安全和静态绑定。

DHCPv6 的思路相同，但用 UDP 546（客户端）和 547（服务器），报文名是 SOLICIT、ADVERTISE、REQUEST、REPLY，不走广播而是用组播地址 \texttt{ff02::1:2}。408 主要考 DHCPv4，知道这个区别即可。

\subsection{本章小结：把协议放到一条时间线上}

把本章的协议放在一起看，各自的角色很清楚：DNS 把名字解析成地址，DHCP 让主机拿到地址和网关，HTTP 取网页，FTP 传文件，SMTP 发邮件，POP3/IMAP 收邮件。它们使用的传输层和端口如下。

\begin{tablebox}{应用层协议速查}
\centering
\small
\begin{tabularx}{\linewidth}{|p{0.15\linewidth}|p{0.25\linewidth}|p{0.18\linewidth}|X|}
\hline
\textbf{协议} & \textbf{传输层 / 端口} & \textbf{谁发起} & \textbf{关键点} \\
\hline
DNS & UDP 53，TCP 53 备用 & 解析器 & 层次命名、递归/迭代、TTL 缓存 \\
HTTP & TCP 80 / 443 & 客户端 & 无状态、持久连接、Cookie、缓存 \\
FTP & TCP 21 控制；20 或临时端口数据 & 客户端控制；数据看模式 & 双连接、带外控制、主动/被动 \\
SMTP & TCP 25 / 587 & 发送方 & 推邮件、命令应答、7 位 ASCII + MIME \\
POP3 & TCP 110 / 995 & 接收方 & 拉邮件、三阶段、下载后删除 \\
IMAP & TCP 143 / 993 & 接收方 & 服务器端邮箱、多设备同步 \\
DHCP & UDP 67 / 68 & 客户端广播 & D-O-R-A、租约、中继 \\
\hline
\end{tabularx}
\end{tablebox}

一台主机刚接入网络时，顺序大致是：先用 DHCP 拿到 IP、掩码、网关和 DNS；访问 \texttt{www.example.com} 时，先用 DNS 解析出 IP；如果目的地址不在本网段，主机用 ARP 找到默认网关的 MAC 地址（ARP 属于网络层/链路层，不是应用层）；然后 TCP 三次握手，最后发 HTTP 请求。DNS 和 DHCP 用 UDP，HTTP 用 TCP；FTP、SMTP、POP3/IMAP 各自在自己的连接上工作，互不替代。

\noindent\textbf{延伸阅读：} Kurose \& Ross《计算机网络：自顶向下方法》第 2 章有 DNS、HTTP、FTP、SMTP/POP3 的抓包示例；谢希仁《计算机网络》第 6 章使用国内常见术语，可对照阅读。
