\section{输入输出系统}

先看一个具体场景：程序要从磁盘读 4 KB 数据到内存。CPU 把起始地址和字节数写进磁盘控制器的寄存器，磁盘开始寻道、旋转；数据到达控制器后，DMA 把数据写进主存；整块传完，控制器向 CPU 发一个中断。短短一条读命令背后，既有接口里的端口寄存器，也有总线的争夺和中断现场的保存。本章就按“设备怎样接入—CPU 怎样等—设备怎样通知—数据怎样搬运—磁盘为什么慢”的顺序展开。

\subsection{从一根导线开始：I/O 接口做什么}

键盘按下一次键，产生的是一个或几个电脉冲；CPU 的总线却是并行、电平固定、时序严格的。两者不能直接连在一起。中间那块电路就是 \textbf{I/O 接口}（I/O interface），也叫 I/O 控制器。它的职责可以分成几类：把外设送来的数据锁存住，等 CPU 来取；把 CPU 写来的数据保持住，等外设慢慢消费；把串行信号转成并行、把非 TTL 电平转成 TTL 电平、把模拟量转成数字量；接收 CPU 的读/写命令，向设备发出启动、停止等控制信号；把设备的忙、闲、出错等状态登记下来供 CPU 查询；设备需要服务时，向 CPU 发出中断请求。

图里 CPU 一侧只有地址、数据、控制三组总线。地址送到译码器，译码器判断这次访问的是不是本接口、以及是接口里的哪一个寄存器；数据端口负责搬数据，状态端口只读，控制端口只写。设备一侧的时序可能和 CPU 完全不同，接口负责把两边的节奏对上。图中把数据、状态、控制画成三条独立的线，实际接口可能把它们复用在更少的引脚上，但“CPU 通过端口访问接口”这一点不变。

能被 CPU 用指令直接访问的寄存器叫 \textbf{I/O 端口}（I/O port）。一个接口通常有多个端口：数据端口、状态端口、控制端口，每个端口有自己的端口地址。接口是电路实体，端口是实体里“能被寻址的格子”。408 选择题常拿“一个接口就是一个端口”做干扰项，实际上一个接口往往包含三个以上的端口。

端口地址怎么放进地址空间，有两种做法。第一种是\textbf{统一编址}，也叫存储器映射 I/O：把端口地址安排在主存地址空间里，CPU 用普通的取数、存数指令访问端口，不需要专门的 I/O 指令。ARM、MIPS、RISC-V 通常采用这种方式。它的好处是指令多、寻址方式多，指针、数组、结构体都能直接指向端口；代价是端口占掉了一部分地址空间，可编址的主存范围相应减少。第二种是\textbf{独立编址}，也叫 I/O 映射 I/O：主存和端口各有一套地址空间，CPU 用专门的 I/O 指令（x86 的 \texttt{IN}、\texttt{OUT}）访问端口，用访存指令访问主存，并通过 \texttt{MEMR/MEMW} 与 \texttt{IOR/IOW} 等控制信号区分。它的好处是不占主存地址空间、端口地址位数少、译码简单；代价是需要专门的指令和引脚。

\subsection{程序查询：CPU 守着设备}

最简单的一种 I/O 控制方式是程序查询。以打印机输出一个字符为例：接口里有一个“忙”位，CPU 先反复读状态端口；忙就继续读，直到状态变成“就绪”，再把字符写到数据端口。

图里的循环就是程序查询的全部工作：读状态、判断、传送、再判断。设备慢的时候，CPU 大部分时间耗在“读状态—判断”这两步上，真正传送数据只是一瞬间。它不需要中断控制器，也不需要 DMA 控制器，硬件最省；代价是 CPU 和外设串行工作，CPU 的算力被白白占住。它适合单片机控制按键、LED 这类简单场合，或者设备速度本来就和 CPU 匹配的专用系统。

有些实现会在查询循环里插入其他任务，隔一段时间查一次，这叫定时查询；但它仍然是 CPU 主动去问设备，设备不能反过来通知 CPU。只要设备没有“主动敲门”的能力，CPU 就必须在某个时刻停下来检查。

\subsection{中断：让设备主动找 CPU}

程序查询的问题在于 CPU 必须守着设备。中断换了一个方向：设备准备好时，向 CPU 发一个中断请求；CPU 在完成当前指令后，暂停主程序，转去执行该设备的中断服务程序（ISR），处理完再返回。设备准备数据的那段时间，CPU 可以继续执行别的程序，因此 CPU 与外设是部分并行的。

中断源不只有 I/O 设备。时钟、电源故障、存储器校验错也会发中断；除零、溢出、缺页、非法指令、系统调用则来自 CPU 内部。408 通常把前者叫\textbf{中断}（外中断），后者叫\textbf{异常}（内中断）。外中断是异步的，和当前指令没有关系；异常是同步的，由当前指令触发。外中断里，可以被 \texttt{IF} 标志屏蔽的称为可屏蔽中断，键盘、磁盘等通常走这一类；电源故障、存储器校验错等用不可屏蔽中断（NMI），不受 \texttt{IF} 限制。

按 CPU 获得服务程序入口的方式，还可分为向量中断和非向量中断。向量中断由中断控制器在响应周期给出中断类型号，CPU 据此查表；非向量中断则由软件轮流查询各个设备，确定是谁发的请求。408 主要考向量中断。

\subsubsection{中断响应：CPU 在什么时候、做什么}

CPU 不是一看到请求就立刻停下来。对可屏蔽中断，通常要同时满足几个条件：中断源有请求且未被屏蔽；CPU 处于开中断状态（\texttt{IF}=1）；当前指令已经执行完；没有复位等更紧急的事件。为什么不在指令中间响应？因为响应中断要保存一个能正确恢复的断点，指令中间的状态（比如写回还没完成、流水线里还有未提交的指令）很难用一个 PC 值表示。异常则不同，它由当前指令的执行结果触发，CPU 会在指令执行过程中或结束时按异常类型处理。

响应时，CPU 硬件会自动做一串操作，这段过程常称为\textbf{中断响应周期}；这串操作不是程序里的某条指令，所以又被称为\textbf{中断隐指令}：

\begin{enumerate}
  \item \textbf{关中断}。对可屏蔽中断，硬件清 \texttt{IF}，防止响应过程本身又被另一个中断打断。
  \item \textbf{保存断点}。把当前程序的 PC（指向下一条要执行的指令）压入堆栈；很多机器连同 PSW/FLAGS 一起保存。x86 在响应中断时依次压入 FLAGS、CS、IP，返回时再由 \texttt{IRET} 弹出。
  \item \textbf{识别中断源}。有多个设备同时请求时，中断控制器按优先级选出最高的一个，在中断响应周期把它的中断类型号送给 CPU。
  \item \textbf{查中断向量表}。以类型号为索引，从向量表中取出服务程序入口地址，装入 PC（以及代码段寄存器），CPU 随即转到 ISR。
\end{enumerate}

进入 ISR 之后，还有两件事由软件完成：开头用 \texttt{PUSH} 保存本程序要用的通用寄存器，这叫\textbf{保护现场}；结尾用 \texttt{POP} 恢复，再执行 \texttt{IRET} 返回。保护现场是 ISR 的责任，不是硬件的责任。硬件保存的是“断点”，软件保存的是“现场”，两者层次不同，考试里经常被混在一起。

\subsubsection{中断向量表：类型号到入口地址}

中断类型号只是一个编号，真正要跳到哪里由中断向量表给出。表可以放在内存的固定区域，每个表项存放对应 ISR 的入口地址（或入口地址信息）。x86 的中断类型号是 8 位，实模式表最多 256 项；表固定在低地址 \texttt{0}～\texttt{0x3FF}，每个表项 4 字节，前 2 字节是 IP、后 2 字节是 CS。32 位保护模式下用的是中断描述符表 IDT，每个表项 8 字节，里面是门描述符，包含段选择子和偏移，不是直接的一个线性地址；64 位模式下每个表项为 16 字节。

图里类型号 $n$ 只是查表的索引，表项里放的是入口地址或入口地址信息。若表项长度为 $L$，第 $n$ 项的首地址就是 $\text{基址}+nL$；实模式 $L=4$，32 位保护模式 IDT 的 $L=8$，64 位模式为 $16$。408 计算题常把 $L$ 直接写出来，按这个式子算即可。表本身由操作系统在启动时初始化，硬件只负责按类型号去查。

\subsubsection{多重中断：谁能打断谁}

如果 ISR 一直关着中断，高优先级的设备也只能等当前 ISR 做完。要支持多重中断（中断嵌套），需要两个条件：一是 ISR 在保护现场之后重新开中断；二是中断系统有优先级裁决，只有优先级更高的请求才能打断当前 ISR。优先级可以用硬件排队电路实现，也可以用中断控制器里的屏蔽寄存器设置；同级或更低级的请求只能挂起，等当前 ISR 返回后再处理。

为什么一定要先保护现场再开中断？假设 ISR 还没有保存寄存器就开了中断，嵌套进来的 ISR 可能改写同一组寄存器；等嵌套返回时，外层 ISR 原来的值已经丢了，恢复现场就会把错误的值写回主程序。堆栈在这里起关键作用：每进入一层中断，断点和现场依次压栈；返回时按后进先出弹出，所以嵌套层次越深，栈越深。

\subsection{DMA：把搬数据交给硬件}

中断方式虽然让 CPU 不用守着设备，但每传送一个字/字节，CPU 仍要进一次 ISR，执行保护现场、取数、存数、恢复现场这一串指令。磁盘不是按字节慢慢来的：一块 4 KB 的数据可能在很短的时间内连续到达。如果按 4 B 一次中断，4 KB 就是 1024 次中断；每次哪怕只花 100 个时钟周期，也要十万多个周期。DMA 的思路是把“逐字搬运”从 CPU 的指令流里拿掉，交给专门的 DMA 控制器（DMAC）。

DMAC 里通常有三组关键寄存器：地址寄存器 AR 存放当前要访问的主存地址；字计数器 WC 存放还剩多少个字/字节要传；数据缓冲寄存器 DR 暂存一次传送的数据。此外还有控制/状态逻辑，用来接收 CPU 的命令、产生总线请求、在结束时发中断。设备侧用 DREQ（DMA 请求）和 DACK（DMA 应答）握手；系统侧用 HOLD（或 BR）向 CPU 申请总线，CPU 用 HLDA（或 BG）表示可以让出。

DMA 传送分三段。第一段是\textbf{预处理}，由 CPU 完成：把主存起始地址写入 AR，把传送字数写入 WC，设置方向，然后启动设备；之后 CPU 就可以去执行别的程序。第二段是\textbf{数据传送}，由 DMAC 完成：设备准备好一个数据，发 DREQ；DMAC 向 CPU 发 HOLD；CPU 在当前总线周期结束后让出总线，回 HLDA；DMAC 回 DACK，把 AR 送上地址总线，完成一次读/写；然后 AR 加 1（或减 1），WC 减 1。若 WC 不为 0，继续下一个数据；若 WC 为 0，进入第三段。第三段是\textbf{后处理}，DMAC 向 CPU 发中断，CPU 执行 ISR 检查状态、处理错误、决定是否启动下一块。

图里上排是 CPU 在做什么，中排是谁占着总线，下排是 DMAC 的动作。预处理和后处理由 CPU 执行指令完成；中间一长段数据传送，CPU 不执行搬运指令，但总线被 DMAC 按字逐个占用。注意边界：DMA 的总线请求（HOLD/BR）是在\textbf{总线周期}边界被采样并让出总线的，不必等一条指令执行完；可屏蔽中断才是在\textbf{指令周期}边界响应。这个粒度差别是 408 选择题的常见考点。

DMAC 与 CPU 争用总线有三种典型策略。\textbf{停止 CPU 访存}（成组传送）是 DMAC 一旦获得总线就一直占着，直到整块数据传完才释放；传送期间 CPU 不能访存，若当前指令和数据都在 Cache 中命中、且不需要写主存，还可以继续执行，一旦需要访存就被挡住。\textbf{周期挪用}（也叫周期窃取）是每传一个字（或几个字）申请一次总线，传完立即释放；CPU 的访存可能被推迟一个或几个周期，但在两次挪用之间仍可访存。\textbf{交替访存}把总线时间切成固定时隙，CPU 和 DMAC 轮流使用，不需要每次申请/释放，但两边都只能拿到一部分带宽。

周期挪用容易被误解成“只用 CPU 空闲的总线周期”。它不是：即使 CPU 正在使用总线，DMAC 也可以在当前总线周期结束后把下一个周期“借”走，CPU 的访存因此被推迟。它之所以叫“挪用”，正是因为它会打断 CPU 的正常访存节奏，只是每次只借一点点。

比 DMA 更进一步的方案是\textbf{通道}（channel），也叫 I/O 处理器（IOP）。通道有自己的指令系统，能执行存放在主存里的通道程序，一组通道命令字（CCW）可以描述“从哪个设备读、读到哪、传多少、下一步做什么”。CPU 只需发一条启动 I/O 的命令，通道就能独立完成一批数据块的传送，结束时再中断 CPU。DMA 只是一个硬件控制器，通道则是一个能执行程序的处理器；选择通道一次服务一个高速设备，数组多路通道可以交错服务多个高速设备，字节多路通道则轮流为多个低速设备服务。

\subsection{磁盘：机械运动的代价}

磁盘和内存最大的不同是它有机械运动。若干盘片叠在同一根主轴上，每个盘面有一个磁头，所有磁头装在同一组臂上一起径向移动。盘面被分成许多同心圆，叫\textbf{磁道}；每条磁道又分成若干\textbf{扇区}；不同盘面上半径相同的磁道组成一个\textbf{柱面}。读写的最小单位是扇区，常见 512 B 或 4 KB。

图左边是盘面俯视：磁头沿半径方向移动，改变它所在的磁道，这就是寻道；盘片旋转，把目标扇区带到磁头下面。图右边是侧视：几片盘片共用主轴，所有磁头固定在同一个臂组上，所以它们同时位于同一柱面。切换磁头只需要电子选择，不需要机械移动；因此磁盘地址通常按“柱面号—磁头号—扇区号”排列，先把同一柱面的所有磁道用完，再移动到下一个柱面，减少寻道次数。

磁盘容量可以按几何参数算：
\[
\text{容量}=\text{盘面数}\times\text{柱面数}\times\text{每道扇区数}\times\text{每扇区字节数}.
\]
柱面数就是每个盘面的磁道数。408 题通常假设每条磁道的扇区数相同；真实磁盘常用区域记录（ZBR），外圈磁道扇区更多，但考试一般不涉及。

读一个扇区要等三件事：把磁头移到目标磁道，叫\textbf{寻道时间}；等目标扇区转到磁头下面，叫\textbf{旋转延迟}；把扇区内容读出来，叫\textbf{传输时间}。总存取时间是三者之和：
\begin{formula}{磁盘存取时间与传输率}{disk-access}
\[
T_{\text{access}}=T_{\text{seek}}+T_{\text{rot}}/2+T_{\text{transfer}},
\qquad T_{\text{rot}}=\frac{60}{r},
\qquad T_{\text{transfer}}=\frac{k}{S}T_{\text{rot}}.
\]
其中 $r$ 是转速（$\mathrm{r/min}$），$S$ 是每道扇区数，$k$ 是本次连续读取的扇区数，$T_{\text{rot}}$ 是转一圈的时间。持续传输率为
\[
R=S\cdot B\cdot\frac{r}{60},
\]
$B$ 是每扇区字节数。
\end{formula}

平均旋转延迟取半圈，前提是目标扇区在圆周上的位置随机，平均要等半圈；最大旋转延迟是一整圈。传输时间按“本次读的扇区数占整道扇区数的比例”乘一圈时间，不是按数据总线宽度算。若连续读同一磁道的 $k$ 个扇区，寻道和旋转延迟只付一次；若跨磁道，还要加上新的寻道和旋转。平均寻道时间与请求分布、初始磁头位置和调度算法都有关，题目通常直接给出；不要把它当成最大寻道时间的一半。

举个数值例子。某磁盘转速 $5400\ \mathrm{r/min}$，平均寻道时间 $10\ \mathrm{ms}$，每道 200 个扇区，每扇区 512 B。转一圈的时间是
\[
T_{\text{rot}}=\frac{60}{5400}\ \mathrm{s}=11.11\ \mathrm{ms},
\]
平均旋转延迟是 $5.56\ \mathrm{ms}$。读一个扇区的传输时间是
\[
T_{\text{transfer}}=\frac{1}{200}\times 11.11\ \mathrm{ms}=0.0556\ \mathrm{ms},
\]
所以平均存取时间约为 $10+5.56+0.056=15.61\ \mathrm{ms}$。持续传输率为
\[
R=200\times 512\times\frac{5400}{60}
=9.216\times10^{6}\ \mathrm{B/s}=9.216\ \mathrm{MB/s}.
\]
如果一次读完整条磁道（200 个扇区），传输时间变成 $11.11\ \mathrm{ms}$，寻道和旋转仍只付一次；单扇区读时传输只占很小一部分，这就是大块 I/O 能摊薄机械开销的原因。

当多个 I/O 请求排队时，先服务谁会影响总寻道距离。\textbf{FCFS} 按到达顺序服务，公平但磁头可能来回跑；\textbf{SSTF} 每次选离当前磁头最近的请求，寻道距离短，但远处的请求可能长期得不到服务；\textbf{SCAN} 像电梯，先沿一个方向服务沿途请求，到端点再反向；\textbf{C-SCAN} 只在一个方向服务，回程直接回到起点，等待时间更均匀；\textbf{LOOK} 是 SCAN 的变体，到了最远的请求就反向，不必走到盘边。

固态硬盘（SSD）没有磁头和盘片，随机读不需要寻道和旋转，延迟主要来自闪存读、地址映射（FTL）、垃圾回收和写放大。它以页为单位读写、以块为单位擦除，随机写比随机读更贵。408 里要区分：磁盘是直接存取，访问时间与位置有关；SSD 是随机存取，但仍有读写粒度和擦除块的限制。

\small

\hline

从查询到中断，变化的是“谁主动”：CPU 不用守着设备，设备可以发请求。从中断到 DMA，变化的是“谁搬数据”：CPU 不再逐字执行传送指令，DMAC 直接在主存和设备之间搬。从 DMA 到通道，变化的是“谁执行 I/O 程序”：DMAC 只会按固定参数搬一块，通道能执行通道程序、串联多个操作、管理多台设备。四者的硬件复杂度和 CPU 开销依次变化，适用场景也不同。

\begin{attention}
本章最容易混淆的几处：
\begin{itemize}
  \item 中断向量是服务程序的入口地址，不是中断类型号；类型号只是查表的索引。
  \item 保护断点（PC、PSW）由硬件在响应时完成；保护现场（通用寄存器）由 ISR 用 \texttt{PUSH} 完成。
  \item DMA 数据不经过 CPU 通用寄存器，但可以经过 DMAC 的数据缓冲；不要理解成“绝对不经过任何缓冲”。
  \item DMA 请求在总线周期边界被采样，可屏蔽中断在指令边界被响应；两者粒度不同。
  \item 周期挪用是“借一个或几个总线周期”，不是“只用总线空闲周期”；CPU 的访存可能被推迟。
  \item 统一编址不是“端口没有地址”，而是端口和主存共用地址空间；独立编址下地址数值相同也不会冲突。
  \item 平均旋转延迟是半圈；一个扇区的传输时间是整圈时间除以每道扇区数，不是按数据总线宽度算。
  \item \texttt{IRET} 恢复中断前的 \texttt{IF}，不是无条件开中断；中断前 \texttt{IF}=0 时，返回后仍为 0。
\end{itemize}
\end{attention}
