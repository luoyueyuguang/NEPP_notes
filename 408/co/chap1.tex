\section{计算机系统概述}

先看一行 C 代码：\texttt{c = a + b;}。编译器把它变成几条机器指令，处理器从存储器中取出这些指令，译码，从寄存器或主存取操作数，做一次加法，再把结果写回。整个过程只涉及三样东西：指令、数据，以及存放它们的存储单元。本章要回答的是，这三样东西怎样被组织成一台机器，以及这种组织方式怎样决定程序跑多快。

\subsection{一条指令在机器里走一遍}

1946 年公布的 ENIAC 是第一台通用电子数字计算机，但它没有“存储程序”：计算步骤靠插线和开关设定，换一道题往往要重新接线。1945 年，冯·诺依曼在为 EDVAC 写的报告中提出了另一条路：把指令也当作数据存进存储器，机器按地址逐条取指、译码、执行。EDVAC 到 1951 年才投入运行，而 EDSAC 在 1949 年就已经跑起了存储程序；此后，“存储程序”成为通用计算机的基本模型。

\begin{mydef}{冯·诺依曼结构}{von-neumann}
冯·诺依曼结构的基本特征是：
\begin{enumerate}
    \item 指令和数据都以二进制表示，存放在同一个存储器中，按地址访问；
    \item 指令由操作码和地址码组成，指令序列由程序计数器（PC）引导，逐条取出执行；
    \item 计算机由运算器、控制器、存储器、输入设备和输出设备五大部分组成；
    \item 原始方案以运算器为中心，输入/输出设备与存储器之间的数据传送也要经过运算器。
\end{enumerate}
\end{mydef}

这里最容易被误解的是“同一个存储器”。它指的是逻辑上统一编址、按地址访问的存储空间，不是说物理上只能有一个存储体。现代处理器把指令 Cache 和数据 Cache 分开，操作系统用虚拟存储把主存和磁盘连成一个地址空间，程序员看到的仍然是一个可以按地址访问的存储空间，所以这些优化并不推翻存储程序模型。

把机箱打开，五大部分的分工可以这样看。运算器负责算术和逻辑运算，核心是 ALU、累加器 ACC、乘商寄存器 MQ 和通用寄存器；控制器负责指挥，核心是 PC、指令寄存器 IR、指令译码器 ID 和时序/控制信号发生器；存储器存放程序和数据，核心是存储体、地址译码器和读写电路，CPU 通过 MAR 送地址、通过 MDR 收/发数据；输入设备把外界信息送进来，输出设备把结果送出去。运算器和控制器合称 CPU，CPU 与主存合称主机，外存和 I/O 设备属于外设。

图里标的是一条加法指令要走的路径。取指阶段，PC 把地址送到 MAR，经地址总线选中主存单元；主存读出内容，经数据总线送到 MDR，再送入 IR；控制器让 PC 指向下一条指令（指令长度可变时加上指令长度）。译码阶段，ID 分析 IR 中的操作码，产生控制信号。执行阶段，如果操作数在存储器中，IR 的地址码再走一次 MAR、主存、MDR，把操作数送到 X 或 ACC；ALU 完成运算，结果写回 ACC 或主存。图中的地址总线是单向的，数据总线是双向的，控制总线传递读/写、中断等信号；实际机器为了并行，往往给指令和数据配不同的总线或 Cache。

\begin{attention}
地址总线的位数决定 CPU 能直接编址多少个单元。$n$ 位地址总线最多选择 $2^n$ 个编址单元；若按字节编址，主存最大容量就是 $2^n$ 字节。数据总线的宽度决定一次能并行传送多少位，64 位数据总线一次传 8 字节。MAR 的位数与地址总线位数一致，MDR 的位数通常与存储字长一致。
\end{attention}

和原始方案相比，现代计算机改成了“以存储器为中心”：CPU 通过系统总线和存储器直接通信，I/O 设备通过 I/O 接口挂到总线上，DMA 方式下数据可以在存储器和 I/O 设备之间直接传送，不必经过运算器。但 CPU 和存储器之间的通路仍然是瓶颈，这就是常说的“冯·诺依曼瓶颈”。后来的 Cache、多级存储层次和更宽的内存总线，很大程度上都是在缓解这条通路的速度差。它说的是带宽限制，不是“内存容量不够”。

从所用器件看，计算机大致经历了电子管、晶体管、中小规模集成电路、大规模与超大规模集成电路四个阶段。1965 年，摩尔（Gordon Moore）提出，集成电路上可经济集成的晶体管数大约每 18--24 个月翻一番，这条经验规律后来被称为摩尔定律（Moore's law）；它支撑了主频和存储容量的长期增长，但近年已经放缓，单核主频不再快速上升，性能提升更多依靠多核、向量指令和专用加速器。摩尔定律描述的是集成度趋势，不等于处理器性能自动按同一比例增长。

\subsection{硬件之上：软件与层次结构}

硬件只认识二进制机器指令。要让“$c=a+b$”这样的表达式跑起来，还需要软件把高层写法逐层落到机器指令上。操作系统、编译程序、汇编程序、链接程序、数据库管理系统、设备驱动，这些都属于系统软件：它们要么管理硬件资源，要么为其他程序提供运行环境。浏览器、办公软件、游戏属于应用软件。两者的边界不是绝对的，数据库系统既可以被看作系统软件，也可以被看作应用支撑平台；408 通常把它归入系统软件。

程序设计语言大致分三级。机器语言就是二进制指令，硬件能直接执行；汇编语言用助记符代替操作码和地址码，再由汇编程序翻译成机器语言；高级语言用接近自然语言和数学表达式的写法，由编译程序翻译，或者由解释程序逐条解释执行。编译和解释的差别不在“谁更高级”，而在翻译和执行的先后关系。

这里要区分两个“层次”概念。一个是上面这种按翻译关系划分的机器层次；另一个是计算机组成里的“体系结构（ISA）与微架构”。指令格式、寻址方式、寄存器个数、数据类型这些对程序员可见的部分属于 ISA；流水线级数、Cache 容量、分支预测器、总线宽度属于微架构，对程序员透明。同一套 ISA 可以有完全不同的微架构，例如同样执行 x86 指令的处理器，流水线深度和 Cache 大小可能差很多。408 选择题常问“哪一项对程序员透明”，Cache 容量和流水线级数通常是透明的那一类，而寄存器个数、指令格式不是。

\subsection{性能：指令、周期与时间}

衡量性能有两个不同的问题：完成一个任务要多久，以及单位时间能完成多少任务。前者叫响应时间或执行时间，后者叫吞吐率。一台机器可能通过流水线让吞吐率很高，但单个任务从开始到结束的延迟并不短；反过来，降低延迟的措施通常也会改善吞吐率。408 题目里说“性能”，默认比较的是同一程序的执行时间。

CPU 执行时间只统计 CPU 真正花在程序上的时间，不包括等待 I/O 的时间；墙钟时间（elapsed time）则把 I/O 等待、操作系统调度都算进去。题目说“忽略 I/O”时，用 CPU 执行时间即可。把 CPU 执行时间拆开，就得到本章最重要的公式：
\begin{formula}{CPU 执行时间}{cpu-time}
\[
T_{\text{CPU}}=\frac{N\times \mathrm{CPI}}{f}=N\times \mathrm{CPI}\times T_{\text{clk}},
\qquad T_{\text{clk}}=\frac{1}{f}.
\]
其中 $N$ 是程序执行的机器指令条数，$\mathrm{CPI}$ 是平均每条指令占用的时钟周期数，$f$ 是主频，$T_{\text{clk}}$ 是时钟周期。
\end{formula}

$N$ 不是源程序的行数，也不是编译器生成的汇编语句数，而是真正被执行的机器指令条数；循环会把它放大，分支会改变它。CPI 也不是指令系统的固定常数，而是这个程序在这台机器上的平均值。三个因子分别对应三类优化：更好的算法和编译器减少 $N$，更好的微架构降低 CPI，更好的工艺和电路提高 $f$。三者不是独立的，提高主频往往要加长流水线或提高电压，可能反过来增加 CPI。

图把一次性能计算拆成两步单位换算：先把“多少条指令”乘上“每条多少周期”，得到总周期数；再乘上“每周期多少秒”，得到时间。以 $N=2.0\times10^{9}$、$\mathrm{CPI}=1.5$、$f=2.0\,\mathrm{GHz}$ 为例，总周期数是 $3.0\times10^{9}$，时钟周期是 $0.5\,\mathrm{ns}$，执行时间就是 $1.5\,\mathrm{s}$。如果只把主频提高一倍而 CPI 也翻倍，执行时间不会变；这就是不能只看主频的原因。

当程序里有多类指令时，平均 CPI 要按指令条数加权，而不是把各类 CPI 做算术平均。设第 $i$ 类指令占全部指令的比例为 $p_i$，CPI 为 $\mathrm{CPI}_i$，则
\[
\mathrm{CPI}_{\text{avg}}=\sum_{i=1}^{k}p_i\,\mathrm{CPI}_i,
\qquad \sum_{i=1}^{k}p_i=1.
\]
等价地，先算总周期数 $\sum_i N_i\,\mathrm{CPI}_i$，再除以总条数 $\sum_i N_i$。两种写法结果相同，题目给“占比”就用前者，给“条数”就用后者。

图中每一段的宽度是 $p_i\times\mathrm{CPI}_i$，也就是这类指令平均给“每条指令”贡献了多少个周期。四段首尾相接，总长度 $0.5+0.8+0.6+0.2=2.1$ 就是平均 CPI。取数/存数类指令只占 $20\%$，但 CPI 高，贡献了 $0.8$ 个周期，是四类里最大的一段；这说明优化时不能只盯着出现次数最多的指令。

知道执行时间和指令条数，就能算指令速率：
\[
\mathrm{MIPS}=\frac{N}{T_{\text{CPU}}\times10^{6}}
=\frac{f}{\mathrm{CPI}\times10^{6}}.
\]
这里 $f$ 用 Hz，分母的 $10^{6}$ 是把“条/秒”换成“百万条/秒”。如果主频用 MHz 表示，则 $\mathrm{MIPS}=f_{\text{MHz}}/\mathrm{CPI}$，不再乘 $10^{6}$。浮点性能用 MFLOPS 表示，定义是每秒执行的百万次浮点运算；GFLOPS、TFLOPS 分别是 $10^{3}$、$10^{6}$ 个 MFLOPS。

MIPS 有一个著名的陷阱：它把不同指令当成等价的工作量。RISC 机器的指令简单，完成同一任务往往需要更多指令，MIPS 可能更高，但程序不一定更快；CISC 机器一条指令做更多事，MIPS 可能更低，实际完成的任务却更多。所以 MIPS 只能在同一指令系统、同一程序的条件下比较，不能跨机器直接比。MFLOPS 也只适合浮点密集型程序，拿它衡量整数或 I/O 密集型负载同样会失真。

实际评测用基准程序（benchmark）。SPEC CPU 让机器运行一组有代表性的程序，把每台机器的执行时间与参考机相比得到一个比值，最后用几何平均汇总。用几何平均而不是算术平均，是因为这些量是比值，几何平均不会被某一个特别快或特别慢的程序过度拉偏。基准程序也有局限：编译器可以针对它做特殊优化，测出来的分数不一定代表真实负载。

\subsection{Amdahl 定律：一部分加速能换来多少}

假设一个程序原来的执行时间是 $T_0$，其中比例为 $\alpha$ 的部分可以加速 $k$ 倍，其余部分完全不能加速。改进后的时间是
\[
T'=(1-\alpha)T_0+\frac{\alpha T_0}{k}
=T_0\left[(1-\alpha)+\frac{\alpha}{k}\right].
\]
整体加速比是
\[
S=\frac{T_0}{T'}=\frac{1}{(1-\alpha)+\alpha/k}.
\]
当 $k\to\infty$ 时，$\alpha/k\to0$，加速比的上限是
\[
S_{\max}=\frac{1}{1-\alpha}.
\]
这个上限只由不能加速的部分决定，和可加速部分能提多快无关。

举个具体的例子：程序原来跑 $100\,\mathrm{s}$，其中 $80\,\mathrm{s}$ 可以加速，$\alpha=0.8$。把这部分提速 $4$ 倍，改进后是 $20+80/4=40\,\mathrm{s}$，加速比 $2.5$；即使把这部分提速 $100$ 倍，时间也只降到 $20.8\,\mathrm{s}$，加速比约 $4.8$，离上限 $5$ 很近。剩下的 $20\,\mathrm{s}$ 才是真正的瓶颈。

用 Amdahl 定律时，$\alpha$ 是“原执行时间中可加速部分的比例”，不是指令条数的比例，也不是代码行数的比例。如果题目给出的是各部分原来的时间，先算它们占总时间的比例，再代入。若同时改进多个部分，设第 $i$ 部分原时间占比为 $\alpha_i$、加速倍数为 $k_i$，则
\[
\frac{T'}{T_0}=\left(1-\sum_i\alpha_i\right)+\sum_i\frac{\alpha_i}{k_i}.
\]
Amdahl 定律假设问题规模固定。如果问题规模随着处理器数量一起变大（例如更大的矩阵、更多的数据），加速比可以接近线性增长，这时用的是 Gustafson 的观点；408 题目通常采用固定问题规模的版本。

\subsection{存储层次：快、大、便宜不能同时要}

遍历一个 $10000\times10000$ 的整型二维数组，按行访问和按列访问的指令条数差不多，耗时却可能差好几倍。原因不在 CPU 算得慢，而在数据所在的位置：按行访问时，相邻元素在内存中连续，第一次缺失会把一整块数据搬进 Cache，后续访问大多命中；按列访问时，每次跨过一整行，搬进来的块用不上，几乎每次都要访问主存。存储层次要解决的就是这个速度差。

程序访问有两个稳定的规律。时间局部性：刚被访问过的单元，很可能很快再被访问，比如循环变量、栈顶、反复调用的函数。空间局部性：一个单元被访问后，它附近的单元很可能接着被访问，比如数组的相邻元素、顺序执行的指令。存储层次把最近用过的和附近的数据放在快而小的层，把久不用的数据放在慢而大的层，用局部性把“平均访问时间”拉近到快的那一层。

设上层命中率为 $h$，命中时间为 $T_{\text{hit}}$，未命中时额外付出的时间为 $T_{\text{miss}}$，则平均访问时间
\[
T_{\text{avg}}=T_{\text{hit}}+(1-h)T_{\text{miss}}.
\]
如果题目给的是“下层完整访问时间”$T_{\text{lower}}$，则写成
\[
T_{\text{avg}}=h\,T_{\text{hit}}+(1-h)T_{\text{lower}}.
\]
两种写法只差 $T_{\text{miss}}$ 的定义：前者把 $T_{\text{miss}}$ 看作“缺失代价”，即比命中多花的时间；后者把下层访问时间整个算进去。做题时先看题目给的是哪一个，不要混用。

存储层次对程序员基本透明：不用改程序，Cache 自动工作。但“透明”不等于“没有影响”。数组按行还是按列遍历、循环是否分块、数据结构是否紧凑，都会改变命中率。虚拟存储则是另一层：它把主存当作磁盘的 Cache，用页表完成地址转换，由硬件和操作系统共同管理；Cache 通常由硬件自动管理，操作系统只负责建立页表和在进程切换时维护地址空间。这些内容在第 3 章展开，这里先建立“上层快而小、下层慢而大、按块搬运、靠局部性生效”的整体图景。

\subsection{容易混淆的几组概念}

\begin{enumerate}
    \item \textbf{CPU、主机与外设。} 运算器加控制器是 CPU；CPU 加主存是主机（408 教材的常用口径）；外存和输入/输出设备属于外设。不要把外存算进主机，也不要把“主机”等同于整台计算机。
    \item \textbf{机器字长、指令字长、存储字长。} 机器字长是 CPU 一次能处理的二进制位数，通常等于通用寄存器位数和 ALU 宽度；指令字长是一条指令的位数，可以等于或多个存储字长；存储字长是一个编址单元的位数。三者可以不同，题目给“字长”时要看它修饰的是哪个对象。
    \item \textbf{主频高不等于速度快。} 执行时间由 $N$、CPI、$T_{\text{clk}}$ 三者共同决定。主频提高但 CPI 或指令条数同步上升时，程序可能一点没快，甚至更慢。
    \item \textbf{CPI 与 IPC。} CPI 是每条指令平均占用的周期数，IPC 是每周期平均完成的指令数，二者互为倒数。理想流水线的 IPC 接近 1；超标量处理器一个周期可以发射多条指令，IPC 可以大于 1，此时 CPI 小于 1。
    \item \textbf{MIPS 不能跨指令系统比较。} MIPS 把指令当成等价的工作量，不同 ISA 的指令功能差别很大。同一台机器跑不同程序，MIPS 也不同，所以它不是一个机器的固有属性。
    \item \textbf{Amdahl 定律中的 $\alpha$。} $\alpha$ 是可加速部分占原执行时间的比例，不是指令条数或代码行数的比例。上限 $1/(1-\alpha)$ 来自不能加速的那部分，换更快的加速部件也突破不了。
    \item \textbf{编译与解释、翻译与解释。} 编译是“先整体翻译，再执行目标程序”；解释是“逐条翻译并执行”。在层次结构里，汇编器和编译器做翻译，微程序解释机器指令；操作系统提供的是系统调用和资源抽象，不是翻译。
    \item \textbf{存储程序与 Cache 分离。} “指令和数据放在同一存储器”是逻辑模型。指令 Cache 和数据 Cache 分开、虚拟存储把磁盘并入地址空间，都是性能优化，不改变按地址访问、顺序取指的基本模型。
    \item \textbf{地址总线与主存容量。} $n$ 位地址总线给出 $2^n$ 个编址单元；只有按字节编址时，最大容量才是 $2^n$ 字节。若按字编址，还要乘存储字长。
    \item \textbf{冯·诺依曼瓶颈。} 它指 CPU 与存储器之间通路的带宽限制，不是容量不足。Cache、多级存储层次、更宽的总线和多通道内存都是在缓解这个瓶颈。
\end{enumerate}
