\section{I/O 管理}

程序调用 \texttt{read(fd, buf, 4096)} 之后，CPU 并不会直接去拨动磁盘的磁头。它把请求交给文件系统，文件系统找到对应的设备，驱动程序再把“读第 $n$ 块”翻译成一组寄存器操作。磁盘控制器收到命令，驱动电机、定位磁道，把数据读进自己的缓冲区，最后向 CPU 发一个中断。整条路径上，软件只负责发请求和收结果，真正的数据搬运由控制器、DMA 或通道完成。

本章沿着这条路径展开：先看设备和控制器长什么样，再看 CPU 用哪几种方式参与 I/O，然后自底向上看 I/O 软件的层次。后半部分讨论两类资源管理问题：内存中的缓冲区怎样安排，磁盘上的 SPOOLing 怎样把独占设备变成共享设备，以及多进程申请设备时怎样分配才不会死锁。

\subsection{设备、控制器与总线}

一台设备通常由两部分组成：机械或物理部分，以及插在总线上的控制器。磁盘的盘片、磁头是机械部分；磁盘控制器负责寻道、读写扇区、校验数据并发出中断。打印机也一样，控制器接收字符编码，控制打印头出字。CPU 看到的是控制器上的寄存器，而不是设备的机械结构。

控制器一般有三类寄存器。数据寄存器暂存要传输的数据；状态寄存器给出“忙”“就绪”“出错”等标志；控制寄存器接收 CPU 发出的命令，例如启动读、启动写、复位。CPU 可以用专门的 I/O 指令访问这些寄存器，例如 x86 的 \texttt{in}、\texttt{out}；也可以把寄存器编入物理地址空间，用普通的访存指令访问，后者称为内存映射 I/O。两种方式对上层软件的影响不同，但控制器内部的行为一样。

设备可以从几个不同角度分类，这些角度彼此独立。按数据单位分，块设备以固定大小的块传输，可以按块寻址，磁盘和光盘属于这一类；字符设备以字节流传输，通常不支持按块随机寻址，键盘、鼠标、打印机属于这一类。按共享属性分，独占设备一次只能给一个进程使用，打印机是典型例子；共享设备可以被多个进程交替访问，磁盘是典型例子；虚拟设备则是用软件把独占设备改造成逻辑上的共享设备，SPOOLing 就属于这一类。按速度分，还可以分成低速、中速和高速设备。

“块设备”和“独占设备”说的不是同一件事。磁盘是块设备，同时又是共享设备；打印机是字符设备，同时又是独占设备。考试里常把这两个维度混在一起，判断时先问清楚题目在按哪个维度分类。

\subsection{I/O 控制方式}

假设要把磁盘上的一块数据读进内存。CPU 可以用四种方式参与这件事，区别在于 CPU 花多少时间、数据由谁搬运、每传多少数据中断一次。

\subsubsection{程序直接控制}

CPU 向控制器发出读命令，然后反复读取状态寄存器。状态寄存器显示“忙”时，CPU 继续读；显示“就绪”时，CPU 把数据寄存器里的内容搬到内存。搬完一个字，再启动下一个字的传输。

这种方式叫程序直接控制，也叫轮询。它的缺点是 CPU 在等待期间只能空转，不能执行其他进程的有用工作。设备越慢，浪费越大。优点是实现简单，不需要中断硬件；在设备响应很快、或者系统很小的时候，轮询反而没有中断开销。

\subsubsection{中断驱动}

CPU 发出读命令后，把当前进程挂起，切换到其他进程。设备把一个字或一个字节准备好，向 CPU 发中断。CPU 响应中断，保存现场，进入中断处理程序，把数据寄存器里的内容搬到内存。如果还有数据，驱动程序再次启动设备，然后返回被中断的进程。

中断驱动把“等待”从 CPU 的忙等变成了设备的异步通知。CPU 在设备工作期间可以运行别的进程。代价是每传一个字或一个字节就要中断一次。中断要保存现场、识别中断源、执行中断服务程序、恢复现场，开销不小。键盘、鼠标、串口这类低速字符设备适合这种方式；高速磁盘如果每字节都中断，CPU 会把大量时间花在中断处理上。

中断处理程序只做最必要的事：读状态、搬数据、唤醒等待的进程。耗时的工作可以推迟到后半部执行，避免长时间关中断。

\subsubsection{DMA}

DMA 方式在设备和主存之间加一个 DMA 控制器。CPU 不再逐字搬运数据，只负责初始化。以读磁盘为例，CPU 把内存起始地址写入 DMA 的地址寄存器 MAR，把要传的字数写入计数寄存器 DC，把“读”命令和方向写入命令寄存器 CR，然后启动 DMA。DMA 控制器向 CPU 申请总线，获得总线控制权后，控制设备把数据逐字写入主存。每传一个字，MAR 按传送单位递增，DC 减 1。DC 减到 0 时，DMA 控制器向 CPU 发一次中断，表示整块数据传完。

DMA 的关键变化有两个。数据传送不再经过 CPU，CPU 只参与开始和结束；中断频率从“每个字一次”降到“每块一次”。块越大，节省的 CPU 时间越多。

DMA 传送期间要占用总线。如果 CPU 也要访存，两者会争用内存周期。DMA 每传一个字，挪用一次总线周期，传完就把总线还给 CPU，这种方式叫周期挪用。另一种做法是一次占住总线，把整块数据传完再释放，叫成组传送。成组传送对 CPU 的影响更大，但传输效率更高。

\subsubsection{通道}

通道比 DMA 更进一步。它是一个专门处理 I/O 的处理器，有自己的指令系统，能执行存放在主存里的通道程序。CPU 只要执行一条“启动 I/O”指令，把通道程序的地址告诉通道，通道就会自己取指令、控制多台设备、按程序里的条件跳转和循环，全部完成后才向 CPU 发一次中断。

DMA 只能做“把一块数据从设备搬到内存”这种固定动作，没有分支和循环能力。通道能执行程序，所以可以把“读多个磁道”“从多台设备收集数据”这样的任务写成通道程序，一次交给通道。CPU 的参与程度从“每块一次”降到“每个通道程序一次”。

通道有三种常见类型。字节多路通道按字节轮流为多台低速设备服务，适合终端、打印机这类设备。数组选择通道按块为高速设备服务，一次只服务一台设备，设备独占通道。数组多路通道按块轮流为多台高速设备服务，兼顾了选择通道的效率和多路通道的并行性。

\subsection{I/O 软件层次}

用户程序调用 \texttt{printf} 时，并不知道数据最终写到磁盘还是屏幕。这个调用会经过库函数、系统调用、设备独立性软件、设备驱动程序，最后变成控制器寄存器上的一次写操作。I/O 软件通常分成四层，每一层只和相邻层打交道。

图中上方是用户态，下方是内核态和硬件。请求从用户层往下传，每一层只处理自己负责的那部分；设备完成操作后，中断从硬件往上走，最终唤醒等待的进程。

中断处理程序在最底层。设备发中断后，硬件保存程序计数器和程序状态字，根据中断向量跳到处理程序入口。处理程序先保存寄存器，再读控制器的状态寄存器，判断是哪台设备、出了什么错。如果是中断驱动的读操作，它把数据寄存器里的内容搬到内存；如果是 DMA，它只做完成后的收尾。最后唤醒等待该 I/O 的进程，恢复现场并返回。中断处理程序应该短，耗时的收尾工作可以放到后半部。

设备驱动程序在中断处理程序之上。它知道某种设备的具体细节：控制器有哪些寄存器、命令字怎么写、状态位怎么解释、出错后怎么重试。上层说“读第 $n$ 块”，驱动程序把它变成“写柱面号、磁头号、扇区号，启动读命令”。驱动程序通常运行在内核态，设备制造商按操作系统的驱动接口编写。不同设备有不同驱动，同一类设备可以共用一个驱动。

设备独立性软件处理所有设备共有的问题。它把逻辑设备名映射到物理设备，提供统一的 \texttt{open}、\texttt{read}、\texttt{write}、\texttt{ioctl} 接口，管理缓冲区，分配设备，处理一般的 I/O 错误，向上层屏蔽不同设备的块大小和扇区大小。逻辑设备表 LUT 就放在这一层：进程用“打印机”这样的逻辑名申请设备，LUT 把它换成物理设备名和驱动程序入口。这样更换设备时，用户程序不用改。

用户层 I/O 软件包括库函数，SPOOLing 守护进程通常也以用户进程形式运行。\texttt{printf} 把格式化后的字符串交给 \texttt{write} 系统调用；打印守护进程在后台把输出井里的文件送到打印机。用户层软件运行在用户态，通过系统调用进入内核。

分层的好处是每一层只依赖下一层的接口。换一块网卡，只需要换驱动，文件系统和用户程序不受影响；换一种文件系统，缓冲区管理和驱动也不用改。代价是请求要穿过几层，函数调用和上下文切换有开销。

\subsection{缓冲区管理}

键盘每秒可能只产生几十个字节，CPU 每秒能执行几十亿条指令。如果 CPU 每读一个字节就等一次键盘，大部分时间都浪费在等待上。缓冲区的作用是在两者之间放一块内存：设备先把数据攒起来，CPU 一次取走一批；或者 CPU 先把输出攒起来，设备慢慢取。这样两边可以并行工作，中断次数也能减少。

缓冲区通常分配在内核空间，属于操作系统的内存，不是磁盘。这一点要和 SPOOLing 的“井”区分开：井在磁盘上，缓冲区在内存里。

\subsubsection{单缓冲与双缓冲}

先看输入方向。设备把一块数据读入缓冲区，耗时记为 $T$；操作系统把缓冲区里的数据搬到用户工作区，耗时记为 $M$；CPU 处理这块数据，耗时记为 $C$。在单缓冲下，设备、缓冲区、用户区只有一条通路，设备和 CPU 不能同时使用同一个缓冲区。

设备把缓冲区填满后，CPU 开始搬移。搬移完成，缓冲区空出来，设备才能开始读下一块。搬移之后的处理 $C$ 可以和下一块的读入 $T$ 重叠，但搬移 $M$ 本身要占着缓冲区，不能和下一块的 $T$ 重叠。因此，第一块要完整经历 $T+M+C$；此后每增加一块，所需时间是 $\max(C,T)+M$。处理 $N$ 块的总时间为
\[
T_{\text{单}}=T+M+C+(N-1)\bigl[\max(C,T)+M\bigr].
\]

双缓冲设置两个缓冲区。设备往缓冲区 0 填数据时，CPU 可以从缓冲区 1 取数据；缓冲区 0 填满后，设备转去填缓冲区 1，CPU 同时处理缓冲区 0。这样设备路径每块花 $T$，CPU 路径每块花 $M+C$，两条路径并行，稳态下每块的时间是两者中较慢的那个：
\[
\max(T,\,M+C).
\]
第一块仍然要经历 $T+M+C$，所以 $N$ 块的总时间为
\[
T_{\text{双}}=T+M+C+(N-1)\max(T,\,M+C).
\]

输出方向的分析完全对称。CPU 先把结果写进用户区，再搬到系统缓冲区（$M$），设备从缓冲区取走输出（$T$）。单缓冲下，设备取走之前缓冲区不能重用，所以每块仍是 $\max(C,T)+M$；双缓冲下，CPU 准备下一块和设备输出上一块可以并行，每块仍是 $\max(T,M+C)$。公式里的 $T$ 换成输出时间，$M$ 换成“用户区到系统缓冲区”的搬移时间即可。

有一个常见的错误：双缓冲的并行路径写成 $\max(T,C)$，漏掉 $M$。只有题目明确说 $M$ 可以忽略，或者 $M$ 已经包含在 $C$ 里，才能把 $M$ 当成 0。否则 CPU 路径是“搬移加处理”，即 $M+C$。

\subsubsection{循环缓冲与缓冲池}

双缓冲只有两个缓冲区，遇到设备忽快忽慢、进程处理一阵停一阵的情况，两个缓冲区不够用。循环缓冲把多个缓冲区组织成一个环，每个缓冲区有一个状态：空、满、正在使用。设备按 \texttt{NextIn} 指针找下一个空缓冲区填入，CPU 按 \texttt{NextOut} 指针找下一个满缓冲区取出。填满后 \texttt{NextIn} 后移，取空后 \texttt{NextOut} 后移。环上的缓冲区首尾相接，指针走到末尾就回到开头。

循环缓冲能吸收突发：设备一次送来好几块，CPU 可以慢慢处理；CPU 一阵忙不过来，设备也有地方存。稳态吞吐率仍由较慢的一边决定，缓冲区数量不会让慢的一边变快，它只是把“等”的位置从设备或 CPU 挪到了队列上。

缓冲池是系统级的一组缓冲区，不再固定分给某台设备。池中的缓冲区按状态挂在三个队列上：空缓冲队列 \texttt{emq}、输入队列 \texttt{inq}、输出队列 \texttt{outq}。设备输入时，缓冲管理程序从 \texttt{emq} 取一个空缓冲区，设备把数据填进去，填满后挂到 \texttt{inq}；进程从 \texttt{inq} 取走数据，缓冲区变空，挂回 \texttt{emq}。输出方向对称：进程从 \texttt{emq} 取空缓冲区，填入输出数据后挂到 \texttt{outq}；设备从 \texttt{outq} 取走数据，输出完成后把空缓冲区挂回 \texttt{emq}。

\subsection{SPOOLing}

三个用户几乎同时提交打印任务，而办公室只有一台打印机。没有 SPOOLing 时，第一个进程独占打印机，第二个和第三个只能等。有了 SPOOLing，三个进程都把要打印的数据写到磁盘上的输出井，写完就返回；后台的打印守护进程按顺序把文件送到打印机。三个进程都觉得自己有一台打印机，实际上它们只是在共享磁盘上的队列。

SPOOLing 是 Simultaneous Peripheral Operations On-Line 的缩写，中文叫假脱机。它由三部分组成。输入井和输出井是在磁盘上开辟的两块存储区域，输入井暂存从输入设备预先读入的数据，输出井暂存进程要输出的数据。输入进程和输出进程是后台进程，输入进程把物理输入设备的数据读进输入井，输出进程把输出井的数据送到物理设备。井管理程序负责分配和回收井中的空间，维护队列。

输出方向的流程如下。进程打开逻辑打印机，系统在输出井中为它建立一个 SPOOLing 文件。进程调用写操作，数据被追加到这个文件里；写完最后一块，进程返回，继续做别的事。此时数据还在磁盘上，没有送到打印机。输出进程按队列顺序取出文件，把内容逐块送到打印机。打印机打完一个文件，输出进程回收井空间，再处理下一个。

输入方向对称。输入进程提前把读卡器、终端等设备的数据读入输入井。进程要读数据时，从输入井取，不必直接和慢速输入设备打交道。输入井里没有数据时，进程阻塞，等输入进程读入后再唤醒。

SPOOLing 把独占设备改造成了共享设备。从进程的角度看，它独占了一台打印机；从系统的角度看，多台逻辑打印机对应同一台物理打印机，请求在队列里排队。它还把慢速设备的操作变成了磁盘操作：用户进程写磁盘比等打印机快得多，写完就能继续运行。这就是“虚拟设备”的含义。

SPOOLing 不会让打印机本身的吞吐率变高。打印机每秒能打多少页是固定的，队列再长也不能改变这一点。它改善的是进程的等待时间和设备利用率：进程不必同步等待慢速设备，打印机也不必在两次任务之间空闲。要实现 SPOOLing，系统需要磁盘存放井，还需要多道程序支持，让输出进程能在用户进程运行的同时工作。

\subsection{设备分配}

设备是资源，多个进程可能同时申请。独占设备一次只能给一个进程，分配不当会让进程互相等待，甚至死锁。共享设备不需要独占，但要多进程的请求排队，按某种策略调度。虚拟设备则是用 SPOOLing 在逻辑上造出多台设备。

为了管理设备，系统维护一组表。系统设备表 SDT 是全局的，每台设备占一个表项，记录设备类型、设备号、指向设备控制表的指针和驱动程序入口。设备控制表 DCT 描述一台设备的状态：设备号、状态（忙或闲）、等待队列队首、指向控制器控制表的指针。控制器控制表 COCT 描述一个控制器：状态、等待队列、指向通道控制表的指针。通道控制表 CHCT 描述一个通道：状态和等待队列。

逻辑设备表 LUT 负责名字映射。进程申请设备时用的是逻辑名，例如“打印机”或 \texttt{/dev/lp0}；LUT 的表项记录逻辑名、物理设备名和驱动程序入口。LUT 可以整个系统一张，也可以每个进程一张。系统一张时，逻辑名必须全局唯一；每个进程一张时，不同进程可以用相同的逻辑名指不同的物理设备。

一次独占设备的分配通常按下面的顺序进行。进程给出逻辑设备名，系统查 LUT 得到物理设备名和驱动程序入口，再通过 SDT 找到该设备的 DCT，看 DCT 中的状态是否空闲。设备忙，就把进程挂到 DCT 的等待队列；设备空闲，就把设备分给它。接着查 COCT，看控制器能否接受；控制器忙，可以释放设备后再等，也可以带着设备排队，后者要小心死锁。再查 CHCT，看通道是否空闲。三层都分配成功，驱动程序才把请求变成寄存器操作，启动 I/O。I/O 完成后，中断处理程序唤醒等待的进程，系统逐层释放通道、控制器和设备，并唤醒相应队列的队首。

共享设备不采用这种独占分配。磁盘可以被多个进程同时打开，系统只把读写请求排成队列，按电梯算法之类的策略调度。虚拟设备用 SPOOLing 实现，进程申请的是输出井中的一个逻辑设备，物理打印机仍然由输出进程串行使用。

设备分配有两种时机。静态分配在进程运行前一次性分配它需要的全部设备，运行期间不再申请。这样做不会因为设备竞争而死锁，但设备利用率低，进程可能占着设备却长时间不用。动态分配在进程运行中按需申请，利用率高，但可能出现死锁。多类独占设备同时被多个进程申请时，系统可以用银行家算法做安全性检查：每次分配前先模拟分配，看是否存在安全序列；若分配后进入不安全状态，就拒绝本次分配，让进程等待。

\subsection{几组容易混淆的概念}

中断驱动和 DMA 的分界在“谁搬数据”。中断驱动由 CPU 在中断服务程序里把数据从设备寄存器搬到内存；DMA 由 DMA 控制器直接在主存和设备之间搬，CPU 只初始化和收尾。中断频率也不同：前者每字或每字节一次，后者每块一次。

块设备和独占设备是两个维度。磁盘是块设备，也是共享设备；打印机是字符设备，也是独占设备。判断时先看题目问的是数据单位还是共享属性。

缓冲和 SPOOLing 解决的不是同一个问题。缓冲区在内存里，用来缓和 CPU 与设备的速度差，减少中断次数；SPOOLing 的井在磁盘上，用来把独占设备改造成共享设备，让多个进程的请求排队。缓冲区通常属于某台设备或某个进程，缓冲池才是系统共享的；SPOOLing 的井从一开始就是共享的。

单缓冲和双缓冲的公式只差一个 $M$，但不能把 $M$ 随手丢掉。单缓冲的稳态间隔是 $\max(C,T)+M$，双缓冲是 $\max(T,M+C)$。双缓冲的 CPU 路径是“搬移加处理”，不是单独的处理时间。

通道和 DMA 的区别在“有没有指令”。DMA 只能按预先设置好的地址和长度搬一块数据，不能分支、不能循环；通道有自己的指令系统，能执行通道程序，控制多台设备，完成后才中断一次。

LUT 和 SDT 都出现在设备分配的题目里，但职责不同。LUT 负责逻辑名到物理名的映射，按进程或按系统建立；SDT 是系统全部设备的清单，记录每台设备的类型、编号和 DCT 指针。题目问“按逻辑设备名找物理设备”时，答案是 LUT；问“系统中有哪些设备、到哪里找它们的控制表”时，答案是 SDT。
